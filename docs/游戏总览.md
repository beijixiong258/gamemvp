# 游戏总览

> 本文说明整体方向。首版范围见[玩法与范围](./MVP/玩法与范围.md)，完成情况见[待办事项](./MVP/待办事项.md)。

## 玩家表达，程序执行

玩家可以用自己的话提出行动、观点或政策。AI 负责理解意思，按约定格式给出影响；程序负责检查、计算并保存结果。玩家可以研究更有效的表达方式，但一句话不能直接改掉金钱、人口、职位等事实。

每次调用 AI 提供三类内容：本次任务及允许影响的项目、相关人物和世界数据、玩家原文。这里的“状态”是当前有什么，“变化量”是接下来变化多少。AI 只能使用游戏已经支持的变化项目，最终结果由程序计算。

游戏以文字、页面跳转、输入框和按钮为主，不追求复杂美术。后端使用 Java 17、Spring Boot、Spring AI、LangGraph4j、MyBatis-Plus 和 MySQL，同一存档的操作按顺序处理。

## 历史提供起点

开局参考明代历史；游戏开始后，人物行动可以让世界偏离历史。AI 应以本局设定和存档为准。地区按省、市、县的上下级关系组织，具体节点见[数据结构与升级](./开发者手册/数据结构与升级.md#三地区关系)。

## 角色能力与玩家思考

角色有自己的能力、知识和经历，玩家也可以通过更好的思考改善方案。“以身入局”让玩家亲自作答或决策；角色能力决定能提供什么程度的思路，玩家可以采用、修改或不用。

每个领域分别保存能力与成就，不设互斥的主职业。一个人可以同时成为文豪、艺术家和商人，参与新领域不会清空旧能力；首版先做书生领域。

长期设计中，AI 还会参考人物立场、承诺、公开形象和重要经历。同一政策由不同经历的人提出，可以产生不同评价；立场转变由具体情境判断，不固定扣分。

## 人物与记忆的后续方向

首版使用固定 NPC，已经接入已结束对话和重要经历的基础记忆。以下是后续扩展方向：

- 大多数人口只作统计；路人可以临时出现，有持续关系或重要影响的人物才长期保存。
- 世界事实保存在数据库；记忆只保存角色经历过、知道或重视的内容，不复制整个世界。
- 在现有按人物和近期经历读取压缩记忆的基础上，进一步结合地点和当前任务检索历史。更完整的语义检索和世界记忆仍属后续扩展。

## 官职与权力的后续方向

人物可以同时在多个组织任职，任职与领域能力分别保存。称号或成就本身不授予行政权；实际能做什么，要看被授予的职责和管辖范围。

权限说明“能处理哪些事、在哪些地区处理”。地区权限可以覆盖下级，不能自动扩大到上级或同级。差遣可以额外授予权限；被架空则是保留职位、收回权限。影响力根据官阶、权限、关系、声望与资源综合判断，不代替权限检查。

皇帝或获同等授权者可以授予、收回和调整别人的权限，因此可以形成摄政、共治等局面。官职可以改名、重组或废除，但仍由已有权限组合而成，不能临时创造新的底层规则。具体官品和岗位见[官职与爵位](./后续设计/官职与爵位.md)。
