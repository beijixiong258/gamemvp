# 古代穿越人生模拟游戏 MVP 设计文档

> 本文只描述第一个可玩闭环、玩家体验和功能范围。长期世界设计见[《游戏设计》](./游戏设计.md)，持久化结构见[《MVP数据模型设计》](./MVP数据模型设计.md)，数值公式、行动结算与智能体编排见[《MVP引擎设计》](./MVP引擎设计.md)。

## 一、MVP目标

MVP 只实现一段完整但极小的人生：玩家角色出生，经历童年和启蒙求学，在十六岁时第一次参加县试，完成考试结算后结束本局。

本阶段验证三个核心问题：

1. 玩家能否使用自然语言完成固定按钮之外的行动，并与 NPC 进行有上下文的对话。
2. 玩家本人的思考与角色自身能力能否共同影响结果，既允许玩家“以身入局”，又保留人物养成的意义。
3. 学习过程和重要人生经历能否持续影响后续回合，并最终共同作用于县试。

县试通过或落榜都是正常结局，不设置传统意义上的游戏失败。

## 三、实现范围

MVP 包含：

- 角色出生、家庭背景和先天属性。
- 0～5 岁童年快速成长。
- 6～15 岁启蒙与求学。
- 每月四个行动回合。
- 读书、练习文章和休息三种固定行动。
- 自由行动和固定 NPC 对话。
- 重大事件与简化人物记忆。
- 县试思维泡泡、系统代行和以身入局。
- 考试结果叙事、人生阶段总结和自动存档。

游戏只保留三个主要场景：家中、私塾和县试考场。界面以文字、少量贴图、状态展示、按钮和输入框为主。

本阶段不实现：

- 动态地图、人物移动、动画和实时战斗。
- 当官、经商、战争及大规模世界推演。
- 完整行政区、官职和权限系统。
- 自由生成并永久保存的新 NPC。
- NPC 后台自主行动。
- 好感、信任、敬重等量化关系。
- 府试、院试及县试之后的人生。

## 四、完整游戏流程

```text
创建存档
  ↓
角色出生、家庭和固定NPC初始化
  ↓
0～5岁快速成长
  ↓
六岁入学并成为书生
  ↓
6～15岁按月行动和求学
  ↓
十六岁进入县试
  ↓
玩家选择“采纳”或“以身入局”
  ↓
生成考试结果和人生阶段总结
  ↓
存档完成，MVP结束
```

童年阶段不要求玩家操纵婴儿逐回合行动，而是用三个快速成长阶段形成先天差异和早年经历。

六岁后进入普通回合。一个月有四个结束回合行动，一年十二个月，从六岁到十六岁共经历四百八十个结束回合行动。一个回合内可以先查看场景、与 NPC 对话或执行其他非结束操作，再通过读书、练习、休息或自由行动结束本回合。

## 五、核心游戏规则

### 1. 状态与变化

数据库保存已经成立的世界事实，例如年龄、能力、疲劳、财富、事件和当前回合。固定行动由 Java 直接计算变化；自由行动由 AI 理解语义并给出驱动量，再由 Java 引擎形成最终状态。

AI 不直接决定人物最终属性、时间、财富余额或考试结果。详细计算关系统一由《MVP引擎设计》维护。

### 2. 人物能力

玩家与 NPC 使用同一套人物结构。人物能力分为三层：

| 层次 | 内容 | 特点 |
|---|---|---|
| 人物通用属性 | 智力、道德、政治、交际、体能 | 跨职业长期保留 |
| 当前状态 | 健康、疲劳 | 随行动明显变化 |
| 书生职业能力 | 识字、经义、文章、策论、文学 | 进入书生职业后才存在 |

角色出生时主职业是 `CAREER_PINGMIN`。六岁入学时新增 `CAREER_SHUSHENG` 职业档案并切换主职业；过去职业记录继续保留。

文章表示组织、论述和成篇能力，文学表示积累、典故、审美和文辞表现，两项不合并。

### 3. 货币

一文铜钱是唯一底层金额单位。所有价格、财富和交易结果都保存为整数文数。

固定换算为：

```text
1两白银 = 1000文
1两黄金 = 20两白银 = 20000文
```

普通金额只自动显示为银两与铜钱；黄金只在明确涉及黄金的玩法中展示。

## 六、场景与行动

### 1. 场景

| 场景 | 作用 | 可见 NPC |
|---|---|---|
| 家中 `SCENE_JIA` | 出生、家庭互动和休息 | 父亲、母亲 |
| 私塾 `SCENE_SISHU` | 读书、练习和求教 | 私塾先生、同窗 |
| 县试考场 `SCENE_XIANSHI` | 最终考试 | 县试考官 |

打开或离开场景只是查看内容，不消耗游戏时间。

### 2. 行动类别

| 行动类型 | 当前行动 | 是否调用 AI | 是否结束回合 |
|---|---|---:|---:|
| 固定行动 `FIXED_ACTION` | 读书、练习文章、休息 | 否 | 是 |
| 自由行动 `FREE_ACTION` | 玩家描述固定按钮之外的行为 | 是 | 是 |
| NPC 对话 `NPC_DIALOGUE` | 选择 NPC 并输入对话 | 是 | 否 |
| 考试行动 `EXAM_ACTION` | 系统代行、以身入局 | 部分环节调用 | 完成考试 |

是否结束回合只由服务端的 `action.json` 决定，前端和 AI 不参与该决定。

### 3. 固定行动

`READ_BOOK` 必须选择一本当前可读的书。每本书分别保存进度，并根据自身难度和能力侧重影响角色。书籍达到不同进度阶段后，会逐步开放给角色使用的知识摘要。

`PRACTICE_WRITING` 用于稳定训练文章组织与成篇能力。

`REST` 用于降低疲劳、恢复健康。

三个固定行动从计算到反馈都不依赖模型；AI 服务不可用时仍能继续游戏。

### 4. 自由行动

玩家可以描述固定按钮没有覆盖的行动，例如请教治事、尝试新的学习方式或处理家庭事务。Resolver 结合当前场景、人物状态和少量相关记忆理解行为，Java 引擎负责结算实际变化。

自由行动成功后结束回合。对人物、家庭或人生方向产生明显影响时，可以形成重大事件和人物记忆。

### 5. NPC 对话

玩家选择当前场景中的 NPC 并输入原文。NPC 回应只依据其公开设定、可见事实和相关记忆，不拥有全知视角。

普通对话不直接改变人物数值，也不结束回合。重要承诺、冲突或帮助可以形成事件与记忆；知识启发、获赠书籍和财富变化通过明确的后续行动结算。

## 七、书籍内容

MVP 首版使用以下书籍：

| 书籍 | 稀有度 | 主要方向 |
|---|---|---|
| 《三字经》 | 常见 | 识字、基础经义 |
| 《千字文》 | 常见 | 识字、文学积累 |
| 《论语》 | 常见 | 经义、文章、策论 |
| 《孟子》 | 少见 | 经义、文章、策论 |
| 《大学》 | 少见 | 经义、策论、文章 |
| 《诗经》 | 少见 | 文学、经义、文章 |
| 《名家文钞》 | 珍本 | 文章、策论、文学 |

年龄、职业、属性、前置书目和持有权共同决定角色当前能否阅读一本书。稀有度决定获取难度，不直接等于学习效率。

人物对每本书分别积累进度。归还或暂时失去书籍不会清除已经学到的内容，再次获得使用权后可以继续学习。

## 八、固定 NPC 与记忆

MVP 保留五类固定 NPC：父亲、母亲、私塾先生、一名同窗和县试考官。名字可以在初始化时生成，身份和默认场景来自内容配置。

事件表示某件事确实发生过，记忆表示某个人以后可能如何想起这件事。两者分开保存：

- 学会重要知识、作出承诺、发生明显冲突或影响考试准备的行为可以形成事件。
- 同一事件可以形成玩家、父母、先生或同窗各自不同视角的记忆。
- 普通闲聊和没有长期影响的操作不保存完整流水。
- MVP 按人物、事件和回合读取少量记忆，不接入向量数据库。

## 九、县试体验

### 1. 考试开始

十六岁时进入县试。系统根据题目、人物通用属性、书生能力、已掌握书籍知识、健康和疲劳形成固定考试状态。

题目出现后，输入框上方显示角色自己的思维泡泡。能力越高、知识越充分，思路越完整；能力不足时，角色可能只能想到零碎内容。泡泡只使用角色已经学到的知识，并且始终是思路而不是范文。

### 2. 系统代行

玩家点击“采纳”，表示让角色按照自身能力完成答卷。系统先确定分数与通过状态，再由 AI 生成符合该结果的答卷表现和叙事。生成文字不反向改变成绩。

### 3. 以身入局

玩家不点击“采纳”，而是在下方输入框亲自作答。Resolver 评价答案内容并形成玩家贡献，最终仍由 Java 引擎结合角色能力和临场状态结算。

认真且正确的答案可以让低属性角色明显超越其系统代行表现；同一篇答案交给两个不同角色，仍会因为角色能力不同而得到不同结果。

### 4. 考试结束

通过和落榜都会生成结果报告与人生阶段总结，并将存档设为完成。MVP 不继续进入府试或院试。

## 十、后端接口范围

| 接口 | 用途 |
|---|---|
| `POST /api/save` | 创建存档并完成出生初始化 |
| `GET /api/save/{saveId}` | 获取存档、角色状态和当前可用内容 |
| `GET /api/save/{saveId}/scene/{sceneCode}` | 查看场景介绍、行动和 NPC |
| `POST /api/save/{saveId}/turn` | 执行当前回合内的一次操作 |
| `GET /api/save/{saveId}/exam` | 获取当前县试题目和思维泡泡 |
| `POST /api/save/{saveId}/exam/adopt` | 采纳角色思路并系统代行 |
| `POST /api/save/{saveId}/exam/involve` | 提交玩家手写答案并以身入局 |
| `GET /api/save/{saveId}/result` | 获取县试结果和人生阶段总结 |

`POST /turn` 根据行动类型使用不同请求内容：

```json
{
  "actionType": "FIXED_ACTION",
  "actionCode": "READ_BOOK",
  "bookCode": "BOOK_LUNYU"
}
```

- `READ_BOOK` 携带 `bookCode`。
- `REST` 和 `PRACTICE_WRITING` 不携带自由文本。
- `FREE_ACTION` 携带 `text`。
- `NPC_DIALOGUE` 携带 `npcId` 和 `text`。

“采纳”和“以身入局”作用于同一次县试，任一路径完成后直接进入考试结果。

## 十一、前端页面

前端只实现四个页面：

1. 出生页：创建角色，展示家庭、先天条件和初始主职业。
2. 成长页：展示年龄、月份、回合、人物状态、职业能力、场景、行动、书籍和 NPC。
3. 县试页：展示题目、思维泡泡、“采纳”按钮和玩家作答输入框。
4. 结果页：展示成绩、通过或落榜状态、关键经历和 MVP 结束提示。

成长页选择读书后继续选择具体书籍，并展示稀有度、来源、当前进度和阅读条件。固定行动不显示自由输入框；自由行动和 NPC 对话分别显示对应输入区域。

县试页的“采纳”不会把思维泡泡复制到输入框。思维泡泡属于角色思路，输入框只代表玩家亲自作答。

MVP 不要求复杂美术，重点是信息层次、行动含义和人生推进过程清楚。

## 十二、技术与内容边界

后端使用 Java 17、Spring Boot、Spring AI、LangGraph4j、MyBatis-Plus 和 MySQL，采用模块化单体结构。游戏按存档串行推进，不拆微服务。

内容配置位于：

```text
src/main/resources
├─ game
│  ├─ equipment.json
│  ├─ book.json
│  ├─ npc.json
│  ├─ scene.json
│  ├─ action.json
│  ├─ exam.json
│  └─ text.json
└─ prompt
   └─ prompt.json
```

- JSON 保存可调整的游戏内容和数值。
- Java 常量保存稳定编码、规则边界和货币换算。
- Engine 保存计算关系。
- MySQL 保存定义表和当前存档事实。
- Controller 使用 DTO 与 VO，不把 Entity 直接作为长期前端协议。
- Service 负责编排用例，Mapper 只承担数据访问。
- LangGraph 只服务一次 AI 操作，不保存长期游戏状态。

## 十三、完成定义

达到以下结果即可认为 MVP 闭环完成：

- 能创建角色并完成童年快速成长，六岁进入书生求学阶段。
- 能按每月四回合持续行动，固定行动不依赖 AI。
- 每本书拥有独立进度，学习结果受到人物、状态和书籍差异影响。
- 自由行动和 NPC 对话能使用当前事实与重要记忆形成合理结果。
- 十六岁能够稳定进入县试，并提供系统代行和以身入局两条路径。
- 两条考试路径共同保留角色能力的作用，同时允许玩家答案改变结果。
- 县试结束后生成报告并完成存档。

## 十四、实现顺序

按以下顺序推进：

1. 以[《MVP数据模型设计》](./MVP数据模型设计.md)和建库脚本为准完成持久化基础。
2. 以[《MVP引擎设计》](./MVP引擎设计.md)为准实现出生、童年、固定行动和时间推进，使游戏在没有 AI 时能够走到县试。
3. 接入自由行动 Resolver。
4. 接入固定 NPC、事件和人物记忆。
5. 完成县试思维泡泡、系统代行、以身入局和结果叙事。
6. 补齐四个前端页面，形成可手动体验的完整闭环。

任何不能直接服务于“出生到第一次县试”的功能，默认移出本次 MVP。
