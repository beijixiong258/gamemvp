# 古代穿越人生模拟游戏 MVP 设计文档

> 本文定义玩家体验、产品范围与完成标准。具体公式见[《MVP引擎设计》](./MVP引擎设计.md)，持久化结构见[《MVP数据模型设计》](./MVP数据模型设计.md)。

## 一、MVP 目标

MVP 实现一段可完整走通的最小人生：

```text
选择出生地并开始人生
  ↓
直接进入六岁求学
  ↓
按回合读书、练习、休息或自由行动
  ↓
经历8岁、12岁、15岁三次阶段考试
  ↓
16岁参加县试
  ↓
生成阶段结果并结束本局
```

核心闭环是：没有 AI 时固定行动和时间仍能运行；接入 AI 后，玩家可以用自然语言补充固定规则没有覆盖的行动，但最终事实仍由 Java 引擎结算。

当前源码已接通开局、存档列表、读档、NPC生成、背包获取、固定及自由行动、对话、重病休养和四次考试系统代行。下文区分当前机制与产品目标；前端、童年AI叙事、长期记忆、考试思维泡泡及以身入局链路尚未完成。

## 二、历史与地区基线

### 1. 开局年代

默认开局为 1547 年，即嘉靖二十六年。按《明史》卷十八记载，夏言于嘉靖二十四年九月复入内阁，嘉靖二十七年正月罢职，因此 1547 年对应他最后一次执政阶段的倒数第二年。

参考：[《明史·本纪第十八·世宗二》](https://zh.wikisource.org/zh-hans/%E6%98%8E%E5%8F%B2/%E5%8D%B718)

真实历史只提供开局背景。玩家开始行动后，存档可以偏离真实历史。

### 2. 地区范围

MVP 使用广东省下的广州、惠州及五个县作为简化世界切片，不追求完整复原明代沿革。当前玩家只能在惠州的非城区县级节点出生，即博罗县或海丰县；广州及其三个县暂时只作为世界背景和后续政治线入口。完整节点和等级只在[《MVP数据模型设计》](./MVP数据模型设计.md)中维护。

## 三、开始人生

出生页只要求玩家填写角色名并选择博罗县或海丰县。点击“开始人生”后，一次完成：

- 建立存档、玩家人物、书生领域档案、初始家庭背景和固定 NPC。
- 以固定初值跳过0～5岁；童年摘要作为后续叙事目标，当前不调用模型逐年推演。
- 把出生地同时设为当前所在地。
- 直接进入六岁、1547 年正月的第一个行动回合。

MVP 不让玩家操作六岁以前的年份，也不逐年计算童年属性。

初始状态固定：

- 智力、道德、政治、交际、体能均为 20。
- 健康 75，疲劳 0。
- 识字 5；经义、文章、策论、文学均为 0。
- 初始家庭财富 100000 文，允许的开局范围为 10000～1000000 文。
- 初始家庭背景固定为家中有一定田产和积蓄，能够供角色入塾读书。
- 人物钱包首版固定2000文，与初始家庭背景分开；之后实际交易修改钱包。

同样的输入产生相同开局数值；存档ID和创建时间各自独立。每次点击新开局创建一个新存档，进入游戏可以选择新开局或读档。

书生领域档案记录求学能力，不限制人物参与其他领域。MVP 只实现该领域；多领域成就与同时任职的整体规则见[《游戏设计》](./游戏设计.md)。

## 四、成长阶段

### 1. 普通回合

六岁后每月四个结束回合，一年十二个月。查看页面、获取物品和普通NPC对话不推进时间；读书、练习文章、休息和自由行动会结束当前回合。健康归零会扣属性并强制休养，休养逐回合推进，碰到考试先暂停并处理考试。

从六岁开始到十六岁县试共 480 个结束回合。年龄只在跨年时变化。

### 2. 阶段考试

| 年龄 | 考试 | 目的 |
|---:|---|---|
| 8 | 蒙学阶段考 | 检查识字和基础理解 |
| 12 | 经义阶段考 | 检查经义理解和初步论述 |
| 15 | 县试预考 | 检查综合表达与应试准备 |
| 16 | 县试 | 本次 MVP 的最终考试 |

前三次考试通过或未通过都继续求学，不回滚成长，也不提前结束本局。县试完成后生成结果与人生阶段总结，存档进入完成状态。

所有阅读进度、考试基础分、临场偏移、玩家内容修正和最终分都按整数展示和保存。

## 五、场景与行动

### 1. 场景

| 场景 | 用途 |
|---|---|
| 家中 `SCENE_JIA` | 家庭互动、休息和自由行动 |
| 私塾 `SCENE_SISHU` | 读书、练习、请教和三次阶段考试 |
| 县试考场 `SCENE_XIANSHI` | 十六岁县试 |
| 集市 `SCENE_JISHI` | 与书商互动并购买进阶或整活书籍 |

进入场景本身不消耗回合。

### 2. 固定行动

- `READ_BOOK`：选择一本当前可读的书，增加该书的整数阅读进度，并按书籍侧重成长。
- `PRACTICE_WRITING`：训练文章能力。
- `REST`：降低疲劳并恢复健康。

固定行动不调用AI，AI服务不可用时仍可继续成长。读书使用1D100决定极端结果：1没看进去，100直接开悟读满；其余按基础公式成长。实际骰点随请求结果保存，超时重传不会重复行动或重投。

### 3. 自由行动

玩家用自然语言描述固定按钮没有覆盖的行为。Resolver 负责理解行为并输出结构化驱动量，Java 引擎再计算真正发生的属性、能力、健康或疲劳变化。

自由行动会结束回合，也能通过同一获取业务领取或购买物品。已经结算且具有长期影响的结果可以成为人生节点；长期人物记忆仍未接入。AI失败直接提示检查网络或账户余额，不自动重试。

### 4. NPC 对话

固定NPC包括父亲、母亲、私塾先生、一名同窗、县试考官和书商。玩家与NPC共用数据和行动入口，MVP不自动运行后台NPC生活模拟。

对话依据当前人物、场景、物品和本场历史回应，不拥有全知视角。普通往返可以执行本轮明确的获取/购买，但不逐轮发属性；玩家手动结束或模型决定结束后，整场进行一次属性结算。获取与属性最终都由Java业务执行，不以模型口头表示“送了书”作为入包事实。

## 六、书籍与成长反馈

七本学校教材是《三字经》《千字文》《论语》《孟子》《大学》《诗经》《名家文钞》，需要向先生执行免费获取行为才入包。书商另提供《经世策论集》《八股破题精义》《GPT-1的权重》三本付费书籍。

现代参数书是穿越题材的整活内容，不因违背明代物品年代而删掉；真实书名、参数集性质及游戏抽象边界见[机制总览](./MVP机制总览与待定事项.md)。

每本书拥有0～100整数进度和独立的满额学识，不设25/60知识档位。未读为0，1～99按进度取得满额学识的六成部分，100取得全部学识。总量汇总所有读过的书；同一种书持有多本不重复贡献，失去物品也不抹去已学进度。

书籍难度、基础进度、能力权重和阅读条件来自内容配置。已持有仍须满足阅读条件；普通读档不会补发教材，价格为0也不是开局自动赠送。

## 七、考试体验

每次考试都提供同样的两种参与方式：

- “系统代行”：角色按自身能力和当时身体状态作答。
- “以身入局”：玩家亲自输入答案，内容评价作为额外修正，但不会替代角色能力。

题目出现时，界面先展示角色的思维泡泡。泡泡只能使用角色已经学到的知识，能力越高越有条理，但不会直接给出完整范文。

成绩确定后，AI 只负责生成与分数和结果一致的答卷表现、评价和叙事，不能反向修改成绩。

当前实现带已保存骰点的系统代行计分和固定文本反馈，不生成AI思维泡泡、完整答卷或评价。骰点1必失败、100必高分通过，其余点数用两端影响较大的曲线修正；不设置或保存种子。考试不额外消耗普通回合，结算后按考试类型继续求学或完成存档。

## 八、页面范围

前端目标为五类页面，目前尚未实现：

1. 入口/存档页：新开局、读档，显示主角姓名、年龄、日期、关键身份和创建时间；未知身份留空。
2. 出生页：角色名、博罗县或海丰县、开始人生。
3. 成长页：日期、人物状态、能力、学识、钱包、背包、初始家庭背景、所在地、场景、行动和NPC。
4. 考试页：考试名称、题目、系统代行；思维泡泡与玩家作答为待接入目标。
5. 结果页：县试成绩、通过状态、关键经历和本局结束提示。

阶段考试复用考试页，完成后返回成长页；县试完成后进入结果页。

## 九、技术边界

后端使用 Java 17、Spring Boot、Spring AI、LangGraph4j、MyBatis-Plus 和 MySQL，保持模块化单体。

- JSON：可调整的书籍、场景、行动、考试和文本内容。
- Java 常量：稳定编码和规则边界。
- Engine：确定性数值关系。
- Resolver：自然语言理解与叙事。
- MySQL：地区定义和存档事实。
- Service：用例编排和事务。

本阶段不实现动态地图、移动耗时、后台NPC行动、完整行政区全集、官职权限、政策、战争、完整商业经营、府试、院试或县试后人生。商人售书只是最小交易入口，不代表已经实现经济模拟。复杂全局并发竞争和种子管理暂不处理。

## 十、产品完成标准

以下是目标体验，不表示未接入的前端与考试AI已经完成；当轮源码机制与待商榷参数以[机制总览](./MVP机制总览与待定事项.md)为准。

- 出生页只能选择博罗县或海丰县，并能一键进入六岁。
- 开局年份、属性、健康、疲劳、能力和初始家庭背景符合固定初值。
- 每月四回合可以持续推进，固定行动不依赖模型。
- 阅读进度和考试分数始终为整数。
- 8、12、15 岁会暂停普通行动并进入对应阶段考试，结算后继续成长。
- 16 岁进入县试，支持系统代行和以身入局，结算后完成存档。
- 自由行动和 NPC 对话遵守“Resolver 解释、Engine 结算、数据库保存事实”的边界。
