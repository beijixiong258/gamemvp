# 接口与方法

> 本文说明程序分工、调用方法和返回数据。计算公式见[规则与数值](../MVP/规则与数值.md)，配置字段见[资源配置](./资源配置.md)。

源码是方法签名的依据；MyBatis-Plus 自带的增删改查方法不重复列出。下文的 Engine 负责数值计算，Resolver 负责调用 AI 解析输入，Service 负责业务处理和保存结果。

## 一、程序分工

| 组件 | 包名 | 是否访问数据库 | 是否调用模型 | 是否推进时间 |
|---|---|---:|---:|---:|
| `CharacterEngine` | `mvp.engine` | 否 | 否 | 否 |
| `TurnEngine` | `mvp.engine` | 否 | 否 | 是，由调用方显式调用 `advance` |
| `ExamEngine` | `mvp.engine` | 否 | 否 | 否 |
| `GameClient` | `mvp.ai` | 否 | 是 | 否 |
| `FreeActionWorkflow` | `mvp.ai` | 否 | 是 | 否 |
| `GameSaveService` | `mvp.service` | 是，读取数据与保存结果 | 协调自由行动及考试调用 | 普通行动及强制休养推进 |
| `EquipmentRecordService` | `mvp.service` | 是，钱包、入包及结果记录 | 否 | 否 |
| `DialogueRecordService` | `mvp.service` | 是，历史、交易及结束结算 | 是 | 普通对话不推进，重病例外 |
| `BookService` | `mvp.service` | 是，定义与阅读进度 | 否 | 否 |
| `ExamRecordService` | `mvp.service` | 是，考试快照、思路与结算 | 思路、答案评价、答卷及总结 | 否 |
| `RegionService` | `mvp.service` | 是，只读查询 | 否 | 否 |

`mvp.controller` 放接口入口，`mvp.entity` 放实体，`mvp.mapper` 访问数据库，`mvp.service` 和 `mvp.service.impl` 放业务接口与实现。同一实体保留 `IService`、`ServiceImpl`，相关业务集中在对应 Service。`mvp.ai` 处理 AI 调用，`mvp.engine` 计算数值，`mvp.utils` 提供计算与资源读取工具；根包只放启动类。

三个 Engine 不保存内部状态。调用方传入完整的当前数据，保存计算结果，并保证同一存档的写操作按顺序执行。目前没有统一的空值、参数范围检查层。

### 领域边界与扩展

MVP 以打通功能和数据链路、保留清晰的扩展边界为目标，不以减少类的数量为目标。

| 领域入口 | 当前链路 | 扩展边界 |
|---|---|---|
| `CharacterController` | 尚无 HTTP 方法；角色创建、读取与行动结算经存档流程和 `CharacterService` 完成 | 玩家和 NPC 共用角色模型；独立人物查询按页面需求增加 |
| `CareerController` | 尚无 HTTP 方法；书生档案已参与开局、阅读及考试 | 各领域使用具体档案和对应 Service，可以同时拥有，不引入互斥主职业 |
| `MemoryController` | 尚无 HTTP 方法；仅有记忆存储结构和提示词 | 总结与检索应接入对话、行动的内部流程；首版范围仍待确定，不要求先暴露表的 CRUD |

`GameSaveService` 负责存档聚合、共享时间及跨领域结算事务；书籍、装备、对话和考试已有各自的业务 Service。角色与书生档案当前仍由存档流程组织读写，新增领域业务归入其对应 Service，不持续向存档服务堆叠独立规则。

加载游戏继续使用存档聚合查询；独立领域查询复用相同 Service，不另写一套业务。影响属性、背包或职业成就的写操作经过行动与结算流程，不通过通用修改接口绕过游戏规则。

## 二、`CharacterEngine`

源码：[CharacterEngine.java](../../src/main/java/mvp/engine/CharacterEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `startLife(String birthRegionId)` | 创建六岁时的人物、书生能力、初始家庭背景和所在地数据副本 | `birthRegionId`：业务层已经选定的出生地区 ID | `StartLifeResult` |
| `intelligenceFactor(CharacterState character)` | 计算学习类行动使用的智力效率系数 | `character`：行动前的人物数据 | `BigDecimal` 系数 |
| `conditionFactor(CharacterState character)` | 根据健康、体能和疲劳计算身体状态效率 | `character`：行动前的人物数据 | `BigDecimal` 系数 |
| `fatigueGain(int baseFatigue, CharacterState character)` | 把行动基础疲劳换算为实际疲劳增长 | `baseFatigue`：配置值；`character`：行动前的人物数据 | 非负整数增长量 |
| `exhaustionDamage(int fatigueAfter)` | 计算行动后疲劳造成的过劳伤害 | `fatigueAfter`：已经结算的疲劳 | 非负整数健康损失 |
| `readBook(CharacterState character, ScholarState scholar, BookRule book, BookProgress progress, long settlementTurnNumber, int diceRoll)` | 一次性结算阅读进度、书生能力、疲劳和过劳伤害 | 人物、能力、书籍规则、原阅读记录、结算回合及服务端骰点 | `ReadBookResult` |
| `practiceWriting(CharacterState character, ScholarState scholar)` | 结算一次文章练习 | 人物与书生能力 | `PracticeWritingResult` |
| `rest(CharacterState character)` | 结算一次疲劳与健康恢复 | 行动前的人物数据 | `RestResult` |
| `applyDriver(CharacterState character, ScholarState scholar, DriverPatch patch)` | 应用自由行动 Resolver 给出的按约定字段返回的变化量 | 人物、书生能力和变化量 | `DriverResult` |
| `knowledgeContribution(int totalKnowledge, int progress)` | 计算单书的实际学识贡献 | 整书学识量、整数进度 | `BigDecimal` 学识 |
| `limitDriver(DriverPatch patch)` | 限制AI单场变化量，缺省数值按0 | 原始变化量 | 有界 `DriverPatch` |
| `enterIllness(CharacterState current)` | 计算首次重病的五维损失 | 人物状态 | `CharacterState` |
| `recoverIllnessTurn(CharacterState current, boolean lastTurn)` | 计算一个强制休养回合 | 人物状态、是否最后一回合 | `CharacterState` |

### 调用注意事项

- `startLife` 不创建时间状态；业务层还需要调用 `TurnEngine.startLife()`。
- 骰点在业务层生成，Engine不生成随机数；读书结果记录和考试开始时的数据负责保存实际骰点。
- `readBook` 的 `settlementTurnNumber` 是本次行动完成后的累计回合编号，用于写入 `BookProgress.lastReadTurnNumber`。
- `readBook`、`practiceWriting`、`rest` 和 `applyDriver` 只返回结算结果，不保存实体。
- `applyDriver` 接收 `BigDecimal` 变化量，由引擎限制驱动量、统一取整并限制最终状态范围。Resolver 不应直接生成最终状态。
- 进度、能力、疲劳增量及健康恢复量按限制范围后的实际变化返回；`exhaustionDamage` 是规则计算的过劳伤害，实际健康差额以人物前后状态为准。

## 三、`TurnEngine`

源码：[TurnEngine.java](../../src/main/java/mvp/engine/TurnEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `startLife()` | 创建六岁开局时的日历与流程状态 | 无 | `TurnState` |
| `advance(TurnState current, boolean endTurn)` | 根据行动是否结束回合推进月内回合、月份、年份和年龄，并识别考试节点 | `current`：结算前时间；`endTurn`：行动是否消耗回合 | `TurnResult` |
| `completeExam(TurnState current, String examType)` | 完成玩家考试流程；阶段考试回到求学，县试结束本局 | 当前时间状态和玩家考试类型编码；调用方保证归属 | 更新后的 `TurnState` |
| `examTypeAtAge(int age)` | 查询指定周岁对应的固定考试 | `age`：周岁 | 考试编码；没有考试时为 `null` |
| `jiajingYear(int currentYear)` | 把公元年份转换成嘉靖年序 | `currentYear`：公元年份 | 嘉靖年序整数 |

`advance` 是唯一推进普通时间的方法。`endTurn=false` 时返回原 `TurnState`，不会递增任何时间字段；考试结算本身不应再次调用它。

### 时间状态

`TurnState`

| 字段 | 类型 | 含义 |
|---|---|---|
| `birthYear` | `int` | 玩家出生年份 |
| `currentYear` | `int` | 当前公元年份 |
| `currentMonth` | `int` | 当前月份 |
| `turnInMonth` | `int` | 即将进行的月内回合 |
| `age` | `int` | 玩家按游戏年份计算的年龄，不代表行动 NPC 的年龄 |
| `totalTurnNumber` | `long` | 已完成的玩家、NPC 行动和强制休养回合数 |
| `status` | `String` | 存档流程状态 |
| `growthStage` | `String` | 成长阶段 |

`TurnResult`

| 字段 | 类型 | 含义 |
|---|---|---|
| `state` | `TurnState` | 推进后状态；未结束回合时为原状态 |
| `triggeredExamType` | `String` | 本次跨年触发的考试编码；没有时为 `null` |
| `finalExam` | `boolean` | 是否触发十六岁县试 |

常见输出状态：

| `status` | `growthStage` | 含义 |
|---|---|---|
| `STUDYING` | `STUDYING` | 正常求学阶段 |
| `STAGE_EXAM_READY` | `STAGE_EXAM` | 八岁、十二岁或十五岁阶段考试待结算 |
| `EXAM_READY` | `EXAM` | 十六岁县试待结算 |
| `COMPLETED` | `COMPLETED` | 县试结算完成，本局结束 |

## 四、`ExamEngine`

源码：[ExamEngine.java](../../src/main/java/mvp/engine/ExamEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `prepare(CharacterState character, ScholarState scholar, BigDecimal knowledgeTotal, ExamWeights weights)` | 汇总知识、能力和身体状态，建立考试数值记录 | 人物、书生能力、全部学识及题目权重 | `ExamPreparation` |
| `knowledgeScore(BigDecimal knowledgeTotal)` | 把全部学识换算为考试知识分 | 不封顶的总学识 | `0`～`100` 的知识值 |
| `luckOffset(int diceRoll)` | 用立方曲线计算普通骰点修正 | 1～100骰点 | 整数修正，准备考试时保存 |
| `baseAbilityScore(CharacterState character, ScholarState scholar, int knowledgeScore, ExamWeights weights)` | 按题目权重计算基础能力分 | 人物、书生能力、知识值和权重 | `0`～`100` 的整数分 |
| `stateOffset(CharacterState character)` | 根据健康、疲劳和体能计算临场偏移 | 考试开始时人物数据 | `-8`～`4` 的整数偏移 |
| `thoughtLevel(int score)` | 把可发挥分映射为思维泡泡层级 | 通常传入基础能力分与临场偏移之和 | `ThoughtLevel` |
| `settleAuto(int baseAbilityScore, int stateOffset, int diceRoll, int luckOffset, int passThreshold)` | 结算系统代行路径 | 已保存的基础分、身体偏移、骰点、骰点修正和通过线 | `ExamResult` |
| `settlePlayer(int baseAbilityScore, int stateOffset, BigDecimal contentModifier, int diceRoll, int luckOffset, int passThreshold)` | 玩家作答的计分入口，已接入HTTP与AI评价流程 | 已保存的数据、AI内容修正及通过线 | `ExamResult` |

`settlePlayer` 先把 BigDecimal 类型的 `contentModifier` 限制在 `-10`～`10`，再四舍五入为整数，避免异常大值转为 int 时溢出。两个结算方法都先使用已保存的骰点修正，再应用1/100极端结果；以 Java 计算结果为最终事实，模型生成内容不得反向修改成绩或通过状态。

### 考试数据结构

`ExamWeights`

| 字段组 | 类型 | 来源 |
|---|---|---|
| `characterZhili`、`characterDaode`、`characterZhengzhi`、`characterJiaoji`、`characterTineng` | `BigDecimal` | `exam.json` 的 `exam[].question[].generalAbilityWeight` |
| `abilityShizi`、`abilityJingyi`、`abilityWenzhang`、`abilityCelun`、`abilityWenxue` | `BigDecimal` | `exam.json` 的 `exam[].question[].careerAbilityWeight` |
| `knowledge` | `BigDecimal` | `exam.json` 的 `exam[].question[].knowledgeWeight` |

| 类型 | 字段及含义 |
|---|---|
| `ExamPreparation` | `knowledgeScore`：知识值；`baseAbilityScore`：基础能力分；`stateOffset`：临场偏移；`thoughtLevel`：思维层级 |
| `ExamResult` | `finalScore`：最终整数分；`effectiveContentModifier`：实际采用的内容修正；`passed`：是否通过；`status`：`COMPLETED_PASS` 或 `COMPLETED_FAIL` |

`ThoughtLevel` 的枚举值为 `DIFFICULT`、`BASIC`、`ORGANIZED`、`CONFIDENT`。

## 五、AI 配置与模型调用

### `GameClient.chat`

源码：[GameClient.java](../../src/main/java/mvp/ai/GameClient.java)

```java
<T> T chat(String promptCode, String userText, Class<T> type)
```

| 参数 | 含义 |
|---|---|
| `promptCode` | `prompt.json` 中的稳定提示词编码 |
| `userText` | 本次调用的动态输入和游戏上下文 |
| `type` | Spring AI 将响应映射到的结构化结果类型 |

`GameClient` 创建时加载 `prompt/prompt.json`，按编码查找提示词。调用时组合系统提示词与 `userText`，将模型结果转为 `T`。编码不存在时抛出 `IllegalArgumentException`；调用失败或返回空值时报 HTTP 502，提示检查网络或模型账户余额，不自动重试。该类不处理事务或保存存档，当前不向模型注册工具；获取意图交给 Service 执行。

## 六、自由行动 LangGraph

源码：[FreeActionWorkflow.java](../../src/main/java/mvp/ai/FreeActionWorkflow.java)、[FreeActionResolver.java](../../src/main/java/mvp/ai/FreeActionResolver.java)、[FreeActionState.java](../../src/main/java/mvp/ai/FreeActionState.java)

### `FreeActionWorkflow.execute`

```java
FreeActionResult execute(FreeActionCommand command)
```

图内的 `FreeActionCommand` 包含 `playerText`、`contextSummary`、`character` 和 `scholar`，不同于 HTTP 请求中的同名类型。场景由 `contextSummary.scene` 提供；`character`、`scholar` 是引擎结算用的类型化快照，不再次拼入模型输入。方法执行固定的两节点图，并返回 `settlement`、`eventSummary`、`lifeMilestone` 和 `acquisitions`：

```text
START → resolve_action → settle_driver → END
```

- `resolve_action` 调用 `FreeActionResolver.resolve`，把模型给出的 `FreeActionResolution` 写入图状态。
- `settle_driver` 只把其中的 `DriverPatch` 交给 `CharacterEngine.applyDriver`，由 Java 产生最终 `DriverResult`。

`FreeActionState` 是节点间的单次调用状态，不是数据库实体。状态中的 `character`、`scholar`、`resolution` 和 `settlement` 可序列化，以适配 LangGraph4j 的默认状态复制机制。

### `FreeActionResolver.resolve`

```java
FreeActionResolution resolve(String playerText, String contextSummary)
```

`playerText` 是本次行动原文，`contextSummary` 是业务层准备的完整事实 JSON。方法组装 `{ "currentText": 原文, "facts": 事实对象 }`，通过 `GameClient` 使用 `PROMPT_FREE_ACTION` 得到结构化结果；固定输出规则只在 `prompt.json` 中维护。`FreeActionResolution` 包含 `driverPatch`、`eventSummary`、`lifeMilestone` 和 `acquisitions`，不包含最终状态。`lifeMilestone` 是事件语义标记，不从属性变化分数推导。

`GameSaveService` 在调用前准备数据，模型返回后核对并保存。图只处理本次调用，不访问数据库、不推进时间或生成记忆；获取意图也须可序列化，扣款和发货由业务层执行。

### `FreeActionResolver.resolveDialogue(String context)`

接收结构化 `facts`、对话对象 `counterpart`、本场 `history`、当轮 `currentText` 及 `manualEnd`，返回 `DialogueResolution(reply, endDialogue, driverPatch, acquisitions)`。`facts` 复用下文 `prepareAction` 的完整事实，作为 JSON 对象传入，不是嵌套转义字符串。普通轮返回回应和获取意图，结束轮才给出整场属性变化量。对话 Service 直接调用此方法，不经过 LangGraph。

`AcquisitionIntent(supplierNpcCode, equipmentCode, quantity)` 不包含价格、余额、最终持有数量或阅读进度，真实执行由 `EquipmentRecordService` 完成。

## 七、存档与行动

| `prepareContent(String saveId)` | 为已升级旧存档补齐缺失NPC和定义，不发物品 | 无 |
| `executeFixedAction(String saveId, FixedActionCommand command)` | 玩家固定行动入口 | `JSONObject`，结构为ActionResult |
| `executeCharacterAction(String saveId, String actorId, FixedActionCommand command)` | 任一人物执行固定行动；actorId为空时使用玩家 | 同上 |
| `prepareExamThought(String saveId, String examId)` | 获取或生成玩家考试的思路缓存，不结算考试 | `ExamRecord` |
| `completeAutoExam(String saveId, String examId)` | 玩家系统代行计分、生成答卷与总结、保存结果 | `ExamResult` |
| `completePlayerExam(String saveId, String examId, PlayerExamCommand command)` | 评价玩家原文、程序计分并生成总结；同请求返回原响应 | `JSONObject`，结构为ExamResult |
| `completeCharacterExam(String saveId, String actorId, String examId)` | 指定人物系统代行；考试必须属于该人物，仅玩家考试切换存档阶段 | `ExamResult` |
| `prepareAction(String saveId, String actorId, String sceneCode)` | 读取模型调用前事实，要求求学且未重病 | `ActionContext` |
| `executeFreeAction(String saveId, String actorId, FreeActionCommand command)` | 重传先查结果记录，再运行LangGraph并事务结算 | `JSONObject` |
| `settleAiAction(ActionContext before, String requestId, Object payload, DriverResult settlement, List<AcquisitionIntent> acquisitions, boolean endTurn, String summary, boolean milestone)` | 核对调用前的数据，执行交易、应用属性、推进时间和记录结果；普通对话的settlement为空 | `JSONObject` |

`ActionContext` 包含 saveId、actorId、turnNumber、sceneCode、character、scholar、contextSummary。模型调用不持有数据库事务；回写前重新锁定存档，核对回合、人物和书生能力。获取造成钱包变化后重新读取人物，避免随后属性保存覆盖扣款。

`contextSummary` 是以下事实对象的 JSON 文本，由自由行动与对话共用：

| 字段 | 含义 |
|---|---|
| `calendar` | 当前游戏的 `currentYear`、`currentMonth`、`turnInMonth`、`totalTurnNumber`，不是现实系统日期 |
| `actor`、`actorAge` | 行动人物及其年龄；年龄按当前游戏年份减该人物生日年份计算，不直接使用存档中的玩家年龄 |
| `scholar` | 行动人物当前的五项书生能力，与用于引擎结算的 `ScholarState` 快照一致 |
| `playerFamilyBackground` | 本存档玩家的初始家庭背景；不是任意 NPC 的家庭档案，也不是可支配资金 |
| `scene` | 本次指定场景及其可用内容 |
| `books` | 行动人物的书目、阅读进度、可读条件、持有数量和学识贡献 |
| `npcs` | 本存档启用的 NPC；实际是否在场仍由 `scene.availableNpcCode` 决定 |

### 请求与返回结构

| 类型 | 字段与含义 |
|---|---|
| `StartLifeCommand` | characterName、birthRegionId |
| `FixedActionCommand` | requestId、actionCode、sceneCode、bookCode、expectedTurnNumber |
| `FreeActionCommand` | requestId、sceneCode、text、expectedTurnNumber |
| `PlayerExamCommand` | requestId：稳定请求编号，最多120字符；text：答案原文，非空白且不超过8000字符 |
| `StartLifeResult` | save、character、familyBackground、scholarProfile，均为已保存的实体 |
| `SaveDetail` | 上述四项，加books、exams、milestones、knowledgeTotal、backpack、npcs |
| `SaveSummary` | saveId、characterName、age、currentYear、status、createdAt、officialPosition、officialRank、degree、titles |
| `ActionChanges` | progressGain、abilityGain、fatigueChange、healthChange、diceRoll；非读书的diceRoll为空 |
| `ActionResult` | detail、changes、feedback |
| `ExamResult` | detail、exam、newlySettled、feedback |

固定行动实际返回保存为JSON的ActionResult，方便网络重传直接返回原响应。玩家答案提交同样保存ExamResult的JSON，重传原样返回；系统代行重传返回原考试与最新detail，newlySettled=false。AI行动结果包含 requestId、actorId、summary、trades、detail。身份字段为空时不推导虚构身份；titles初始为 []。

固定行动支持 READ_BOOK、PRACTICE_WRITING、REST。expectedTurnNumber为调用方最后读到的save.totalTurnNumber，不是结算后的回合；重病触发时一次请求可能额外推进多个强制回合，以响应中的时间为准。

## 九、对话与请求结果

接口：[DialogueRecordService.java](../../src/main/java/mvp/service/DialogueRecordService.java)、[EventRecordService.java](../../src/main/java/mvp/service/EventRecordService.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `start(String saveId, String actorId, StartDialogueCommand command)` | 创建整场对话；command为requestId、counterpartId、sceneCode | 对话JSON，初始version=0 |
| `respond(String saveId, String dialogueId, DialogueCommand command)` | 发言或结束；command为requestId、text、expectedVersion、endDialogue | dialogue、reply、applied |
| `loadDialogue(String saveId, String dialogueId)` | 读取历史和当前版本 | `DialogueRecord` |
| `EventRecordService.replay(String saveId, String requestId, Object payload)` | 同一存档查已执行结果，并比对原始参数 | 已存JSON或null；参数不同拒绝 |
| `recordOperation(String saveId, String actorId, String requestId, Object payload, String code, long turnNumber, Object result)` | 保存非人生节点的请求结果记录 | 无 |

普通对话可以执行本轮获取意图，但不应用属性。手动endDialogue=true时text可为空，只总结历史，不重做旧交易；模型也可通过endDialogue结束。结束标志、属性、历史与结果记录一并提交，已经结束不能再产生第二次属性结算。

对话消息和自由行动的requestId最多100字符，其余普通结果记录入口最多120字符，建议统一使用UUID。不复用同一个编号表达不同操作；本次失败未形成结果记录时可沿用编号重试。系统内部给附属交易追加后缀，客户端不要自行使用这些内部编号。

模型失败返回502，状态冲突通常返回409。失败请求不自动推进回合；已有成功对话轮的交易不会因为后续结束失败而撤销。

## 十、考试与地区服务

接口：[ExamRecordService.java](../../src/main/java/mvp/service/ExamRecordService.java)、[RegionService.java](../../src/main/java/mvp/service/RegionService.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `ExamRecordService.prepare(GameSave save, String characterId, CharacterState character, ScholarState scholar, BigDecimal knowledgeTotal)` | 节点回合完成后保存题目、通过线、B/R、总学识、骰点和骰点修正 | READY状态的ExamRecord |
| `loadForCharacter(GameSave save, String characterId, String examId)` | 校验考试归属；未完成记录还须符合当前阶段和回合 | `ExamRecord` |
| `generateThought(ExamRecord exam, String characterContext)` | 在事务外生成思路，已有文本直接复用 | `String` |
| `saveThought(GameSave save, String characterId, ExamRecord before, String thought)` | 在存档锁事务内核对快照、保存或复用思路 | `ExamRecord` |
| `resolveAuto(ExamRecord exam, String characterContext)` | 程序计分后生成答卷和总结；已完成则复用 | `ExamResolution` |
| `resolvePlayer(ExamRecord exam, String playerInput, String characterContext)` | 评价原文、程序计分、生成总结；已提交的不同答案被拒绝 | `ExamResolution` |
| `settleResolved(GameSave save, String characterId, ExamRecord before, ExamResolution resolution)` | 在存档锁事务内核对快照并写入全部结果，不推进阶段 | `ExamSettlement(exam, newlySettled)` |
| `listForSave(String saveId)` | 按发生回合读取存档内全部考试 | `List<ExamRecord>` |
| `RegionService.listMvpBirthRegions()` | 用初始化数据中的惠州ID定位父节点，返回其启用的直属子节点，不指定显示顺序 | `List<Region>` |

`GameSaveServiceImpl.prepareTriggeredExam` 始终选择玩家作为节点考试的应考人，使用节点回合结算后的玩家数据。NPC 可以共用计分入口，但当前不自动创建独立 NPC 考试；NPC 成绩只更新自己的考试、领域活跃回合及事件，不改变存档阶段。

考试结算本身不消耗普通回合；玩家阶段考试后会继续玩家尚未结束的强制休养，NPC 剩余休养在下次自身固定行动时处理。两种作答方式通过GameSaveServiceImpl.finishExam统一切换阶段、记人生节点和处理休养。

GameSaveServiceImpl先在短事务中锁存档并读取考试与人物事实，释放事务后调用ExamRecordService生成内容，最后再锁存档保存。模型调用使用项目现有GameClient的结构化输出，事务边界采用TransactionTemplate，参考[Spring AI实体输出](https://docs.spring.io/spring-ai/reference/api/chatclient.html#_returning_an_entity)与[Spring编程式事务](https://docs.spring.io/spring-framework/reference/data-access/transaction/programmatic.html)。IService和ServiceImpl继续保留，考试业务集中在同一个Service。

characterContext包含人物姓名、游戏年份、人物年龄、七项通用状态、五项书生能力，以及currentProgress>0的书籍名称、进度、完成状态和知识介绍。思路和评价输入包含冻结的题目、评分点、B/R、学识及thoughtLevel，不提供骰点或最终成绩；答卷与总结输入另带Java已确定的confirmedResult。AI输出分别映射为ThoughtOutput(thought)、EvaluationOutput(contentModifier, evaluation)、NarrativeOutput(answerText, summary)。

思路只生成并保存一次，不消耗回合；已结束且没有缓存的考试不再生成思路。系统代行发起一次模型调用生成答卷和总结，玩家交卷先评价再总结，共两次模型调用。全部生成成功后才提交考试；模型调用失败、空文本、缺失内容修正或过长输出返回502，考试保持待考。文本长度上限：思路3000、代行答卷8000、评价和总结各4000字符。

请求结果由 `EventRecordServiceImpl` 使用与 HTTP 响应相同的 Spring `JsonMapper` 序列化保存，确保重放时日期等字段的值和类型保持一致。提交时仍校验考试归属、阶段、回合及冻结计分字段；不同方式或不同原文不能覆盖已完成考试。并发相同提交仅保留首份结算，但同时发起时可能产生重复模型调用。已完成考试不再调用模型或补写历史内容。

典型调用：查询出生地 → 开局并取得实际saveId/characterId → 领取教材 → 读取详情 → 提交行动 → 以响应中的最新回合继续。示例参数中的真实ID需从响应取得，不可把编码当成数据库ID。

```json
{
  "requestId": "claim-001",
  "sceneCode": "SCENE_SISHU",
  "supplierNpcCode": "NPC_XIANSHENG",
  "equipmentCode": "BOOK_SANZIJING",
  "quantity": 1
}
```

领取成功后，再提交独立的读书请求：

```json
{
  "requestId": "read-001",
  "actionCode": "READ_BOOK",
  "sceneCode": "SCENE_SISHU",
  "bookCode": "BOOK_SANZIJING",
  "expectedTurnNumber": 0
}
```

0仅适用于尚未经过回合的新存档。网络超时原样重传；新的行为使用新编号和最新回合。对话同理，每轮使用响应中的version作为下一轮expectedVersion。

### 考试调用

存档进入STAGE_EXAM_READY或EXAM_READY后，从detail.exams选择属于玩家且status=READY的考试。先调用thought接口取得思路，再选择player或auto交卷；两个交卷入口互斥。

玩家交卷示例：

```json
{
  "requestId": "exam-player-001",
  "text": "这里填写玩家针对当前题目的完整答案。"
}
```

响应中exam.playerInput保留原文，aiPlayerContentModifier为-10至10的整数，finalScore为程序计分，aiContent包含评价与总结。系统代行另返回aiAnswerText完整答卷。前端以detail.save.status决定回到成长页或展示结局。

## 十二、通用工具

### `Calculator`

[`mvp.utils.Calculator`](../../src/main/java/mvp/utils/Calculator.java) 提供 BigDecimal 构造、百分比转换、固定精度除法、HALF_UP 取整和 clamp。类为 public final，构造器私有；跨包使用的方法和 ONE 常量为 public static。它不作为 Spring Bean 或业务入口，数值计算统一复用这套精度规则。

### `ClasspathJsonLoader.load`

源码：[ClasspathJsonLoader.java](../../src/main/java/mvp/utils/ClasspathJsonLoader.java)

```java
<T> T load(String resourcePath, Class<T> type)
```

`resourcePath` 是相对于 classpath 根目录的路径，`type` 是目标 Java 类型。该组件使用 Hutool 读取 UTF-8 文本并反序列化；读取或转换失败时包装为 `IllegalStateException`。提示词、书籍、考试及场景等资源共用该组件，业务 Service 不因读取 JSON 而依赖 AI 包。

旧库先按[数据结构与升级](./数据结构与升级.md#十数据库升级)确认结构升级方式；更改schema或JSON不会自动迁移存档。

修改方法时同步检查签名、输入输出字段、数据库或模型调用、时间推进及调用顺序。资源引用另见[资源配置](./资源配置.md)。
