## 使用约定

源码是方法签名的最终依据，JSON 文件是静态配置值的最终依据。本目录负责解释如何调用和维护它们；签名或配置结构变化时，应在同一次修改中同步对应参考文档。

`prompt/prompt.json` 由 `GameClient` 加载供自由行动和对话Resolver使用。教材定义按编码补充入库，已有定义不会因修改JSON自动覆盖；免费教材也必须实际获取才入包。NPC原型已用于开局生成，考试AI和长期记忆提示词仍预留。旧库升级方式见数据模型文档，运行时资源边界见《资源 JSON 参考》。

持久化代码按 MyBatis-Plus 常规技术层组织：Controller 统一放在 `mvp.controller`，实体放在 `mvp.entity`，Mapper 放在 `mvp.mapper`，Service 接口放在 `mvp.service`，实现类放在 `mvp.service.impl`。同一业务实体仍保留 `IService` 与 `ServiceImpl`，具体业务尽量归入对应 Service。`mvp.ai` 和 `mvp.engine` 分别承载模型编排与确定性规则；根包 `mvp` 只保留应用启动类。

## 更新检查清单

修改核心方法时检查：

1. 方法签名、参数类型和返回类型是否同步。
2. 输入输出 `record` 的字段是否同步。
3. 方法是否新增数据库、模型调用或时间推进等副作用。
4. 调用顺序是否仍符合《MVP 引擎设计》。

修改 JSON 时检查：

1. 根属性和字段类型是否保持一致。
2. 被引用的编码是否确实存在。
3. 场景与行动、场景与 NPC 的双向配置是否一致。
4. 书籍能力权重是否合计为 `100`，考试权重是否合计为 `1.00`。
5. 新增模板变量时，调用方是否提供同名值。
