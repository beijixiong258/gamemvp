# 核心方法参考

> 本文对应当前 Java 源码，只记录可供业务层调用的自定义方法和它们使用的数据结构。数值公式见[《MVP 引擎设计》](../MVP引擎设计.md)。MyBatis-Plus 继承的通用 CRUD、无业务方法的 Mapper 和 Controller 不在本文重复列出。

## 一、调用边界

| 组件 | 包名 | 是否访问数据库 | 是否调用模型 | 是否推进时间 |
|---|---|---:|---:|---:|
| `CharacterEngine` | `mvp.engine` | 否 | 否 | 否 |
| `TurnEngine` | `mvp.engine` | 否 | 否 | 是，由调用方显式调用 `advance` |
| `ExamEngine` | `mvp.engine` | 否 | 否 | 否 |
| `GameClient` | `mvp.ai` | 否 | 是 | 否 |
| `FreeActionWorkflow` | `mvp.ai` | 否 | 是 | 否 |
| `GameSaveService` | `mvp.service` | 是，快照与结算 | 自由行动调用 | 普通行动及强制休养推进 |
| `EquipmentRecordService` | `mvp.service` | 是，钱包、入包及回执 | 否 | 否 |
| `DialogueRecordService` | `mvp.service` | 是，历史、交易及结束结算 | 是 | 普通对话不推进，重病例外 |
| `BookService` | `mvp.service` | 是，定义与阅读进度 | 否 | 否 |
| `ExamRecordService` | `mvp.service` | 是，考试快照与结算 | 否 | 否 |
| `RegionService` | `mvp.service` | 是，只读查询 | 否 | 否 |

三个 Engine 都是无状态计算类。调用方负责传入完整快照、保存返回结果，并保证同一存档的写操作按顺序执行。当前方法没有统一的空值或参数范围校验层。

## 二、`CharacterEngine`

源码：[CharacterEngine.java](../../src/main/java/mvp/engine/CharacterEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `startLife(String birthRegionId)` | 创建六岁时的人物、书生能力、初始家庭背景和所在地快照 | `birthRegionId`：业务层已经选定的出生地区 ID | `StartLifeResult` |
| `intelligenceFactor(CharacterState character)` | 计算学习类行动使用的智力效率系数 | `character`：行动前人物快照 | `BigDecimal` 系数 |
| `conditionFactor(CharacterState character)` | 根据健康、体能和疲劳计算身体状态效率 | `character`：行动前人物快照 | `BigDecimal` 系数 |
| `fatigueGain(int baseFatigue, CharacterState character)` | 把行动基础疲劳换算为实际疲劳增长 | `baseFatigue`：配置值；`character`：行动前人物快照 | 非负整数增长量 |
| `exhaustionDamage(int fatigueAfter)` | 计算行动后疲劳造成的过劳伤害 | `fatigueAfter`：已经结算的疲劳 | 非负整数健康损失 |
| `readBook(CharacterState character, ScholarState scholar, BookRule book, BookProgress progress, long settlementTurnNumber, int diceRoll)` | 一次性结算阅读进度、书生能力、疲劳和过劳伤害 | 人物、能力、书籍规则、原阅读记录、结算回合及服务端骰点 | `ReadBookResult` |
| `practiceWriting(CharacterState character, ScholarState scholar)` | 结算一次文章练习 | 人物和书生能力快照 | `PracticeWritingResult` |
| `rest(CharacterState character)` | 结算一次疲劳与健康恢复 | 行动前人物快照 | `RestResult` |
| `applyDriver(CharacterState character, ScholarState scholar, DriverPatch patch)` | 应用自由行动 Resolver 给出的结构化驱动量 | 人物、书生能力和驱动量 | `DriverResult` |

| `knowledgeContribution(int totalKnowledge, int progress)` | 计算单书的实际学识贡献 | 整书学识量、整数进度 | `BigDecimal` 学识 |
| `limitDriver(DriverPatch patch)` | 收束AI单场驱动量，缺省数值按0 | 原始驱动量 | 有界 `DriverPatch` |
| `enterIllness(CharacterState current)` | 计算首次重病的五维损失 | 人物状态 | `CharacterState` |
| `recoverIllnessTurn(CharacterState current, boolean lastTurn)` | 计算一个强制休养回合 | 人物状态、是否最后一回合 | `CharacterState` |

### 调用注意事项

- `startLife` 不创建时间状态；业务层还需要调用 `TurnEngine.startLife()`。
- 骰点在业务层生成，Engine不生成随机数；读书回执和考试快照负责保存实际骰点。
- `readBook` 的 `settlementTurnNumber` 是本次行动完成后的累计回合编号，用于写入 `BookProgress.lastReadTurnNumber`。
- `readBook`、`practiceWriting`、`rest` 和 `applyDriver` 只返回结算结果，不保存实体。
- `applyDriver` 接收 `BigDecimal` 驱动量，由引擎统一取整并限制最终状态范围。Resolver 不应直接生成 After 状态。
- 返回结果中的增减量均以限制范围后的实际变化为准。

## 三、`TurnEngine`

源码：[TurnEngine.java](../../src/main/java/mvp/engine/TurnEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `startLife()` | 创建六岁开局时的日历与流程状态 | 无 | `TurnState` |
| `advance(TurnState current, boolean endTurn)` | 根据行动是否结束回合推进月内回合、月份、年份和年龄，并识别考试节点 | `current`：结算前时间；`endTurn`：行动是否消耗回合 | `TurnResult` |
| `completeExam(TurnState current, String examType)` | 完成考试流程；阶段考试回到求学，县试结束本局 | 当前时间状态和考试类型编码 | 更新后的 `TurnState` |
| `examTypeAtAge(int age)` | 查询指定周岁对应的刚性考试 | `age`：周岁 | 考试编码；没有考试时为 `null` |
| `jiajingYear(int currentYear)` | 把公元年份转换成嘉靖年序 | `currentYear`：公元年份 | 嘉靖年序整数 |

`advance` 是唯一推进普通时间的方法。`endTurn=false` 时返回原 `TurnState`，不会递增任何时间字段；考试结算本身不应再次调用它。

## 四、`ExamEngine`

源码：[ExamEngine.java](../../src/main/java/mvp/engine/ExamEngine.java)

### 公开方法

| 方法 | 作用 | 参数 | 返回值 |
|---|---|---|---|
| `prepare(CharacterState character, ScholarState scholar, BigDecimal knowledgeTotal, ExamWeights weights)` | 汇总知识、能力和身体状态，建立考试数值快照 | 人物、书生能力、全部学识及题目权重 | `ExamPreparation` |
| `knowledgeScore(BigDecimal knowledgeTotal)` | 把全部学识换算为考试知识分 | 不封顶的总学识 | `0`～`100` 的知识值 |
| `luckOffset(int diceRoll)` | 用立方曲线计算普通骰点修正 | 1～100骰点 | 整数修正，准备考试时保存 |
| `baseAbilityScore(CharacterState character, ScholarState scholar, int knowledgeScore, ExamWeights weights)` | 按题目权重计算基础能力分 | 人物、书生能力、知识值和权重 | `0`～`100` 的整数分 |
| `stateOffset(CharacterState character)` | 根据健康、疲劳和体能计算临场偏移 | 考试开始时人物快照 | `-8`～`4` 的整数偏移 |
| `thoughtLevel(int score)` | 把可发挥分映射为思维泡泡层级 | 通常传入基础能力分与临场偏移之和 | `ThoughtLevel` |
| `settleAuto(int baseAbilityScore, int stateOffset, int diceRoll, int luckOffset, int passThreshold)` | 结算系统代行路径 | 已保存的基础分、身体偏移、骰点、骰点修正和通过线 | `ExamResult` |
| `settlePlayer(int baseAbilityScore, int stateOffset, BigDecimal contentModifier, int diceRoll, int luckOffset, int passThreshold)` | 玩家作答的引擎入口，HTTP链路尚未接入 | 已保存快照、Resolver内容修正及通过线 | `ExamResult` |

`settlePlayer` 会把 `contentModifier` 四舍五入并限制在 `-25`～`25`。两个结算方法都先使用已保存的骰点修正，再应用1/100极端结果；以 Java 计算结果为最终事实，模型生成内容不得反向修改成绩或通过状态。

### 考试数据结构

`ExamWeights`

| 字段组 | 类型 | 来源 |
|---|---|---|
| `characterZhili`、`characterDaode`、`characterZhengzhi`、`characterJiaoji`、`characterTineng` | `BigDecimal` | `exam.json.generalAbilityWeight` |
| `abilityShizi`、`abilityJingyi`、`abilityWenzhang`、`abilityCelun`、`abilityWenxue` | `BigDecimal` | `exam.json.careerAbilityWeight` |
| `knowledge` | `BigDecimal` | `exam.json.knowledgeWeight` |

| 类型 | 字段及含义 |
|---|---|
| `ExamPreparation` | `knowledgeScore`：知识值；`baseAbilityScore`：基础能力分；`stateOffset`：临场偏移；`thoughtLevel`：思维层级 |
| `ExamResult` | `finalScore`：最终整数分；`effectiveContentModifier`：实际采用的内容修正；`passed`：是否通过；`status`：`COMPLETED_PASS` 或 `COMPLETED_FAIL` |

`ThoughtLevel` 的枚举值为 `DIFFICULT`、`BASIC`、`ORGANIZED`、`CONFIDENT`。

## 五、AI 配置与模型调用

### `GameClient.chat`

源码：[GameClient.java](../../src/main/java/mvp/ai/GameClient.java)

```java
<T> T chat(String promptCode, String userText, Class<T> type, Object... tools)
```

| 参数 | 含义 |
|---|---|
| `promptCode` | `prompt.json` 中的稳定提示词编码 |
| `userText` | 本次调用的动态输入和游戏上下文 |
| `type` | Spring AI 将响应映射到的结构化结果类型 |
| `tools` | 本次模型调用可使用的工具；不需要时可省略 |

`GameClient` 创建时通过 `ClasspathJsonLoader` 加载 `prompt/prompt.json` 并建立不可修改的编码索引。调用时由它组合对应的系统提示词与 `userText`，返回模型响应反序列化后的 `T`；编码不存在时抛出 `IllegalArgumentException`。调用失败或返回空值时抛出HTTP 502，提示检查网络或模型账户余额。重试配置关闭；该类不负责事务、存档写入或规则结算。当前获取行为通过结构化意图交由Service执行，并未将数据库方法直接暴露为 `tools`。

### `ClasspathJsonLoader.load`

源码：[ClasspathJsonLoader.java](../../src/main/java/mvp/ai/ClasspathJsonLoader.java)

```java
<T> T load(String resourcePath, Class<T> type)
```

`resourcePath` 是相对于 classpath 根目录的路径，`type` 是目标 Java 类型。该方法使用 Hutool 读取 UTF-8 文本并反序列化；读取或转换失败时包装为 `IllegalStateException`。

## 六、自由行动 LangGraph

源码：[FreeActionWorkflow.java](../../src/main/java/mvp/ai/FreeActionWorkflow.java)、[FreeActionResolver.java](../../src/main/java/mvp/ai/FreeActionResolver.java)、[FreeActionState.java](../../src/main/java/mvp/ai/FreeActionState.java)

### `FreeActionWorkflow.execute`

```java
FreeActionResult execute(FreeActionCommand command)
```

`command` 包含 `playerText`、`sceneCode`、`contextSummary`、`character` 和 `scholar`。方法执行固定的两节点图，并返回 `settlement`、`eventSummary`、`lifeMilestone` 和 `acquisitions`：

```text
START → resolve_action → settle_driver → END
```

- `resolve_action` 调用 `FreeActionResolver.resolve`，把模型给出的 `FreeActionResolution` 写入图状态。
- `settle_driver` 只把其中的 `DriverPatch` 交给 `CharacterEngine.applyDriver`，由 Java 产生最终 `DriverResult`。

`FreeActionState` 是节点间的单次调用状态，不是数据库实体。状态中的 `character`、`scholar`、`resolution` 和 `settlement` 可序列化，以适配 LangGraph4j 的默认状态复制机制。

### `FreeActionResolver.resolve`

```java
FreeActionResolution resolve(
    String playerText,
    String sceneCode,
    String contextSummary,
    CharacterState character,
    ScholarState scholar
)
```

该方法读取 `PROMPT_FREE_ACTION`，把玩家原文、场景、补充上下文及行动前数值组装成 `Prompt`，再通过 `GameClient` 得到结构化结果。`FreeActionResolution` 包含 `driverPatch`、`eventSummary`、`lifeMilestone` 和 `acquisitions`；它不包含最终 After 状态。

当前图不访问数据库、不推进时间，也不生成记忆。当前由 `GameSaveService` 准备快照，模型完成后核对状态并持久化。图状态中的获取意图同样需要可序列化，图内不直接扣款或发货。

### `FreeActionResolver.resolveDialogue(String context)`

接收人物、场景、对方、本场历史、当轮原文及 `manualEnd`，返回 `DialogueResolution(reply, endDialogue, driverPatch, acquisitions)`。普通轮只回应并给出本轮获取意图，整场结束轮才给出完整属性驱动量。该方法由对话Service直接调用，当前没有另搭对话LangGraph；避免把只有一次模型调用的流程再拆成图。

`AcquisitionIntent(supplierNpcCode, equipmentCode, quantity)` 不包含价格、余额、最终持有数量或阅读进度，真实执行由 `EquipmentRecordService` 完成。

## 七、存档与行动编排

接口：[GameSaveService.java](../../src/main/java/mvp/service/GameSaveService.java)；实现：[GameSaveServiceImpl.java](../../src/main/java/mvp/service/impl/GameSaveServiceImpl.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `listBirthRegions()` | 查询出生页允许选择的惠州县级地区 | `List<Region>` |
| `startLife(StartLifeCommand command)` | 角色名、出生地；建立六岁玩家、固定NPC、领域与家庭，只补定义不发书 | `StartLifeResult` |
| `listSaves()` | 按创建时间倒序读取存档列表 | `List<SaveSummary>` |
| `loadDetail(String saveId)` | 只读玩家完整状态 | `SaveDetail` |
| `listBooks(String saveId)` | 只读玩家书目、进度与不可读原因 | `List<LibraryBook>` |
| `prepareContent(String saveId)` | 为已升级旧存档补齐缺失NPC和定义，不发物品 | 无 |
| `executeFixedAction(String saveId, FixedActionCommand command)` | 玩家固定行动入口 | `JSONObject`，结构为ActionResult |
| `executeCharacterAction(String saveId, String actorId, FixedActionCommand command)` | 任一人物执行固定行动；actorId为空时使用玩家 | 同上 |
| `completeAutoExam(String saveId, String examId)` | 玩家系统代行 | `ExamResult` |
| `completeCharacterExam(String saveId, String actorId, String examId)` | 指定人物系统代行；考试必须属于该人物 | `ExamResult` |
| `prepareAction(String saveId, String actorId, String sceneCode)` | 读取模型调用前事实，要求求学且未重病 | `ActionContext` |
| `executeFreeAction(String saveId, String actorId, FreeActionCommand command)` | 重传先查回执，再运行LangGraph并事务结算 | `JSONObject` |
| `settleAiAction(ActionContext before, String requestId, Object payload, DriverResult settlement, List<AcquisitionIntent> acquisitions, boolean endTurn, String summary, boolean milestone)` | 核对快照，执行交易、应用属性、推进时间和记录结果；普通对话的settlement为空 | `JSONObject` |

`ActionContext` 包含 saveId、actorId、turnNumber、sceneCode、character、scholar、contextSummary。模型调用不持有数据库事务；回写前重新锁定存档，核对回合、人物和书生能力。获取造成钱包变化后重新读取人物，避免随后属性保存覆盖扣款。

### 请求与返回结构

| 类型 | 字段与含义 |
|---|---|
| `StartLifeCommand` | characterName、birthRegionId |
| `FixedActionCommand` | requestId、actionCode、sceneCode、bookCode、expectedTurnNumber |
| `FreeActionCommand` | requestId、sceneCode、text、expectedTurnNumber |
| `StartLifeResult` | save、character、familyBackground、scholarProfile，均为已持久化实体 |
| `SaveDetail` | 上述四项，加books、exams、milestones、knowledgeTotal、backpack、npcs |
| `SaveSummary` | saveId、characterName、age、currentYear、status、createdAt、officialPosition、officialRank、degree、titles |
| `ActionChanges` | progressGain、abilityGain、fatigueChange、healthChange、diceRoll；非读书的diceRoll为空 |
| `ActionResult` | detail、changes、feedback |
| `ExamResult` | detail、exam、newlySettled、feedback |

固定行动实际返回保存为JSON的ActionResult，方便网络重传直接返回原响应。AI行动结果包含 requestId、actorId、summary、trades、detail。身份字段为空时不推导虚构身份；titles初始为 []。

固定行动支持 READ_BOOK、PRACTICE_WRITING、REST。expectedTurnNumber为调用方最后读到的save.totalTurnNumber，不是结算后的回合；重病触发时一次请求可能额外推进多个强制回合，以响应中的时间为准。

## 八、书库与装备获取

接口：[BookService.java](../../src/main/java/mvp/service/BookService.java)、[EquipmentRecordService.java](../../src/main/java/mvp/service/EquipmentRecordService.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `BookService.importDefinitions()` | 按编码补充缺失装备与书籍，已有定义不覆盖 | 无 |
| `listLibrary(GameSave save, String characterId, CharacterState character, ScholarState scholar)` | 人物的书目、进度、持有数量和阅读条件 | `List<LibraryBook>` |
| `read(GameSave save, String characterId, CharacterState character, ScholarState scholar, String bookCode, long settlementTurnNumber)` | 读取前检查条件、生成骰点、调用引擎并保存进度；上层保存人物和时间 | `BookActionResult(bookName, settlement)` |
| `totalKnowledge(String characterId)` | 汇总该人物所有已读书籍的实际贡献 | `BigDecimal` |
| `EquipmentRecordService.acquire(String saveId, String actorId, AcquisitionCommand command)` | 免费或收费获取共用入口，完成扣款、入包及回执 | `JSONObject` |
| `backpack(String saveId, String actorId)` | 同种装备聚合数量，不创建记录 | `List<InventoryItem>` |

`LibraryBook` 字段：bookCode、bookName、equipmentId、currentProgress、requiredProgress、totalReadTurnNumber、completed、readable、blockedReasons、knowledgeSummary、ownedQuantity、price、supplierNpcCode、totalKnowledge、acquiredKnowledge。书目可见不等于已拥有或可阅读；知识介绍不是分档解锁结果。

`AcquisitionCommand` 字段：

| 字段 | 作用 |
|---|---|
| requestId | 同一次获取始终使用的稳定编号 |
| sceneCode | 获取发生场景 |
| supplierNpcCode | NPC供应者编码，必须实际在场 |
| equipmentCode | 装备定义编码 |
| quantity | 本次数量，1～100 |

价格和余额由服务端读取。数量可叠加，新requestId允许再次购买；免费领取也必须调用该入口。`InventoryItem` 包含equipment定义和quantity。获取结果包含equipmentRecordId、equipmentCode、equipmentName、quantity、cost、walletAfter、turnNumber。

## 九、对话与请求回执

接口：[DialogueRecordService.java](../../src/main/java/mvp/service/DialogueRecordService.java)、[EventRecordService.java](../../src/main/java/mvp/service/EventRecordService.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `start(String saveId, String actorId, StartDialogueCommand command)` | 创建整场对话；command为requestId、counterpartId、sceneCode | 对话JSON，初始version=0 |
| `respond(String saveId, String dialogueId, DialogueCommand command)` | 发言或结束；command为requestId、text、expectedVersion、endDialogue | dialogue、reply、applied |
| `loadDialogue(String saveId, String dialogueId)` | 读取历史和当前版本 | `DialogueRecord` |
| `EventRecordService.replay(String saveId, String requestId, Object payload)` | 同一存档查已执行结果，并比对原始参数 | 已存JSON或null；参数不同拒绝 |
| `recordOperation(String saveId, String actorId, String requestId, Object payload, String code, long turnNumber, Object result)` | 保存非人生节点的业务回执 | 无 |

普通对话可以执行本轮获取意图，但不应用属性。手动endDialogue=true时text可为空，只总结历史，不重做旧交易；模型也可通过endDialogue结束。结束标志、属性、历史与回执一并提交，已经结束不能再产生第二次属性结算。

对话消息和自由行动的requestId最多100字符，其余普通回执入口最多120字符，建议统一使用UUID。不复用同一个编号表达不同操作；本次失败未形成回执时可沿用编号重试。系统内部给附属交易追加后缀，客户端不要自行使用这些内部编号。

模型失败返回502，状态冲突通常返回409。失败请求不自动推进回合；已有成功对话轮的交易不会因为后续结束失败而撤销。

## 十、考试与地区服务

接口：[ExamRecordService.java](../../src/main/java/mvp/service/ExamRecordService.java)、[RegionService.java](../../src/main/java/mvp/service/RegionService.java)。

| 方法 | 作用与参数 | 返回值 |
|---|---|---|
| `ExamRecordService.prepare(GameSave save, String characterId, CharacterState character, ScholarState scholar, BigDecimal knowledgeTotal)` | 节点回合完成后保存题目、通过线、B/R、总学识、骰点和骰点修正 | READY状态的ExamRecord |
| `settleAuto(GameSave save, String characterId, String examId)` | 使用已保存快照结算；相同考试不重复处理 | `AutoExamSettlement(exam, newlySettled)` |

考试结算本身不消耗普通回合，但阶段考试后可能继续尚未结束的强制休养。系统代行不调用模型；思维泡泡、玩家答案评价、AI答卷链路仍未接入。

## 十一、HTTP入口及调用顺序

| 请求 | 用途/请求体 |
|---|---|
| `GET /api/save` | 存档列表 |
| `GET /api/save/birth-regions` | 可选出生地 |
| `POST /api/save/start` | StartLifeCommand |
| `GET /api/save/{saveId}` | 玩家详情 |
| `POST /api/save/{saveId}/content` | 显式补齐旧存档内容，无请求体 |
| `GET /api/book/{saveId}` | 玩家书库 |
| `GET /api/equipment/{saveId}/{characterId}` | 任一人物背包 |
| `POST /api/equipment/{saveId}/{characterId}/acquire` | AcquisitionCommand |
| `POST /api/turn/{saveId}/action` | 玩家FixedActionCommand |
| `POST /api/turn/{saveId}/actor/{characterId}/action` | 任一人物FixedActionCommand |
| `POST /api/turn/{saveId}/actor/{characterId}/free` | FreeActionCommand |
| `POST /api/dialogue/{saveId}/actor/{actorId}/start` | StartDialogueCommand |
| `POST /api/dialogue/{saveId}/{dialogueId}/message` | DialogueCommand |
| `GET /api/dialogue/{saveId}/{dialogueId}` | 对话历史与版本 |
| `POST /api/exam/{saveId}/{examId}/auto` | 玩家系统代行，无请求体 |
| `POST /api/exam/{saveId}/actor/{characterId}/{examId}/auto` | 指定人物系统代行 |

典型调用：查询出生地 → 开局并取得实际saveId/characterId → 领取教材 → 读取详情 → 提交行动 → 以响应中的最新回合继续。示例参数中的真实ID需从响应取得，不可把编码当成数据库ID。

```json
{
  "requestId": "claim-001",
  "sceneCode": "SCENE_SISHU",
  "supplierNpcCode": "NPC_XIANSHENG",
  "equipmentCode": "BOOK_SANZIJING",
  "quantity": 1
}
```

领取成功后，再提交独立的读书请求：

```json
{
  "requestId": "read-001",
  "actionCode": "READ_BOOK",
  "sceneCode": "SCENE_SISHU",
  "bookCode": "BOOK_SANZIJING",
  "expectedTurnNumber": 0
}
```

0仅适用于尚未经过回合的新存档。网络超时原样重传；新的行为使用新编号和最新回合。对话同理，每轮使用响应中的version作为下一轮expectedVersion。

## 十二、内部数值工具

`mvp.utils.Caculator` 集中提供BigDecimal构造、百分比转换、固定精度除法、HALF_UP取整和clamp。它不是HTTP或业务服务入口，新增数值关系应复用相同精度规则。

旧库先按[数据模型设计](../MVP数据模型设计.md#十新库与旧库升级)确认结构升级方式；更改schema或JSON不会自动迁移存档。
