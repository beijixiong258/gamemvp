# 后端开发

Java 17、Spring Boot、Spring AI、LangGraph4j、MyBatis-Plus、MySQL；依赖与版本以 [pom.xml](../../pom.xml) 为准。玩法数值见[规则与数值](../MVP/规则与数值.md)，本机运行见[启动与部署](启动与部署.md)。本文件维护边界、调用约定和数据关系，具体签名及字段直接查源码。

Engine 无持久状态，不查库、不调用模型、不自行掷骰，时间计算结果由 Service 保存。独立领域业务放入对应 Service，人物可同时拥有多个领域档案。MyBatis-Plus 通用方法以[官方服务接口](https://baomidou.com/guides/data-interface/)为准。

自由行动图为 `START → resolve_action → settle_driver → END`：[FreeActionWorkflow](../../src/main/java/mvp/ai/FreeActionWorkflow.java) 只解析本次输入并计算 `DriverResult`，不保存数据、推进时间或生成记忆。[FreeActionState](../../src/main/java/mvp/ai/FreeActionState.java) 及其快照、解析结果、获取意图须可序列化。对话直接调用 Resolver，不经过该图。

## HTTP 接口

以下均带 `/api` 前缀；`saveId`、`actorId`、`characterId`、`examId`、`dialogueId` 使用响应中的真实 ID，场景、NPC 和书籍使用稳定资源编码。

| 方法与路径 | 请求体／用途 |
| --- | --- |
| `GET /save` | 存档摘要，按创建时间倒序 |
| `GET /save/birth-regions` | 可选出生地区 |
| `POST /save/start` | `{characterName,birthRegionId}`，创建独立六岁存档 |
| `GET /save/{saveId}` | 完整玩家详情 |
| `POST /save/{saveId}/content` | 无请求体，补齐旧存档内容 |
| `POST /save/{saveId}/background` | 无请求体，生成或复用童年背景 |
| `GET /book/{saveId}` | 玩家书目、进度与不可读原因 |
| `POST /book/{saveId}/{bookCode}/player/question` | `{sceneCode,expectedTurnNumber}` |
| `POST /book/{saveId}/{bookCode}/player/answer` | `{questionId,text}` |
| `GET /equipment/{saveId}/{characterId}` | 人物背包，公共物品按定义汇总、动态物件按实例显示 |
| `GET /equipment/{saveId}/scene/{sceneCode}` | 当前场景有效物件 |
| `POST /equipment/{saveId}/{characterId}/acquire` | `{requestId,sceneCode,supplierNpcCode,equipmentCode,quantity}` |
| `POST /equipment/{saveId}/{characterId}/pickup` | `{requestId,itemId,sceneCode,expectedTurnNumber}`，拾取场景物件 |
| `POST /equipment/{saveId}/{characterId}/use` | 同上，每次使用一份固定用途物品 |
| `POST /turn/{saveId}/action` | `{requestId,actionCode,sceneCode,bookCode,expectedTurnNumber}`，玩家固定行动 |
| `POST /turn/{saveId}/actor/{characterId}/action` | 同上，指定人物固定行动 |
| `POST /turn/{saveId}/actor/{characterId}/free` | `{requestId,sceneCode,text,expectedTurnNumber}` |
| `POST /dialogue/{saveId}/actor/{actorId}/start` | `{requestId,counterpartId,sceneCode}` |
| `POST /dialogue/{saveId}/{dialogueId}/message` | `{requestId,text,expectedVersion,endDialogue}` |
| `GET /dialogue/{saveId}/{dialogueId}` | 历史与版本 |
| `POST /exam/{saveId}/{examId}/thought` | 无请求体，玩家应考思路 |
| `POST /exam/{saveId}/{examId}/player` | `{requestId,text}`，亲自作答 |
| `POST /exam/{saveId}/{examId}/auto` | 无请求体，玩家系统代行 |
| `POST /exam/{saveId}/actor/{characterId}/{examId}/auto` | 无请求体，指定人物系统代行 |

姓名去除首尾空白后为 2～8 个 Unicode 字符。固定行动仅支持 `READ_BOOK`、`PRACTICE_WRITING`、`REST`，非读书不需要 `bookCode`。付费物品数量为 1～100；免费教材每个人物每种限领一次，数量必须为 1。价格和供应者资格由后端决定。读书体会、玩家考试答案和自由行动正文非空且最多 8000 字符；对话正文最多 4000 字符，主动结束时 `text` 可空且不会作为新发言。

### 请求与返回

当前直接返回业务对象，不包装统一的 `code/data/message`。类型定义见上述 Service 的 record 及[前端类型](../../src/frontend/src/types/game.ts)。

| 操作 | 主要响应 |
| --- | --- |
| 开局 | `save、character、familyBackground、scholarProfile` |
| 详情 | 开局四项及 `books、exams、milestones、knowledgeTotal、backpack、npcs、sceneItems、supplies` |
| 固定行动 | `detail、changes、feedback`；changes 含进度、能力、疲劳、健康变化及骰点 |
| 体会出题／提交 | 题目含 `questionId、actorId、bookCode、bookName、sceneCode、turnNumber、currentProgress、question`；提交体会在行动响应上加 `questionId、bookCode、score、evaluation` |
| 获取 | `requestId、actorId、equipmentRecordId、equipmentCode、equipmentName、quantity、cost、walletAfter、turnNumber` |
| 拾取／使用 | `requestId、actorId、equipmentRecordId、equipmentCode、equipmentName、quantity、cost、turnNumber、summary`；拾取另含 `walletAfter`，使用另含 `remainingQuantity、fatigueChange、fatigueAfter` |
| 场景物件 | `id、itemCode、itemName、description、sceneCode、retentionLevel、expiresAtTurn、quantity` |
| 目录供应 | `SupplyOffer(equipment,sceneCode,ownedQuantity,canAcquire,blockedReasons)` |
| 自由行动／AI 结算 | `requestId、actorId、summary、trades、resolvedNpcs、sceneItems、detail` |
| 对话开始／消息 | 对话记录；消息返回 `dialogue、reply、applied` |
| 思路／考试 | 考试记录的 `aiThoughtBubble`；交卷返回 `detail、exam、newlySettled、feedback` |
| 背景 | `FamilyBackground`，正文在 `backgroundSummary` |

书目含真实数量、价格、提供者、进度、品质与不可读原因；可见不等于拥有或可读。进度达到100时 `completed=true、readable=false`，普通阅读和写体会均拒绝，不再消耗回合或结算收益。`playerReadingEnabled && readable && !completed` 才允许写体会。身份字段为空不虚构身份，称号初始 `[]`。

典型流程：查出生地 → 开局取 ID → 可选生成童年 → 讲堂领教材 → 读详情 → 提交行动 → 使用响应的新回合。下面领取和读书是两次独立请求：

```json
{"requestId":"claim-001","sceneCode":"SCENE_SISHU_JIANGTANG","supplierNpcCode":"NPC_DOUBAO","equipmentCode":"BOOK_SANZIJING","quantity":1}
```

```json
{"requestId":"read-001","actionCode":"READ_BOOK","sceneCode":"SCENE_SISHU_JIANGTANG","bookCode":"BOOK_SANZIJING","expectedTurnNumber":0}
```

示例回合 0 仅适用尚未行动的新局。`expectedTurnNumber` 使用最后读到的累计回合，重病可能令一次请求额外推进多个回合。待考时从详情选择属于玩家且 `status=READY` 的考试，思路可先获取，`player` 与 `auto` 交卷互斥；完成后按存档状态继续求学或结束。

## 事务与模型

写入先锁存档并查原请求，模型调用放在事务外，回写前重新取得锁并核对人物、领域、回合及对应题目／考试快照；业务事务使用项目现有 `TransactionTemplate` 和 `@Transactional`。[Spring 编程式事务](https://docs.spring.io/spring-framework/reference/data-access/transaction/programmatic.html)

- `requestId` 按存档唯一，相同编号和参数重放原结果，换参数返回 409。对话消息与自由行动的 requestId 最多 100 字符，其余普通结果入口最多 120，统一用 UUID；附属交易后缀由后端分配。
- 固定行动检查 `expectedTurnNumber`，对话检查 `expectedVersion`。参数拒绝、未找到、状态冲突、模型失败分别使用 400／404／409／502。重传先查结果，避免重复交易、增长或掷骰；事件响应由与 HTTP 相同的 Spring `JsonMapper` 序列化。
- 交易按数据库价格扣款、向实际供应者收款、入包并保存请求结果，同一事务完成。免费书按人物与定义检查既有取得记录；固定目录不扣供应者库存。AI 结算交易后重读人物，避免保存属性时覆盖钱包。自由行动可向当前场景的合法供应者下单；私人对话只允许当前对方的固定供应编码，不能让其他在场者代发。自由行动和对话中的交易回执另含程序确认的 `supplierId、supplierNpcCode`，实际供应者加入对应事件的参与者集合。`SupplyOffer` 只表达现行目录、资金与领取规则，不创建独立库存。
- 体会题按人物、书籍和回合缓存，`questionId` 推导体会提交的请求编号；同题同文重放，换原文、跨人物／书籍或推进回合后提交体会均拒绝。
- 考试 ID 保证只结算一次，冻结题目、B/R、通过线、学识和骰点。思路缓存，系统代行一次模型调用生成答卷与总结，玩家作答先评价再总结；全部成功才交卷。相同系统代行重传返回原考试与最新详情，`newlySettled=false`；玩家重传返回原 JSON。并发相同提交可能重复调用模型，但只保留首份结算。
- 童年用 `CHILDHOOD_BACKGROUND/{saveId}` 标记已生成，与正文原子保存；不凭正文长度判断。目标 250～500 字，拒绝空白或超过 1000 个 Unicode 字符，结果标记只存背景 ID 和完成状态，不重复存正文。
- 对话 `version` 从 0 记录成功轮数，最多五轮。普通轮可执行本轮交易、当前对方的保留决策及场景物件变化，结束轮再统一结算属性；主动结束只总结历史，忽略未发送文字，人物和物件决策为空，不重做旧交易。`reply` 为空白、获取列表含 null、第五轮未返回 `endDialogue=true` 时先拒绝本轮，既有成功轮次保留。
- AI 调用错误不自动重试。文本上限：考试思路 3000、代行答卷 8000、评价和总结各 4000；缺失或超长内容返回 502。历史已完成考试不补写或重新评价。

`GameClient.chat(promptCode,userText,type)` 使用 Spring AI 结构化输出；不存在的提示词编码抛 `IllegalArgumentException`，模型失败或空结果返回 502。不注册模型工具；获取、NPC 与场景物件意图由对应 Service 核验和执行。[实体输出说明](https://docs.spring.io/spring-ai/reference/api/chatclient.html#_returning_an_entity)

自由行动输入为 `{currentText,facts}`，facts 包含游戏日历、行动者及真实年龄、领域能力、玩家初始家庭背景、场景、书目、实际供应、场景物件和当前在场启用 NPC；家庭背景不是 NPC 的个人背景或可支配资金。人物实体是程序提供的背景资料，提示词要求私有数值不自动成为双方共同知识；记忆构建另对白名单中的参与者身份与执行事实取值。自由行动另在 facts 中加入行动者的记忆，对话在顶层加入回应者记忆，并带 `counterpart、history、currentText、manualEnd、dialogueRound、maxDialogueRounds`。事实和记忆作为 JSON 对象／数组嵌入，避免二次转义。

考试上下文包含人物及年龄、能力、已读书籍的进度和介绍；思路与评价只含冻结的题目、评分点、B/R、学识和思维档位，不透露骰点或最终成绩。结果叙事另带程序确定的 `confirmedResult`。读书体会出题还携带场景与窦苞身份。模型只给变化量、内容评价或叙事，不能自行改变事实和最终分数。

## 静态资源

文件位于 [resources](../../src/main/resources)，根对象保存同名数组，业务代码大写蛇形。定义和完整字段直接查 JSON：

| 文件 | 条目 | 维护约束 |
| --- | --- | --- |
| [action.json](../../src/main/resources/game/action.json) | 9 | 行动类型、规则、场景、提示词、反馈；`requiredParameter` 不含全部 HTTP 公共参数 |
| [equipment.json](../../src/main/resources/game/equipment.json) | 11 | 10 本书和清茶；稳定编码、品质、整数价格、供应 NPC 及固定使用效果 |
| [book.json](../../src/main/resources/game/book.json) | 10 | 一对一装备扩展；五项能力权重合计 100；进度与速度取统一常量 |
| [exam.json](../../src/main/resources/game/exam.json) | 4 | 每种恰好一道题；通用、领域、学识权重合计 1.00；年龄与 TurnEngine 一致 |
| [npc.json](../../src/main/resources/game/npc.json) | 7 | 固定姓名与身份，`defaultSceneCode` 必须包含该 NPC |
| [scene.json](../../src/main/resources/game/scene.json) | 9 | 七个业务场景及两个历史兼容场景，行动与 NPC 许可 |
| [text.json](../../src/main/resources/game/text.json) | 6 | `{{变量名}}` 模板，调用方提供全部占位值 |
| [prompt.json](../../src/main/resources/prompt/prompt.json) | 9 | 公共背景与规则、可复用规则组、各任务的角色／任务／专有规则；动态事实由调用方传入 |

装备品质由 `Equipment.Rarity` 定义 COMMON／UNCOMMON／RARE／EPIC／LEGENDARY，数据库和 JSON 仅存代码，中文及颜色由代码推导。阅读条件全部同时满足：`MIN_AGE` 比年龄，`MIN_GENERAL_ATTRIBUTE` 比人物字段，`MIN_CAREER_ABILITY` 比领域字段，`BOOK_PROGRESS` 比 target 书籍进度。`growthDomainCode` 只表示收益领域，不限制人物身份。

场景 `availableActionCode` 与行动 `availableSceneCode` 双向一致；场景中的 NPC、供应者及默认驻留位置须引用已定义编码。书籍引用装备，前置阅读引用书籍，考试场景引用场景，提示词和反馈引用各自文件。重命名代码需同步全部引用，显示名可单独改。

Vite 启动时读取场景资源，修改后重启前端；后端也独立校验。三个阶段考对应讲堂、县试对应考场，页面按考试类型选背景，待考与计分仍按类型和存档阶段。`SCENE_JIA`、`SCENE_SISHU` 保留旧请求兼容。

提示词输出分别为：童年 `backgroundSummary`；体会出题 `question`；体会评阅 `score/evaluation`；自由行动 `driverPatch/eventSummary/lifeMilestone/acquisitions/npcChanges/sceneItemChanges`；对话 `reply/endDialogue/driverPatch/acquisitions/npcChanges/sceneItemChanges`；记忆 `summary/level/kind/retentionTurns/reason/reinforcedMemoryIds`；考试思路 `thought`；考试评价 `contentModifier/evaluation`；考试答卷 `answerText/summary`（亲自作答时 answerText 为空）。获取意图仅含供应者、装备代码及数量，不含价格或最终状态，历史 `executedTrades` 不再次下单。

`NpcIntent` 包含 `characterId/name/age/description/personality/level/retentionTurns/reason/participated`；既有身份只引用观察快照中的 ID，新身份每次最多 2 个，总意图最多 4 个。仅真实参与才允许更新保留策略和进入事件参与者集合，固定 NPC 权限不由意图改变。 私人对话的 `npcChanges` 只允许当前 `counterpart.id`，创建第三人或引用其他人物均返回 502；新人物通过自由行动产生。

`SceneItemChange` 包含 `itemId/itemName/description/retentionLevel/retentionTurns`，每次最多 8 条，其中新建最多 2 个。它只描述场景物件及保留策略，不包含价格、装备定义、所有者、额外数量或数值效果。主流程先完成本次时间与重病结算，再用观察回合验证旧对象、用实际结算回合计算新期限；因此本次强制推进不截短刚确认的身份和物件期限。

公共背景为明代中后期（嘉靖至万历年间）的穿越模拟人生类游戏，具体地区由本局事实提供。`gameBackground` 和 `commonRules` 全部复用，`ruleGroups` 保存体会、行动事实、属性变化、交易、记忆和考试知识规则，各任务用 `ruleRefs` 按需引用，只保留 `role/task/rules` 中的专有内容。`GameClient` 启动时统一组装并缓存“游戏背景 → 智能体角色 → 任务 → 具体指示”，不存在的规则引用直接报错；输出结构由现有 Java record 与 Spring AI 提供，不重复维护 JSON 示例。保持已有九个 `promptCode` 稳定；调整结构化返回字段时，同步Java record、对应提示词与本文说明。

`GameClient` 在后端启动时加载提示词，修改后须重启后端，前端无需重启。新版只作用于后续实际发起的模型调用，已缓存的童年、体会题、考试思路及已保存结果不会自动重生成。

模型配置在 [application.yaml](../../src/main/resources/application.yaml)。MiMo 通过 `extra-body.thinking.type=disabled` 关闭内部深度思考；游戏展示的应考思路仍由专用提示词生成。[MiMo 说明](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)、[Spring AI extraBody](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html#_using_extra_parameters_with_openai_compatible_servers)

## 数据与记忆

正式定义以 [schema.sql](../../src/main/resources/db/schema.sql) 和[实体](../../src/main/java/mvp/entity)为准，共 13 张表。金额、属性、进度和分数为整数，学识允许小数。游戏期限使用累计回合，同回合内事件先后使用稳定序号；现实创建时间只用于存档列表。

| 表／关系 | 关键约束 |
| --- | --- |
| `region` | `parent_id` 自关联；广东1、广州2、惠州3、番禺4、南海5、顺德6、博罗7、海丰8；出生查询取惠州直属启用节点 |
| `game_save` | 一条共享时间线，`age` 为玩家年龄，NPC 按自己的生日年份计算 |
| `game_character` | 玩家 type=1、NPC=0；固定NPC的 `(save_id,npc_code)` 唯一；动态NPC无模板编码，保存所在场景、分级、到期和归档状态 |
| `family_background` | 每存档唯一，仅描述玩家初始家庭；交易不改家庭财富 |
| `career_profile_shusheng` | 每人物唯一；读书、练习、考试及 AI 属性结算更新活跃回合，休息不更新 |
| `equipment_definition / book_definition` | 跨存档公共目录，书籍以装备 ID 一对一扩展；按稳定编码同步资源、保留原定义 ID |
| `character_equipment` | `SCENE/OWNED/CONSUMED` 三种状态；人物和定义引用可空以支持动态场景物件，直接存档外键保证无主物件也随本局处理；已有引用保护保留 |

| `event_record` | UUID 主键，`event_sequence` 自增唯一；`(save_id,request_id)` 唯一；保存原参数、真实参与者和实际回执 |
| `dialogue_record` | 双方同属存档，保存场景、开始回合、成功轮数、结束状态、原文和已执行事实 |
| `exam_record` | `(character_id,exam_type)` 唯一，冻结题目和计分输入；学识 DECIMAL(16,4)，其余分数整数 |
| `memory_record` | 拥有者／来源事件唯一；保存关联人物和物品、场景、来源／强化序号、发生／强化回合、级别、类别、原因、期限和归档状态 |

地区和目录共享，其他业务数据归存档，人物复合外键保证同局归属。SQL 级联处理存档不操作外部记忆文件；仍被引用的地区和公共装备不能删除。考试表 `request_id` 为保留字段，玩家请求去重在 event_record；题目、思路、原文、答卷、评价总结独立保存，不重算历史快照。

NPC 的 `retention_level/expires_at_turn/current_scene_code/archived/retention_reason` 与记忆分级独立；固定人物和玩家为 L2。动态身份的 L0 期限为结算回合加 1，L1 为 3／9／18 回合，L2 无期限。新互动只延长或升级，读取不改变期限；归档保留身份，活跃对话双方受到保护。场景物件采用相同的三级期限，持有或耗尽记录固定为 L2；`SCENE`／`OWNED` 的数量大于 0，耗尽后数量为 0 并保留 `CONSUMED` 历史。

`EventRecordService.save` 在现有事务中锁存档后插入，由数据库分配事件序号并按 UUID 读回，提交后的记忆回调再次读取真实事件。原 `recordOperation` 保留仅行动者默认值，重载增加 `List<String> participantIds`，逐个确认属于同存档。已执行交易的实际供应者和 resolver 标识的真实互动者由主流程确认；仅观察到的人物不自动获得记忆。对话仍只给实际双方评估整场历史。

记忆来自已提交的 `END_DIALOGUE`、`FREE_ACTION` 和人生节点。同一自由行动形成重要节点时只评估节点，内部 `AI_ACTION` 保留重放回执但不重复生成记忆。对话手动结束的 actor 草稿被排除；自然语言、公开身份、场景物件和实际交易分别传入，不把场景中出现的东西当作已持有。

`MemoryResolver` 使用 `PROMPT_MEMORY_SUMMARY`，一次调用生成摘要和保留建议；保留 `IService`／`ServiceImpl` 结构，保存与到期逻辑归 `MemoryRecordServiceImpl`。L0 保存归档索引而不建正文，L1 到期退出召回，L2 长期保留。人生节点、关系经历、明确约定为 L2，实际交易至少为 L1。详细行为见[跨场记忆](../MVP/规则与数值.md#跨场记忆)。

正文使用 `version: 1` UTF-8 JSON，含来源序号和首次 `retentionDecision`，旧正文缺少这两个字段仍可读取。正文先原子发布，再在独立短事务保存索引、强化更早的本人记忆，并将真实关系／约定对应的动态 NPC 升为 L2；摘要补齐前已到期归档的身份可恢复原 ID 和场景，不改变 enabled，也不复活已归档的 L1 记忆。索引事务锁存档并重读当前回合，模型等待期间已经到期的 L1 不因旧回合快照被续期。索引失败重试复用首次决策，同一事件不重复续期；已有索引缺正文时只修复摘要，不重设期限。

召回优先保留与当前对象有关的关系／约定及本人长期经历，再补近期事件；每次最多 8 条、完整 JSON 最多 5000 个 Unicode 字符。返回来源序号以区分同回合先后，补齐只看严格更早事件，旧事件不会把后来记忆当成本次事实。失败不回滚游戏事件，后续每次检索最多补两条活跃缺口，单条失败冷却 60 秒；归档不重新生成，读取不续期。

约定是有来源的历史，书生线不增加数值好感、任务状态或自动履约。当前钱包、背包与考试结果始终优先，详见 [memory/README.md](../../memory/README.md)。

## 数据库维护

本机共享 `local` Compose 的 MySQL 3306 和 Redis 6379，MVP 使用 `localhost:3306/mvp`，配置入口为 [compose.yaml](../../compose.yaml)。保留已有外部数据卷，新机器按 Compose 声明准备对应卷；游戏不依赖 Redis。

首次执行 schema 创建库、13 张表和地区；装备及书籍目录在开局／补内容时同步，仅建库后目录表为空属正常。`CREATE TABLE IF NOT EXISTS` 不升级旧表。SQL 按 UTF-8 读取、连接使用 utf8mb4，DDL 会自动提交；维护前核对真实表结构和数据，不能用重建存档表代替增量升级。

进入存档先 `POST /content` 再读详情。装备和书籍按稳定编码同步当前资源，保留已有定义 ID、人物实例、阅读进度和历史结算；并发首次导入遇到相同编码时读取已存在定义后更新。固定 NPC 补缺失身份，仅把已识别的旧模板默认名更新为对应正式姓名，保留自定义姓名、钱包、能力和记忆，不自动发书，也不改历史考试。

旧装备实例增加强化回合时，先按取得回合回填再加入回合顺序约束；旧记忆来源序号按来源事件关联回填。旧版本未记录的同回合实际顺序不能还原，不用 UUID 顺序冒充真实先后。旧正文没有保留决策或事件序号时保持可读，数据库负责当前保留状态。

MySQL 的自增列不能用于 CHECK，带级联动作的外键列也不能与 CHECK 混用；因此物品状态、数量、场景和保留策略由 CHECK 约束，人物／装备引用与所有权的组合由 Service 校验，外键继续保护同存档和公共定义引用。[MySQL CHECK 约束](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)

数据库索引和 `memory/` 必须一起迁移。清理本局时只处理该存档及关联业务记录，保留地区、公共目录和共享数据卷；外部记忆文件按本机规则移入 `C:\Users\user\Desktop\智能体回收站\垃圾桶`，不永久删除。文件格式和故障恢复见[记忆目录说明](../../memory/README.md)。
