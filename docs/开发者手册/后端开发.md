# 后端开发

本文及接口表记录当前书生线实现。人物状态使用 `stamina/maxStamina` 展示体力，`characterPilao` 保留为内部持久字段，疲劳用于描述行动消耗；体能是独立的长期属性。体能变化保留当前体力的绝对点数，上限下降时截断超出部分。

已实现动态体力上限、禁止透支、每人物每游戏回合一次主要行动和手动结束回合。上限按体能 0～100 经 `k=0.10` 归一化 sigmoid 映射到 50～150，向下取整并保障端点。健康 ≥50 时学习健康系数为 1，0～50 按归一化 sigmoid 映射到 0.5～1；当前体力 ≤20 时学习效率再乘 0.80，每次实际扣除体力后仍在过劳区间则损失 1 点健康。75 以上健康的未来伤害抵抗效果未接入。完整规则见[规则与数值](../MVP/规则与数值.md#体能与体力上限)。

系统操作、以身入局是概念分类，不作为按钮名称。阅读、练习文章、休息、考试属于系统操作，按角色能力与规则执行；阅读（手动）、考试（手动）属于以身入局，由玩家亲自提供内容。阅读（手动）分为生成阅读题目、提交阅读回答。该分类与是否调用 AI 分开：考试仍调用 AI，但按两种考试统一基础成本结算，不额外收 AI 费用；人物对话和自定义行动保持各自业务名称，不据此扩展分类。

Java 17、Spring Boot、Spring AI、LangGraph4j、MyBatis-Plus、MySQL；依赖与版本以 [pom.xml](../../pom.xml) 为准。玩法数值见[规则与数值](../MVP/规则与数值.md)，本机运行见[启动与部署](启动与部署.md)。本文件维护边界、调用约定和数据关系，具体签名及字段直接查源码。

Engine 无持久状态，不查库、不调用模型、不自行掷骰，时间计算结果由 Service 保存。独立领域业务放入对应 Service，人物可同时拥有多个领域档案。MyBatis-Plus 通用方法以[官方服务接口](https://baomidou.com/guides/data-interface/)为准。

自定义行动与人物对话共用 `START → interpret → resolve → review → settle_driver → END`：[FreeActionWorkflow](../../src/main/java/mvp/ai/FreeActionWorkflow.java) 在事务外调用三个模型阶段、复验契约并预计算 `DriverResult`，不直接保存数据、推进时间或生成记忆。[ActionGuard](../../src/main/java/mvp/ai/ActionGuard.java) 负责上下文投影及来源／效果约束，[FreeActionState](../../src/main/java/mvp/ai/FreeActionState.java) 保存本次状态。对话通过 executeDialogue 进入同一张图。

## HTTP 接口

界面正式名称已统一：书籍 `/player` 路径对应阅读（手动），考试 `/player` 路径与 `EXAM_PLAYER` 对应考试（手动），考试 `/auto` 路径与 `EXAM_AUTO` 对应考试。接口路径及业务代码标识保留。

以下均带 `/api` 前缀；`saveId`、`actorId`、`characterId`、`examId`、`dialogueId` 使用响应中的真实 ID，场景、NPC 和书籍使用稳定资源编码。

| 方法与路径 | 请求体／用途 |
| --- | --- |
| `GET /save` | 存档摘要，按创建时间倒序 |
| `GET /save/birth-regions` | 可选出生地区 |
| `POST /save/start` | `{characterName,birthRegionId}`，创建独立六岁存档 |
| `GET /save/{saveId}` | 完整玩家详情 |
| `POST /save/{saveId}/content` | 无请求体，补齐旧存档内容及阅读收益差额，返回本次实际补发的 ReadingReward |
| `POST /save/{saveId}/background` | 无请求体，生成或复用童年背景 |
| `GET /book/{saveId}` | 玩家书目、进度与不可读原因 |
| `POST /book/{saveId}/{bookCode}/player/question` | `{sceneCode,expectedTurnNumber}`，生成阅读题目，属于阅读（手动） |
| `POST /book/{saveId}/{bookCode}/player/answer` | `{questionId,text}`，提交阅读回答，属于阅读（手动） |
| `GET /equipment/{saveId}/{characterId}` | 人物背包，公共物品按定义汇总、动态物件按实例显示 |
| `GET /equipment/{saveId}/scene/{sceneCode}` | 当前场景有效物件 |
| `POST /equipment/{saveId}/{characterId}/acquire` | `{requestId,sceneCode,supplierNpcCode,equipmentCode,quantity}` |
| `POST /equipment/{saveId}/{characterId}/pickup` | `{requestId,itemId,sceneCode,expectedTurnNumber}`，拾取场景物件 |
| `POST /equipment/{saveId}/{characterId}/use` | 同上，每次使用一份固定用途物品 |
| `POST /turn/{saveId}/end-turn` | `{requestId,expectedTurnNumber}`，手动结束玩家游戏回合，可空过 |
| `POST /turn/{saveId}/action` | `{requestId,actionCode,sceneCode,bookCode,expectedTurnNumber}`，玩家固定行动（系统操作） |
| `POST /turn/{saveId}/actor/{characterId}/action` | 同上，指定人物固定行动（系统操作） |
| `POST /turn/{saveId}/actor/{characterId}/free` | `{requestId,sceneCode,text,expectedTurnNumber}`，自定义行动 |
| `POST /dialogue/{saveId}/actor/{actorId}/start` | `{requestId,counterpartId,sceneCode}`，开始人物对话 |
| `POST /dialogue/{saveId}/{dialogueId}/message` | `{requestId,text,expectedVersion,endDialogue}`，发送人物对话消息或主动结束本场 |
| `POST /dialogue/{saveId}/{dialogueId}/abandon` | `{requestId,expectedVersion}`，免费结束，不额外生成回复，各轮已扣体力、数值和交易保留 |
| `GET /dialogue/{saveId}/{dialogueId}` | 历史与版本 |
| `POST /exam/{saveId}/{examId}/thought` | 无请求体，玩家应考思路 |
| `POST /exam/{saveId}/{examId}/player` | `{requestId,text}`，考试（手动） |
| `POST /exam/{saveId}/{examId}/auto` | 无请求体，为玩家执行考试 |
| `POST /exam/{saveId}/actor/{characterId}/{examId}/auto` | 无请求体，为指定人物执行考试 |

姓名去除首尾空白后为 2～8 个 Unicode 字符。固定行动仅支持阅读（`READ_BOOK`）、练习文章（`PRACTICE_WRITING`）、休息（`REST`），练习文章与休息不需要 `bookCode`。付费物品数量为 1～100；免费教材每个人物每种限领一次，数量必须为 1。价格和供应者资格由后端决定。手动阅读回答、考试（手动）答卷和自定义行动正文非空且最多 8000 字符；对话正文最多 4000 字符，主动结束时 `text` 可空且不会作为新发言。

### 请求与返回

当前直接返回业务对象，不包装统一的 `code/data/message`。类型定义见上述 Service 的 record 及[前端类型](../../src/frontend/src/types/game.ts)。

| 操作 | 主要响应 |
| --- | --- |
| 开局 | `save、character、familyBackground、scholarProfile` |
| 详情 | 开局四项及 `books、exams、milestones、knowledgeTotal、backpack、npcs、sceneItems、supplies、actionRules、backgroundGenerated、activeDialogue` |
| 结束回合 | `detail、feedback`，普通情况推进一回合，重病可能继续强制休养 |
| 固定行动 | `detail、changes、feedback`；changes 含进度、能力、疲劳、健康变化、骰点及 `readingRewardGain` |
| 生成阅读题目／提交阅读回答 | 题目含 `questionId、actorId、bookCode、bookName、sceneCode、turnNumber、currentProgress、question`；提交阅读回答在行动响应上加 `questionId、bookCode、score、evaluation` |
| 获取 | `requestId、actorId、equipmentRecordId、equipmentCode、equipmentName、quantity、cost、walletAfter、turnNumber` |
| 拾取／使用 | `requestId、actorId、equipmentRecordId、equipmentCode、equipmentName、quantity、cost、turnNumber、summary`；拾取另含 `walletAfter`，使用另含 `remainingQuantity、fatigueChange、staminaAfter、maxStamina、healthChange、healthAfter` |
| 场景物件 | `id、itemCode、itemName、description、sceneCode、retentionLevel、expiresAtTurn、quantity` |
| 目录供应 | `SupplyOffer(equipment,sceneCode,ownedQuantity,canAcquire,blockedReasons)` |
| 自定义行动／AI 结算 | `requestId、actorId、summary、narrative、narrativeAuthority、trades、resolvedNpcs、sceneItems、detail` |
| 手动结束或离开对话 | `dialogue、staminaCost、feedback`，结束标志和版本更新，本次 `staminaCost=0`，本场已扣总量在 `dialogue.staminaCost`，不重复发放成长 |
| 人物对话开始／消息 | 对话记录；消息返回 `dialogue、reply、applied` |
| 思路／考试 | 考试记录的 `aiThoughtBubble`；交卷返回 `detail、exam、newlySettled、feedback` |
| 背景 | `FamilyBackground`，正文在 `backgroundSummary` |

书目含真实数量、价格、提供者、进度、品质、完整成长 `readingReward`、阅读成本 `fatigueCost` 与不可读原因；可见不等于拥有或可读。进度达到 100 时 `completed=true、readable=false`，阅读及提交回答均拒绝，不再消耗体力、额度或发放收益。`playerReadingEnabled && readable && !completed` 才允许提交回答，仍须校验本回合额度和体力。身份字段为空不虚构身份，称号初始 `[]`。

`Character` 返回派生 `stamina、maxStamina` 及可空 `majorActionTurn`。`majorActionTurn` 与 `save.totalTurnNumber` 相等即主要行动已用；`aiGrowthTurn` 仅保留旧存档字段兼容，不再记录新的领取回合或限制成长。`actionRules` 返回 `aiStaminaCost、examStaminaCost、practiceStaminaCost、restStaminaRecovery、restHealthRecovery、restHealthCap、consumableStaminaRecoveryLimit、overworkThreshold、dialogueMinStaminaCost、dialogueCharactersPerStamina`，客户端据此展示成本与禁用原因；`backgroundGenerated` 依据真实生成事件判断童年缓存。`activeDialogue` 返回当前存档未结束的完整对话或 null，包括派生 `staminaCharacters、staminaCost`，客户端据此恢复原文和已扣金额，不能依赖本地缓存判断会话是否存在。

`ReadingReward` 是十个整数的平铺对象：`characterZhili、characterDaode、characterZhengzhi、characterJiaoji、characterTineng、abilityShizi、abilityJingyi、abilityWenzhang、abilityCelun、abilityWenxue`。书目的 `readingReward` 表示全书从 0 到 100 的完整额度；行动的 `changes.readingRewardGain` 表示本次实际到账的阅读成长（非书籍学习行动为全 0），`abilityGain` 保留兼容。历史请求重放可能缺少新字段，前端按未提供处理，不猜测旧结果。

`POST /save/{saveId}/content` 直接返回本次实际补发的 `ReadingReward`，无补发时十项为 0。客户端先调用该接口，再 GET 最新详情；这次补发不放入阅读产生的游戏回合收益。GET 详情与书目仍只读，不触发补发。

典型流程：查出生地 → 开局取 ID → 可选生成童年 → 讲堂领教材 → 读详情 → 提交主要行动 → 可继续人物互动 → 手动结束回合。下面领取和阅读是两次独立请求：

```json
{"requestId":"claim-001","sceneCode":"SCENE_SISHU_JIANGTANG","supplierNpcCode":"NPC_DOUBAO","equipmentCode":"BOOK_SANZIJING","quantity":1}
```

```json
{"requestId":"read-001","actionCode":"READ_BOOK","sceneCode":"SCENE_SISHU_JIANGTANG","bookCode":"BOOK_SANZIJING","expectedTurnNumber":0}
```

示例的 `expectedTurnNumber=0` 使用最后读到的累计回合，不以已提交行动次数推算；主要行动成功后回合保持 0，额度已用，调用结束回合后才变化。重病时结束回合可能一次完成多个强制休养回合，遇考试暂停，交卷后继续剩余休养。待考时从详情选择玩家 `READY` 考试，`player` 与 `auto` 交卷互斥；完成后按存档状态继续求学或结束。

## 事务与模型

自定义行动每次成功消耗 15 点体力；对话按本场双方已保存文字每 100 字约耗 1 点、向上取整、整场最低 15 点，空对话为 0。首轮收到有效回复后至少扣 15 点，之后每轮将累计应付减去已扣部分，实时扣差额；数值、字数、扣款回执同事务提交。结束和离开免费，不核对价格或实际 token。内部模型阶段、格式修正和配套结果不另收费。阅读与考试按各自基础成本结算：两种阅读仅收书籍成本，两种交卷统一收 5 点。手动阅读出题、童年背景、考试思路及创建对话免费；缓存与已提交请求重放不重复调用或扣费。自动记忆摘要、复核与缺口补齐不额外收费。

游戏回合表示存档共享时间，`expectedTurnNumber` 校验累计回合。阅读、提交阅读回答、练习文章、休息共享 `majorActionTurn`，动作本身不推进时间；自定义行动和人物对话不占主要行动额度，也不推进时间。`expectedVersion` 校验对话版本；回复、主动结束与离开均更新版本，不表示游戏时间或实际聊天轮数。主要行动和自定义行动按当前体力与各自额度执行；`end-turn` 仍确认没有活跃对话，不要求主要行动已用，也不自然恢复体力。

写入先锁存档并查原请求，模型调用放在事务外，回写前重新取得锁并核对人物、领域、回合及对应题目／考试快照；业务事务使用项目现有 `TransactionTemplate` 和 `@Transactional`。[Spring 编程式事务](https://docs.spring.io/spring-framework/reference/data-access/transaction/programmatic.html)

- `requestId` 按存档唯一，相同编号和参数重放原结果，换参数返回 409。对话消息与自定义行动的 requestId 最多 100 字符，其余普通结果入口最多 120，统一用 UUID；附属交易后缀由后端分配。
- 固定行动与结束回合检查 `expectedTurnNumber`，对话消息与离开检查 `expectedVersion`。参数拒绝、未找到、状态冲突、模型失败分别使用 400／404／409／502。重传先查结果，避免重复交易、增长或掷骰；事件响应由与 HTTP 相同的 Spring `JsonMapper` 序列化。
- 交易按数据库价格扣款、向实际供应者收款、入包并保存请求结果，同一事务完成。免费书按人物与定义检查既有取得记录；固定目录不扣供应者库存。AI 结算交易后重读人物，避免保存属性时覆盖钱包。自定义行动可向当前场景的合法供应者下单；私人对话只允许当前对方的固定供应编码，不能让其他在场者代发。自定义行动和人物对话中的交易回执另含程序确认的 `supplierId、supplierNpcCode`，实际供应者加入对应事件的参与者集合。`SupplyOffer` 只表达现行目录、资金与领取规则，不创建独立库存。
- 手动阅读题目按人物、书籍和回合缓存，`questionId` 推导提交请求编号；同题同文重放，换原文、跨人物／书籍或跨游戏回合均拒绝。新出题须主要行动未用、体力足以支付本书成本，当次不扣体力且不占主要行动；提交只扣书籍成本并占用主要行动。
- 考试入场先补满体力，再冻结题目、B/R、通过线、学识记录和骰点。考试思路免费，两种交卷统一消耗 5 点体力，ID 保证只结算一次。考试生成答卷与总结；考试（手动）先取得整数 `answerScore` 和评价，再生成总结，全部成功才交卷。相同请求重传返回已保存结果，不重复扣费或改卷。
- 童年用 `CHILDHOOD_BACKGROUND/{saveId}` 标记已生成，与正文原子保存；不凭正文长度判断。目标 250～500 字，拒绝空白或超过 1000 个 Unicode 字符，结果标记只存背景 ID 和完成状态，不重复存正文。
- 人物对话创建记录不调用 AI、不收费；最多五轮，每轮结算数值、交易、当前对方保留决策及物件变化。NPC 消息保存 `numericChanges`、本轮双方文字的 `staminaCharacters` 及本轮实扣 `staminaCost`，无需新增数据库列；累计已扣金额由回执求和，只有带扣款字段的新消息参与本场字数计费，旧消息不追扣。发送前用已扣金额与当前余额限制 `maxReplyCharacters`，不足或为 0 时不调用 AI；提交时重新检查余额，扣后体力归零或身体不能继续交谈时直接结束。主动结束、离开、自然结束均调用同一免费收尾方法，不生成额外回复、补扣体力或重发成长；未发送草稿不进入历史。空对话不触发记忆，实际交谈结束记为 `END_DIALOGUE`。无效回复或第五轮未按约定结束时拒绝本轮，既有成功轮次保留。
- 网络调用错误不自动重试；行动与记忆的结构校验每阶段最多一次格式修正，语义拒绝不重试。文本上限：考试思路 3000、考试生成的答卷 8000、评价和总结各 4000；缺失或超长内容返回 502。历史已完成考试不补写或重新评价。

`GameClient.chat(promptCode,userText,type)` 使用 Spring AI 结构化输出；不存在的提示词编码抛 `IllegalArgumentException`，模型失败或空结果返回 502。行动和记忆使用 chatChecked 做结构校验，两种考试方式和阅读（手动）调用保持原接口。不注册模型工具；获取、NPC 与场景物件意图由对应 Service 核验和执行。[实体输出说明](https://docs.spring.io/spring-ai/reference/api/chatclient.html#_returning_an_entity)

自定义行动与人物对话共用 `FreeActionWorkflow` 的理解、解算、复核和属性预计算流程，`ActionGuard` 负责上下文投影、来源与效果校验。私人对话不把发起者的完整钱包、能力、家庭和背包交给回应者，历史交易也去掉 walletAfter 等私有字段；在场人物只传公开身份。自定义行动仅使用行动者自己的记忆，对话仅使用回应者自己的记忆。具体结构、限制和待执行样例见[智能体解算与验证](智能体解算与验证.md)。

考试基础分按当前四场配置采用智力 10% 与五项书生能力合计 90%，学识权重和其余通用属性权重均为 0；学识继续作为学习记录与叙事上下文。考试上下文包含人物、能力和已读书籍；思路与评价使用冻结题目和能力信息，不透露骰点或最终成绩。手动评价模型返回 `answerScore/evaluation`，`answerScore` 必须为 0～100 整数，程序以 60 为答卷合格基准计算最终分：其中 T 为本场及格线、B 为基础能力、R 为状态偏移、L 为原始运气修正，round 使用 HALF_UP；普通骰采用 `T + round(0.8×(answerScore−60)+0.2×(B−T)) + R + round(0.2×L)`，收束至 0～100；骰点 1／100 强制成绩 0／100 并失败／通过。程序的 `effectiveContentModifier = 最终分 − (B+R+L)` 保存到既有 `aiPlayerContentModifier`，表示相对自动基线的最终调整，并非模型给出的加减分。实际答卷分写入 `aiContent` 开头，正式结果仍用 `finalScore/passThreshold/status`。

人物对话与自定义行动不再限制每游戏回合正向成长次数，每次实际新收获均可成长。对话每轮执行 `DriverResult`，`numericChanges` 取本轮结算前后真实数字差；结束不再扣体力，也不汇总重发历史收益。驱动量证据须包含 `current`，不能单靠旧历史再次领取成长。AI 无权直接恢复或额外扣除体力，统一消耗由 Service 负责。

重病在健康归零时登记 4 回合休养并扣除固定属性；普通固定行动全部拒绝，玩家结束回合后按剩余次数强制推进，每回合恢复 20 点体力，最后一次恢复健康至 40。遇考试节点暂停，入场休整后冻结考试快照，阶段考试完成再继续剩余病休；这些推进是病休流程，不是主要行动自动结束回合。

装备品质由 `Equipment.Rarity` 定义 COMMON／UNCOMMON／RARE／EPIC／LEGENDARY，数据库和 JSON 仅存代码，中文及颜色由代码推导。阅读条件全部同时满足：`MIN_AGE` 比年龄，`MIN_GENERAL_ATTRIBUTE` 比人物字段，`MIN_CAREER_ABILITY` 比领域字段，`BOOK_PROGRESS` 比 target 书籍进度。`growthDomainCode` 只表示收益领域，不限制人物身份。

`BookServiceImpl` 启动时按稳定书籍编码读取并校验 `readingReward`；修改资源后需重启后端。完整成长与阅读门槛以当前资源中的最终整数为准，运行时不额外缩放，也不从品质、价格或旧权重推算。五项 `ability*Weight` 仅保留旧定义兼容，引擎不使用。成长按 `floor(完整额度×进度/100)` 的累计差发放，达到 100 后不再发奖励；逐书数值与当前学识公式见[规则与数值](../MVP/规则与数值.md#每本书的完整成长)。

本轮新增《蒙学字课》100 文、《乡塾作文入门》200 文、《经义辨析录》700 文、《文章章法集》2200 文、《治学通论》6000 文；既有《经世策论集》1800 文、《八股破题精义》4800 文（EPIC）、《GPT-1的权重》30000 文（LEGENDARY）。《GPT-1的权重》完整成长中的智力为 9、文章为 10，其余配置保持资源定义。目录和成长以 JSON 为唯一运行来源，不由文档生成。

休息由规则常量提供 20 点体力恢复、5 点健康恢复和 75 点休息健康上限，已有更高健康不会被降低。消耗品使用 `equipment[].restoration` 的 `staminaRecovery/healthCost`，恢复量硬限制为 0～20，健康成本限制为 0～100；清茶配置为恢复 10、健康成本 0。满体力时拒绝使用且不扣数量、健康；成功使用先恢复体力，再扣健康成本，健康最低为 0，并返回实际 `healthChange/healthAfter`。当前只配置清茶，不新增药物或收入。

场景 `availableActionCode` 与行动 `availableSceneCode` 双向一致；场景中的 NPC、供应者及默认驻留位置须引用已定义编码。书籍引用装备，前置阅读引用书籍，考试场景引用场景，提示词和反馈引用各自文件。重命名代码需同步全部引用，显示名可单独改。

Vite 启动时读取场景资源，修改后重启前端；后端也独立校验。三个阶段考对应讲堂、县试对应考场，页面按考试类型选背景，待考与计分仍按类型和存档阶段。`SCENE_JIA`、`SCENE_SISHU` 保留旧请求兼容。

提示词输出分别为：童年 `backgroundSummary`；生成阅读题目 `question`；手动阅读回答评阅 `score/evaluation`；行动理解 `statements/acquisitionRequests`；自定义行动与人物对话共用 `Resolution`（驱动量、narrative、结束／重要经历标志、交易／人物／物件意图与 evidence）；行动和记忆复核 `approved/violations/reason`；记忆 `summary/level/kind/retentionTurns/reason/reinforcedMemoryIds/evidenceIds`；考试思路 `thought`；考试评价 `answerScore/evaluation`；考试答卷 `answerText/summary`。对外对话仍返回 `reply`；自定义行动 `summary` 是程序结算回执，另有 `narrative` 描述经过。获取意图仅含供应者、装备代码及数量，不含价格或最终状态，历史交易不再次下单。

`Resolution.endDialogue` 已是布尔字段；`GameClient.chatChecked` 按该返回类型校验输出，`DialogueRecordServiceImpl` 读取为 `true` 后收尾，本轮费用已随回复结算，结束不另扣。提示词要求一个小结果达成就结束，第一轮可结束，仅缺少必要信息才追问；NPC 正文通常 30～80 字、最多 120 字并服从 `maxReplyCharacters`，对话复核理由最多 80 字。五轮为兜底上限，简洁和及时收尾由提示词约束，不新增字段、额外调用或自动语义重试。

`NpcIntent` 包含 `characterId/name/age/description/personality/level/retentionTurns/reason/participated`；既有身份只引用观察快照中的 ID，新身份每次最多 2 个，总意图最多 4 个。仅真实参与才允许更新保留策略和进入事件参与者集合，固定 NPC 权限不由意图改变。 私人对话的 `npcChanges` 只允许当前 `counterpart.id`，创建第三人或引用其他人物均返回 502；新人物通过自定义行动产生。

`SceneItemChange` 包含 `itemId/itemName/description/retentionLevel/retentionTurns/templateCode`，每次最多 8 条，其中新建最多 2 个。新增物件必须使用 ScenePropTemplate 的普通纸片、小石子、落叶或木片，名称与说明逐字匹配模板；已有物件只沿用观察到的 ID。意图不包含价格、所有者、额外数量或数值效果。AI 行动不推进时间，程序按观察到的当前回合验证旧对象并计算新期限；后续手动结束回合负责到期处理。

公共背景为明代中后期（嘉靖至万历年间）的穿越模拟人生类游戏，具体地区由本局事实提供。`gameBackground` 和 `commonRules` 全部复用，`ruleGroups` 保存阅读（手动）、行动事实、属性变化、交易、记忆和考试知识规则，各任务用 `ruleRefs` 按需引用，只保留 `role/task/rules` 中的专有内容。`GameClient` 启动时统一组装并缓存“游戏背景 → 智能体角色 → 任务 → 具体指示”，不存在的规则引用直接报错；输出结构由现有 Java record 与 Spring AI 提供，不重复维护 JSON 示例。保留已有九个 `promptCode`，新增 ACTION_INTERPRET、ACTION_REVIEW、MEMORY_REVIEW 三项对应提示词；调整结构化返回字段时，同步Java record、对应提示词与本文说明。

`GameClient` 在后端启动时加载提示词，修改后须重启后端，前端无需重启。新版只作用于后续实际发起的模型调用，已缓存的童年、手动阅读题目、考试思路及已保存结果不会自动重生成。

模型配置在 [application.yaml](../../src/main/resources/application.yaml)。MiMo 通过 `extra-body.thinking.type=disabled` 关闭内部深度思考；游戏展示的应考思路仍由专用提示词生成。[MiMo 说明](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)、[Spring AI extraBody](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html#_using_extra_parameters_with_openai_compatible_servers)

正式定义以 [schema.sql](../../src/main/resources/db/schema.sql) 和[实体](../../src/main/java/mvp/entity)为准，共 13 张表。金额、属性、进度和分数为整数，学识允许小数。游戏期限使用累计回合，同回合内事件先后使用稳定序号；现实创建时间只用于存档列表。

| 表／关系 | 关键约束 |
| --- | --- |
| `region` | `parent_id` 自关联；广东1、广州2、惠州3、番禺4、南海5、顺德6、博罗7、海丰8；出生查询取惠州直属启用节点 |

| `family_background` | 每存档唯一，仅描述玩家初始家庭；交易不改家庭财富 |
| `career_profile_shusheng` | 每人物唯一；阅读、提交阅读回答、练习文章、考试及 AI 属性结算更新活跃游戏回合，休息不更新 |
| `equipment_definition / book_definition` | 跨存档公共目录，书籍以装备 ID 一对一扩展；按稳定编码同步资源、保留原定义 ID |
| `character_equipment` | `SCENE/OWNED/CONSUMED` 三种状态；人物和定义引用可空以支持动态场景物件，直接存档外键保证无主物件也随本局处理；已有引用保护保留 |

| `event_record` | UUID 主键，`event_sequence` 自增唯一；`(save_id,request_id)` 唯一；保存原参数、真实参与者和实际回执 |

| `exam_record` | `(character_id,exam_type)` 唯一，冻结题目和计分输入；学识 DECIMAL(16,4)，其余分数整数 |

地区和目录共享，其他业务数据归存档，人物复合外键保证同局归属。SQL 级联处理存档不操作外部记忆文件；仍被引用的地区和公共装备不能删除。考试表 `request_id` 为保留字段，玩家请求去重在 event_record；题目、思路、原文、答卷、评价总结独立保存，不重算历史快照。

NPC 的 `retention_level/expires_at_turn/current_scene_code/archived/retention_reason` 与记忆分级独立；固定人物和玩家为 L2。动态身份的 L0 期限为结算回合加 1，L1 为 3／9／18 回合，L2 无期限。新互动只延长或升级，读取不改变期限；归档保留身份，活跃对话双方受到保护。场景物件采用相同的三级期限，持有或耗尽记录固定为 L2；`SCENE`／`OWNED` 的数量大于 0，耗尽后数量为 0 并保留 `CONSUMED` 历史。

`EventRecordService.save` 在现有事务中锁存档后插入，由数据库分配事件序号并按 UUID 读回，提交后的记忆回调再次读取真实事件。原 `recordOperation` 保留仅行动者默认值，重载增加 `List<String> participantIds`，逐个确认属于同存档。已执行交易的实际供应者和 resolver 标识的真实互动者由主流程确认；仅观察到的人物不自动获得记忆。对话仍只给实际双方评估整场历史。

记忆来自已提交的 `END_DIALOGUE`、`FREE_ACTION` 和人生节点。同一自定义行动形成重要节点时只评估节点，内部 `AI_ACTION` 保留重放回执但不重复生成记忆。对话手动结束的 actor 草稿被排除；自然语言、公开身份、场景物件和实际交易分别传入，不把场景中出现的东西当作已持有。

`MemoryResolver` 使用 `PROMPT_MEMORY_SUMMARY` 生成带 evidenceIds 的摘要和保留建议，再由 `PROMPT_MEMORY_REVIEW` 独立复核；保留 `IService`／`ServiceImpl` 结构，保存与到期逻辑归 `MemoryRecordServiceImpl`。L0 保存归档索引而不建正文，L1 到期退出召回，L2 长期保留。人生节点、关系经历、明确约定为 L2，实际交易至少为 L1。详细行为见[跨场记忆](../MVP/规则与数值.md#跨场记忆)。

正文使用 `version: 1` UTF-8 JSON，含来源序号和首次 `retentionDecision`，旧正文缺少这两个字段仍可读取。正文先原子发布，再在独立短事务保存索引、强化更早的本人记忆，并将真实关系／约定对应的动态 NPC 升为 L2；摘要补齐前已到期归档的身份可恢复原 ID 和场景，不改变 enabled，也不复活已归档的 L1 记忆。索引事务锁存档并重读当前回合，模型等待期间已经到期的 L1 不因旧回合快照被续期。索引失败重试复用首次决策，同一事件不重复续期；已有索引缺正文时只修复摘要，不重设期限。

召回优先保留与当前对象有关的关系／约定及本人长期经历，再补近期事件；每次最多 8 条、完整 JSON 最多 5000 个 Unicode 字符。返回来源序号以区分同回合先后，补齐只看严格更早事件，旧事件不会把后来记忆当成本次事实。失败不回滚游戏事件，后续每次检索最多补两条活跃缺口，单条失败冷却 60 秒；归档不重新生成，读取不续期。

约定是有来源的历史，书生线不增加数值好感、任务状态或自动履约。当前钱包、背包与考试结果始终优先，详见 [人物记忆](人物记忆.md)。

## 数据库维护

本机共享 `local` Compose 的 MySQL 3306 和 Redis 6379，MVP 使用 `localhost:3306/mvp`，配置入口为 [compose.yaml](../../compose.yaml)。保留已有外部数据卷，新机器按 Compose 声明准备对应卷；游戏不依赖 Redis。

首次执行 schema 创建库、13 张表和地区；装备及书籍目录在开局／补内容时同步，仅建库后目录表为空属正常。`CREATE TABLE IF NOT EXISTS` 不升级旧表。SQL 按 UTF-8 读取、连接使用 utf8mb4，DDL 会自动提交；维护前核对真实表结构和数据，不能用重建存档表代替增量升级。

进入存档先 `POST /save/{saveId}/content` 再读详情。装备和书籍按稳定编码同步当前资源，保留已有定义 ID、人物实例、阅读进度和历史结算；并发首次导入遇到相同编码时读取已存在定义后更新。固定 NPC 补缺失身份，仅把已识别的旧模板默认名更新为对应正式姓名，保留自定义姓名、钱包和记忆，不自动发书，也不改历史考试；人物能力仅增加下面核算确认的阅读差额。

### 旧阅读收益核算

补内容或人物写入在存档行锁内调用 `BookService.reconcileReadingRewards`，先取该人物按事件序号最新的核算记录。自定义行动和人物对话在短事务内完成核算再取得模型快照，模型执行不持锁；固定行动、阅读（手动）和考试沿用各自写事务。核算结果与人物、书生档案及触发操作原子保存。

`event_record` 中非人生节点的 `BOOK_REWARDS_RECONCILED` 保存逐书 `rewardBudgets`（该次配置）、`legacyRewards`（后续计算使用的已消耗额度底数）和实际补发 `grantedReward`。首次请求编号为 `SYSTEM/BOOK_REWARDS/{characterId}`，之后调参的核算编号追加上一条核算事件的 `eventSequence`。原记录保留，不覆盖历史；系统事件不生成记忆或推进时间。

最新快照与现行成长配置相同时直接返回，无需重扫历史或再次补发。配置变化时追加新核算记录；始终比较最新记录，因此从 A 调到 B 再调回 A 也不会复用旧 A 的底数。

首次核算按存档及真实行动者读取 `READ_BOOK`、`BOOK_PLAYER_ANSWER` 原回执，校验 `detail.character.id` 和请求中的稳定书籍编码。累计旧 `changes.abilityGain`；有 `readingRewardGain` 时使用完整十项。`BOOK_MASTERED` 只作节点，不再加一次收益。逐书回执数须等于 `totalReadTurnNumber`，累计 `progressGain` 须等于当前进度；缺失、负值或不一致返回 409 并回滚，不拿当前属性反推历史。

已有额度快照的调参核算，先计算每本书 `已消耗额度 = max(上一条 legacyRewards, 上一条 rewardBudgets 在当前进度的累计额度)`，再将其作为新的 `legacyRewards`。应补为 `max(0, 现行配置在当前进度的累计额度 - 已消耗额度)`，汇总后加入现值并封顶 100。此底数包含此前补发及因属性封顶而未到账的额度，所以调低额度、后续属性下降或切回旧配置都不会重新领取。旧超额保留，后续新增阅读进度先抵足这部分。

例如全书额度原为 20，进度 40 时已消耗 8；额度改为 10 后不补发，随后读到 100 只增加 2，总量为 10。额度从 10 提高到 20 时，则按现有进度补足正差额。人物已有非阅读成长、身体状态、活动回合、钱包、阅读进度和冻结考试均不覆盖。

没有 `rewardBudgets` 的旧核算记录，仅在 `legacyRewards` 为空、`grantedReward` 全为 0，且所有阅读回执均发生在该记录之后时自动恢复。此时各回执的 `detail.books[].readingReward`、最终进度和 `progressGain` 可还原每次已消耗额度，包括封顶未到账部分。已补过收益却缺逐书快照，或恢复所需回执不完整时返回 409，须先核对原始记录，不能估算。

该兼容流程复用既有事件表和进度表，无新增 DDL；并发与重试依靠存档锁和唯一请求约束。只调整阅读门槛而不改变成长额度时，不追加成长核算记录。

### 其他旧表维护

旧装备实例增加强化回合时，先按取得回合回填再加入回合顺序约束；旧记忆来源序号按来源事件关联回填。旧版本未记录的同回合实际顺序不能还原，不用 UUID 顺序冒充真实先后。旧正文没有保留决策或事件序号时保持可读，数据库负责当前保留状态。

MySQL 的自增列不能用于 CHECK，带级联动作的外键列也不能与 CHECK 混用；因此物品状态、数量、场景和保留策略由 CHECK 约束，人物／装备引用与所有权的组合由 Service 校验，外键继续保护同存档和公共定义引用。[MySQL CHECK 约束](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)

数据库索引和 `memory/` 必须一起迁移。清理本局时只处理该存档及关联业务记录，保留地区、公共目录和共享数据卷；外部记忆文件按本机规则移入 `C:\Users\user\Desktop\智能体回收站\垃圾桶`，不永久删除。文件格式和故障恢复见[人物记忆](人物记忆.md)。

行动与记忆的信任边界、回执字段、上下文裁剪及验证限制统一见[智能体解算与验证](智能体解算与验证.md)。记忆召回新增 summaryAuthority 与来自原始事件的 sourceEvidence，格式版本不变。
