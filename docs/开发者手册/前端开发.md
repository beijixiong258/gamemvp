# 豪杰成长计划plus · 前端

Vue 3 + TypeScript 网页客户端，与 Java 后端共用当前仓库。日常手动启动见[启动与部署](启动与部署.md)，页面规则见[前端页面与交互](../MVP/前端页面与交互.md)。下文源码、路由和请求说明均为**当前实现**；正式术语及规则状态统一见[术语与规则状态](../MVP/规则与数值.md#术语与规则状态)。

## 术语与实现边界

系统操作、以身入局是操作方式的概念分类，不作为按钮名称。系统操作按角色能力与规则执行，操作名保留原名；以身入局由玩家亲自提供内容，操作名加“（手动）”。两类方式不按是否调用 AI 划分：考试仍调用 AI，但按两种考试统一的基础成本结算，不另加 AI 费用。人物对话、自定义行动保留各自规范术语，不在本节强行归类。

现有业务标识保持不变，文档和交流按以下正式术语描述：

| 业务代码 | 正式术语 |
| --- | --- |
| `READ_BOOK` | 阅读，属于系统操作 |
| `READ_BOOK_PLAYER` | 阅读（手动），属于以身入局；分为生成阅读题目、提交阅读回答 |
| `PRACTICE_WRITING` | 练习文章，属于系统操作 |
| `REST` | 休息，属于系统操作 |
| `FREE_ACTION` | 自定义行动 |
| `NPC_DIALOGUE` | 人物对话 |
| `EXAM_AUTO` | 考试，属于系统操作 |
| `EXAM_PLAYER` | 考试（手动），属于以身入局 |

**界面命名：** 正式名称已统一为“阅读”“阅读（手动）”“考试”“考试（手动）”；业务代码与 API 标识保留。

**当前实现：** 阅读、提交阅读回答、练习文章和休息共用每人物每游戏回合一次主要行动额度，成功后不自动推进时间。主界面的“结束回合”调用独立接口，可以空过，不自然恢复体力；人物对话、自定义行动在主要行动后仍可进行。对话的 `version` 控制本场版本，回复、主动结束与免费离开均更新版本，不代表游戏回合。

`Character.majorActionTurn` 与 `save.totalTurnNumber` 相等时，主要行动额度已用；`aiGrowthTurn` 由后端限制人物对话和自定义行动每回合首次实际正向成长，不作为前端操作额度展示。`SaveDetail.actionRules` 集中返回 `aiStaminaCost、examStaminaCost、practiceStaminaCost、restStaminaRecovery、restHealthRecovery、restHealthCap、consumableStaminaRecoveryLimit、overworkThreshold`，前端不另维护成本常量。

`GameView` 与 `CharacterStats` 直接展示 `character.stamina / character.maxStamina`，不从 `characterPilao` 自行换算。后者保留为后端持久字段标识；`characterTineng` 是长期属性体能。行动反馈中 `fatigueChange > 0` 显示“疲劳消耗 X 点体力”，小于零显示“恢复 X 点体力”，等于零显示“体力无变化”。

**体能与体力上限：** 已实现体能 0～100 经 `k=0.10` 归一化 sigmoid 映射到 50～150 点整数上限，向下取整并保障端点；体能增长不补当前体力。前端只展示派生结果，公式统一见[体能与体力上限](../MVP/规则与数值.md#体能与体力上限)。

**体力使用边界：** 体力不足时禁用对应消耗按钮并显示所需与剩余点数；休息、查看、免费离开对话不因余额不足被封死。当前体力 ≤20 点显示过劳，效率与健康变化由后端结算。两种阅读都仅消耗 `LibraryBook.fatigueCost`，练习消耗 8 点，独立 AI 行动（自定义行动、对话回复与主动结束）消耗 15 点，两种考试交卷统一消耗 5 点；数值从详情读取。

休息每次最多恢复 20 点体力和 5 点健康，体力不超过动态上限，健康只恢复至 75 点，原本高于 75 时不降低。健康达到 50 点后学习效率不受健康惩罚，低于 50 的具体曲线由后端计算；75 以上健康用于后续伤害事件韧性的设计，本轮未实现该效果。体力恢复类消耗品每次最多恢复 20 点，清茶具体效果仍读后端物品说明。

## 场景与图片

`regionId` 是行政地区，`locationId` 是界面地点，`sceneCode` 是业务场景。县城和庭院只导航；具体房间、书铺提交行动，县试随考试流程进入，县衙未开放。

Vite 以 `src/frontend` 为工作目录，从 [src/main/resources/game/scene.json](../../src/main/resources/game/scene.json) 读取并注入 `__GAME_SCENES__`，页面据此显示行动和 NPC，不另维护业务许可表；改资源后重启 Vite，发布时前后端使用同一源码状态。服务端仍独立校验，旧场景仅保留历史兼容。

`@images` 指向唯一原图目录 [src/main/resources/images](../../src/main/resources/images)，通过静态导入取得浏览器 URL；素材清单见[图片素材](图片素材.md)。该目录不是后端默认公开静态目录，不能直接使用本机路径或假定存在 `/images` 接口。

## 路由与状态

使用 [Hash 路由](https://router.vuejs.org/guide/essentials/history-mode.html#hash-mode)，刷新不要求服务端逐路由回退：

| 路由 | 内容 |
| --- | --- |
| `/#/`、`/#/new` | 存档列表、开局 |
| `/#/save/:saveId?place=home` | 成长与地点 |
| `/#/save/:saveId/exam/:examId` | 待考与已完成试卷 |
| `/#/save/:saveId/result` | 本局结束 |

SaveShell 进入存档先 POST content 再 GET 详情，同步固定目录、补缺失人物与已识别的旧模板姓名，保留定义 ID 和存档历史，不发书或重置进度；旧阅读成长按历史回执和最新额度快照补齐正差额，返回本次实际补发的十项 ReadingReward，非零时展示到账提示。相同配置不重复核算，成长配置变化后由后端处理已领额度；历史数据不足返回 409，进入流程保持错误状态，不绕过补齐直接开放写操作。状态以服务端为准：玩家 READY 考试优先，COMPLETED 进入结果；写请求结束后重新判断，地点记录不能覆盖业务状态。考试通过与否直接读 `COMPLETED_PASS/COMPLETED_FAIL`。

浏览不耗游戏回合；重病时普通行动不可用，“结束回合，继续休养”交由后端推进剩余强制休养，遇考试暂停，阶段考试后继续。弹层支持焦点约束、Esc 与恢复焦点；收起对话不发送结束，主动结束发送空文本，未发送草稿不进入历史。草稿、地点、对话 ID、同一游戏回合的手动阅读题目和待确认请求保存在当前浏览器。

## 人物与物品面板

详情的 `npcs` 已由后端过滤到当前有效人物；固定人物按场景配置分组，动态人物使用 `currentSceneCode`，不由页面猜测名字或身份。L0／L1 的到期和活跃对话保护均由后端决定，页面刷新和查询不延长保留时间。

`sceneItems` 提供本局有效场景物件，主界面按当前 `sceneCode` 显示“身边小物”。拾取调用 `/equipment/{saveId}/{characterId}/pickup`，传原 `itemId`、场景和最后读取的游戏回合；成功后同一实例从场景进入行囊。`backpack` 中公共物品按定义汇总，动态小物保留独立 `itemId` 与说明。

`supplies` 使用 `SupplyOffer`：`equipment` 为公共定义，`sceneCode` 为交易地点，`ownedQuantity` 为真实持有数，`canAcquire` 与 `blockedReasons` 表示规则和资金限制。书铺杂物面板显示清茶，免费教材入口依据后端限领状态。前端不维护一套独立价格或库存。

书目与行囊书籍共用 `BookCard`，按稳定 `equipmentCode/bookCode` 遍历服务端完整书目，不限制书籍总数、价格或单书成长。卡片显示 `completed/readable/blockedReasons`、进度、`readingReward` 及 `fatigueCost`；已完成或条件不足时禁用阅读。阅读（手动）出题免费且不占主要行动，但须主要行动未用、体力足以支付本书阅读成本；提交时只扣书籍成本并占主要行动。缓存题目可继续查看，跨回合失效。实际成长来自 `changes.readingRewardGain`，旧回执缺字段不补造数值。

行囊按 `useEffectCode` 展示固定用途和使用按钮，`usable` 决定当前是否可用；体力充足时，清茶保留用途说明、禁用按钮并显示“此刻体力充足”，服务端也会拒绝。使用时传 `itemId`、具体场景和当前游戏回合到 `/use`，单次只消费一份，成功后重读详情。未进入具体房间或书铺时禁用使用并提示先选择地点；动态小物的叙事文字不生成数值效果按钮。

详情的 `backgroundGenerated` 区分初始家庭描述与已生成童年缓存；首次生成和复用均免费。考试入场先补满体力再冻结快照，考试思路免费，两种方式交卷统一收 `examStaminaCost`。考试（手动）以答卷为主要依据，答案按 0～100 分评价、60 分为合格基准，再按各场合格线校正；正式结果始终读取 `finalScore、passThreshold` 和状态，不在前端反推或重新判卷。实际答卷评分已由后端写入 `aiContent`，随评价正文展示；手动考试的 `aiPlayerContentModifier` 显示为“相对自动基线调整”，不冒充答卷分。对话创建与免费离开均不收费，回复和主动结束使用独立 AI 行动成本；离开不结算未提交成长且保留已完成交易。

## 请求恢复

- 业务写入前持久化完整路径、正文及生成一次的 requestId。未确认时禁止新写入，网络失败、超时、408、429 或服务错误保留原请求，重试原样发送；不自动重发全部 POST。
- 拾取、使用、目录获取、结束回合和免费离开对话复用同一业务请求恢复流程。结束回合向 `/turn/{saveId}/end-turn` 发送 `{requestId,expectedTurnNumber}`；离开对话向 `/dialogue/{saveId}/{dialogueId}/abandon` 发送 `{requestId,expectedVersion}`。生成阅读题目使用最后读取的游戏回合，提交阅读回答沿用 `questionId`，考试沿用 `examId`；签名见[后端开发](后端开发.md#http-接口)。
- POST 成功即清除待确认请求，再读最新进度，包括免费生成题目、思路及童年往事；后续 GET 失败只重读。409 重新读取存档和对话，保留草稿；明确的参数错误允许修改再提交。过期读档响应不覆盖随后选中的存档。
- 开局接口没有 requestId 去重，发送前记录结果待确认；结果不明时先核对存档列表，玩家明确核对后才允许再次开局。本地存储不可写时拒绝发起无法记录的写操作。
- GET 上限 20 秒，POST 与 Vite 转发上限 180 秒。浏览器超时不代表后端撤销；显示等待、错误及适用的原请求重试／刷新入口，弹层内也能操作。
- 读档及每次详情刷新均以服务端 `activeDialogue` 恢复活跃对话，本地 ID 仅作便捷缓存，不决定会话是否存在；换浏览器或清空缓存后仍可继续或免费离开，服务端确认无活跃对话时清除旧缓存。当前页可继续查看刚结束的交谈。手动阅读题目只恢复同一游戏回合且书籍仍满足条件的本地缓存。

前端开发／预览仅绑定回环地址，端口占用直接报错；`/api` 原样转发到 `http://127.0.0.1:8080`。[Vite proxy](https://vite.dev/config/server-options.html#server-proxy)
