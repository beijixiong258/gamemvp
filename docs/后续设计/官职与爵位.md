## 二、岗位

岗位枚举为 `OfficialPosition`，以 `OFFICIAL_` 开头，采用表内拼音或简写。六部、各寺的同类岗位共用代码，以 `organizationId` 区分机构。

`officialPositionName` 保存实际岗位名，为空时使用 `displayName`。例如副使、兵备道共用 `OFFICIAL_FUSHI`。地方岗位通过 `regionId` 关联地区树，跨省辖区另由授权确定。

### 2.6 本官、兼任与差遣

本官是政治体系中的计品依据，不是互斥的“主职业”，不影响人物同时保有其他领域成就。人物可有多条任职，同一时刻最多指定一条有效任职为本官；兼任不会自动改成本官，也不因岗位品级更高而自动提高 `baseRank`。

- 正式兼任增加一条任职及其对应权限、工资；升任本官则替换原本官，不把新旧岗位当作两份兼任。
- 差遣调整职责与授权，可以设置临时名称，不必增加固定岗位枚举。侍郎掌部事仍以侍郎为本官，`baseRank = 14`，不额外建立尚书任职；战时临设“超级总司令”同样按差遣处理。
- 差遣职权来自明确授权，不能仅按名称或官品推导。品级较低者可以主持部务，品级较高者也可以保留官职而被收回实权。差遣待遇单独记入额外收入，见下文薪酬规则。

任免须区分撤销兼任、撤销差遣、改任本官、降品、革职和留衔：撤销兼任只结束该任职及对应权限、工资；撤销差遣只结束对应授权与待遇，不自动免去本官。涉及本官时，由任免明确新本官和是否保留、调整品级，不自动挑选最高兼职顶替。

## 三、加官

加官枚举为 `HonoraryTitle`，允许并存。普通授本官按岗位本品确定品级，高层改任可明确保留或调整。

`rank = max(baseRank, 所有有效加官的 rank)`

既无本官、也未获准保留本官品级时，`baseRank = 0`；也无有效加官时，`rank = 0`。加官撤销后重算。加官不累加数值，爵位不参与官品计算。

## 四、爵位与俸禄

爵位枚举为 `NobleRank`，保存最高有效爵等及封号。封爵独立于升官，不授予行政权；世袭规则另定。

| 爵等 | 代码 |
| --- | --- |
| 无爵 | `NONE` |
| 伯 | `EARL` |
| 侯 | `MARQUIS` |
| 公 | `DUKE` |

### 4.1 收入构成

`totalsalary = 各有效岗位的 basesalary 之和 + 各有效 extrasalaryN.salary 之和`，所有金额统一为非负整数文／年。

- 每条任职记录用 `basesalary` 保存该岗位的基本工资。本官岗位按有效 `rank` 核定，本官或加官变化时相应调整；加官不再另发一份工资。
- 每份兼任按自身岗位待遇核定 `basesalary` 并累加，不把人物最高 `rank` 套用到所有兼职。兼任仍属于岗位工资，不计入额外收入。内阁等不固定品级岗位在任命时明确待遇，`defaultRank = 0` 不代表工资为零。
- 爵禄、差遣待遇和津贴等计入 `extrasalary`，按编号逐项保存，不能与岗位工资重复计入。
- 免职停发对应岗位工资，不影响其他有效兼任或额外收入。保留官品不等于继续领取已免职位的工资。
- `totalsalary` 为当前有效待遇的年额合计，不是已经发进钱包的累计金额；无有效收入时为 0。

### 4.2 差遣与其他额外收入

人物用 `extrasalary` 保存额外收入，内容为 JSON 对象，以 `extrasalary1`、`extrasalary2` 等作为明细编号。每项必须说明来源和金额，可同时保有多项。

- `extrasalary1` 固定用于当前爵禄；从未封爵时可以没有该项，金额按 0 计。
- `extrasalary2` 起用于差遣、津贴及其他明确核定的额外收入。一项来源对应一个编号，不限制为固定几项，也不为每项新增数据库列。
- 编号用于定位收入，不代表品级或金额高低。同一项待遇调整金额时沿用编号，变更历史记入事件；新增其他来源使用新编号，已有编号不因排序或其他项目结束而改变。

| 明细字段 | 类型 | 含义 |
| --- | --- | --- |
| `description` | `String` | 差遣或收入描述，说明为什么领取这笔钱 |
| `salary` | `int` | 本项核定的非负整数金额，单位为文／年 |
| `startTurnNumber` | `Long` | 生效回合 |
| `endTurnNumber` | `Long` | 停止计薪的回合，可空；到达该回合后不再计入有效收入 |

例如人物已有爵禄，又在战时获任“超级总司令”，其 `extrasalary` 可记录如下；金额和回合仅作格式示例：

```json
{
  "extrasalary1": {
    "description": "伯爵爵禄",
    "salary": 6000,
    "startTurnNumber": 480,
    "endTurnNumber": null
  },
  "extrasalary2": {
    "description": "战时差遣：超级总司令，统筹本次战事",
    "salary": 12000,
    "startTurnNumber": 600,
    "endTurnNumber": null
  }
}
```

授予差遣时明确待遇及对应收入编号；战事结束或差遣撤销时，按该编号填写结束回合，保留原编号。只有已生效且未结束的项目计入合计，未生效或已结束的项目按 0 计。收入明细只记录待遇，不授予职位、官品或权限；实际授权仍由任命及授权系统处理。“掌部事”也按差遣记录其额外待遇，不伪造尚书兼任工资。

该字段记录核定待遇，不作为普通交易流水；一次性赏赐不反复计入年额。具体发薪周期、临时任职不足一年的折算及一次性赏赐记录方式留待薪酬结算机制确定。

### 4.3 爵禄

- AI 按爵等及授予情境填写非负整数年爵禄，授爵／改禄时更新 `extrasalary1` 的描述、金额及生效信息，并保存变更事件；计算当前收入不反查历史事件。
- 升爵以新核定额替换该项旧额，不另加一份爵禄；削爵时结束该项，计入合计的爵禄归零。以后重新封爵仍使用 `extrasalary1`，不影响其他编号的收入。

## 五、字段与存储

官品存 INT；岗位、加官、爵等存 VARCHAR 代码，以 `@EnumValue` 标记枚举的 `code`，不存枚举序号。[枚举映射说明](https://baomidou.com/guides/auto-convert-enum/)

### 5.1 岗位枚举属性

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `code` | `String` | 稳定入库代码，与常量名一致 |
| `displayName` | `String` | 默认中文名称 |
| `defaultRank` | `int` | 岗位本品；典史 `0` 为无品，内阁 `0` 为不自动授品 |

### 5.2 任职记录（允许多条）

| 字段 | 类型 | 数据库列／含义 |
| --- | --- | --- |
| `characterId` | `String` | `character_id CHAR(32)`；人物 |
| `organizationId` | `String` | `organization_id CHAR(32)`；任职机构 |
| `regionId` | `String` | `region_id CHAR(32)`；可空，关联地区 |
| `officialPosition` | `OfficialPosition` | `official_position VARCHAR(64)`；岗位代码 |
| `officialPositionName` | `String` | `official_position_name VARCHAR(128)`；可空，实际岗位名 |
| `baseOffice` | `boolean` | `base_office TINYINT(1)`；是否为明确指定的本官任职，其他有效任职为兼任 |
| `basesalary` | `int` | `basesalary INT`；本岗位核定基本工资，按 4.1 节规则确定，单位为文／年 |

| `endTurnNumber` | `Long` | `end_turn_number BIGINT`；结束回合，空表示任职中 |

| `nobleTitleName` | `String` | `noble_title_name VARCHAR(64)`；封号，无爵为空 |
| `extrasalary` | `String` | `extrasalary JSON`；按编号保存的额外收入明细对象，初始为 `{}`，结构见 4.2 节 |

岗位工资只保存在任职记录中，爵禄只保存在 `extrasalary1` 中；人物不再重复保存这些金额或合计值。事件保存待遇变更历史，显示与结算直接读取当前任职和额外收入明细。
