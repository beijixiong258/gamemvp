# 中央会议与行政流程

> 后续政治线设计，尚未实现。MVP 仍只有六岁到十六岁县试的原有书生线。制度借用明代人物、机构及称谓，结合集体决策玩法，不声称还原明代实际制度。官品、岗位和工资字段见[官职与爵位](官职与爵位.md)，解算器现状见[智能体解算与验证](../开发者手册/智能体解算与验证.md)。

## 已确定的权责

`rank` 只决定基本工资及交互身份、对方态度；不授予行政权限，不决定选举资格或岗位的上下级。任官中的“+1／−1”按岗位层级配置，不能按十八级官品加减。

内阁固定六人：首辅／首相一人、次辅／副首相一人、其他大学士四人。六人都是大学士，权限叠加。固定六席是本作配置，不是“历史内阁始终六人”的断言。

| 岗位 | 权限与行为 |
| --- | --- |
| 所有大学士 | 提出议案，参加有表决资格的正式会议，否决部级行政议案，召集小会并选择列席人员，协调、了解进度和催办 |
| 副首相 | 继承大学士权限；可直接向中央委员会提案，包括罢免首相；常委会不通过时可支付影响力召开中央委员会 |
| 首相 | 继承大学士及相应提案、升级权限，增加常委会议长职责：安排议程、组织开会、维持程序；召开中央委员会的影响力消耗低于副首相 |
| 皇帝 | 审批常委会和中央委员会已通过的议案，正式结果只有 true／false；false 退回原会议重新讨论，不能直接改案或下令 |
| 部长 | 主持本部事务及部级会议，在既定权限和预算内执行；本部议案未通过或被否决时，可支付影响力提请常委会裁决 |

常委会首相不参加表决，次辅与四名大学士共五票，普通议案至少三票同意。首相的议长职责不能变成阻断副首相合法中央提案的权限。大学士否决部级议案的权限不能向上扩展成否决常委会或中央委员会，也不直接变更已经完成的业务事实。

“分管”仅作为人物关注领域、经验与工作习惯：影响关注哪些议题、掌握哪些材料、容易提出什么方案，不划分独占部门、不限制干预范围。没有固定分管的大学士仍拥有全部共通行为。副首相不另设一套独占部门。

皇帝通过高亲密度人物私聊表达意图，由对方自行决定是否提出、推动议案。私聊不构成正式命令，亲近关系也不替代提案、投票或审批。此前“花大量影响力直接下旨”的备选方案不采用。

地方总督、巡抚先用固定岗位权限与辖区，不逐件生成敕令解释上下级关系。以后由权限配置扩展，角色名称和 rank 均不自动创造权限。

## 会议层级

| 形式 | 参会者与表决资格 | 结果效力 |
| --- | --- | --- |
| 小会 | 大学士召集，自选相关人物列席；没有正式集体表决权的自动授予 | 由 resolver 统一解算沟通、承诺、既有权限内的协作或待审提案 |
| 部级会议 | 本部部长及按岗位配置的成员，具体席位待定；列席者不自动投票 | 本部权限内的行政议案；大学士可以否决，部长可提请上级裁决 |
| 常委会 | 六名阁员；首相主持不投票，其余五人投票；可请相关人员说明情况 | 权限内议案通过后送皇帝审批；否决后正副首相可支付影响力升级 |
| 中央委员会／集体会 | 按具有常设上朝资格的岗位确定委员；临时列席者不因到场而变成委员 | 处理重大或升级议题；通过后送皇帝审批 |

中央委员的完整岗位名单以后确定，不固定为先前示例的十四人。参会、发言、投票、提案、主持和审批是不同权限；一人兼任多个席位不增加票数。普通会议表决者不能替换任官流程中明确规定的岗位 +1 选举人。

## 小会统一机制

“提出跨部门方案”“要求进度报告”“协调争议”“催办”共用同一个小会行为：选择议题与列席人员 → 给每位角色提供其可见信息 → 交谈 → resolver 提出结构化结果 → 程序验证权限与资源 → 提交或生成待审议案。

小会可确认谁说了什么、谁愿意配合、谁承担已有权限内的工作。涉及新增税赋、预算、任职、战争等事项时，只形成待审方案，不能把“我同意”“我回去办”当成已经生效。已有合法授权内的执行也须有明确对象与实际回执，不能仅凭会议纪要扣钱、造物或调兵。

不额外实现独立的报告、催办、跨部门协作子系统。resolver 是输出行为及驱动量的智能体；NPC 动机、立场和关系变化由角色上下文决定，不另用一套固定赞成度公式替代。

## 正式议案与任官

正式状态区分草案、已提交、会议通过、待皇帝审批、退回、已生效和执行结果。具体状态名属于后续实现建议；核心约束是表态、通过、审批、生效及执行不能混为一件事。

1. 部级会议未通过或被大学士否决，部长支付影响力后提请常委会裁决。
2. 常委会未通过，正副首相可以支付影响力召开中央委员会；首相费用较低，具体数值待定。
3. 副首相有直接向中央委员会提案的权限，不必先取得首相同意。提案权与支付成本召集临时会议分开。
4. 常委会或中央委员会通过的正式议案送皇帝审批；false 退回重议，true 才满足生效条件。不得把反复开会或调用 AI 当成自动重新收费、重新执行的理由。
5. 已生效议案仍须按实际预算、任职空缺和资源执行；过去已经花掉的费用不会因政策撤回而自动退回。

等额选举：有提名权者提出候选人，由目标岗位 +1 层级有表决权的人表决。差额选举：不经过提名，从目标岗位 −1 层级的合格人选中直接由 +1 层级投票。提名者、候选池和选举人按岗位配置；不能用 rank 计算，也不能让临时列席人员扩大任官选举人范围。候选资格、空缺、履历等条件仍需核对。

罢免首相走中央委员会，副首相可以发起。建议当事人回避、由适格人员临时主持，防止首相自行主持自己的罢免案。普通中央表决门槛、罢免首相是否采用三分之二、具体回避及临时议长人选仍属待定细则，不能把桌面推演的阈值直接写成已实现规则。

## 投票可见性：建议稿

建议政策议案完成全部投票后公开实名结果；人事议案只公开汇总票数。个别否决及其责任主体公开记录。议案发起者、主持者与玩家均不能凭身份自动获得秘密票明细；NPC 私下声称投了某票仍只是发言，可真可假。玩家按所扮演角色的知情权限获取消息，策划推演可查看全票，但不能作为玩家信息。

此可见性方案尚待最终确定；无论采用哪种方式，都不得把程序掌握的全部票明细直接塞进每位 NPC 的上下文。

## 四类议案的建议路由

下面用于检查架构，不是已实现功能；金额和军事规模的分级阈值待定。

| 场景 | 建议流程 | 必须分开的结果 |
| --- | --- | --- |
| 新增一种全国税 | 户部拟案／大学士小会协调 → 常委讨论 → 中央委员会决议 → 皇帝审批 → 税收执行 | 提出税目、批准税目与实际税款入库分开；不能批准即产生全部未来收入 |
| 任免正部级官员 | 核对岗位与资格 → 等额或差额程序，由岗位 +1 的阁员按规则表决 → 皇帝审批 → 任职回执 | 提名不授职，讨论罢免不等于职位已经空缺；首相在常委会不投票 |
| 区域性对蒙古军事行动 | 已有授权内按固定指挥权执行；新增区域方案由兵部／小会准备 → 常委会 → 皇帝 | 动员、军费、后勤与战果分别结算；突破授权或全国动员阈值转中央 |
| 对西班牙帝国宣战、远征 | 相关部门准备外交、海军、财政方案 → 中央委员会决议 → 皇帝审批 → 分期执行 | 宣战不等于立即拥有舰队、航路、粮饷或必然取胜；属于架空场景 |

## 夏言事件：史实输入与游戏分支

史实参考：《明史》记载，1547 年十二月仇鸾被逮；1548 年正月因议复河套，曾铣被逮、夏言罢职；三月曾铣被杀、夏言被逮；十月夏言被杀。罢免与刑事处置是不同阶段，不能合并为同一任免投票。[《明史》卷十八](https://zh.wikisource.org/zh-hans/明史/卷18)

夏言支持曾铣复套，皇帝态度变化与严嵩的政治行动构成冲突背景；不能编成“夏言因已经打败仗而被罢”的单一事件。军事方案、修边拨款、谗言与具体指控需要各自保留来源，不能把一方指控直接确认为犯罪。[《明史》卷一百九十六](https://zh.wikisource.org/zh-hans/明史/卷196)、[卷二百零四](https://zh.wikisource.org/zh-hans/明史/卷204)

在本作架构中可映射为：复套方案争议 → 小会核对军费和执行材料 → 常委或中央重议政策 → 副首相等有权者提出罢免首相 → 中央会议及皇帝审批 → 独立调查、审判与刑罚流程。最后的刑事结果不能由任免会议直接伪造。

1547 年 NPC 只知道当时有渠道获得的军事、财政和政治消息。1548 年的史实用于策划参考，不能提前作为 NPC 决策依据，也不锁死本存档未来。如果玩家促成可行的缩减方案、改变关键信息或联盟，人物可以改变投票；严嵩等人也可以继续按其动机反对。

桌面推演曾临时假设“可参与政治的玩家”，只用于测试后续玩法，不能把 MVP 的六岁角色改成大学士。三十名有效投票者、二十票门槛、原案 21∶9 通过罢免、干预后 19∶11 未通过，均是控制变量的示例数，不是史料、不是真实模型结果，也不构成固定 NPC 票仓。军费方案在小会得到支持时，钱包、职位和军队仍不应直接变化。

## 待定与边界

中央委员及部级会议的完整名单、中央表决门槛、回避规则、影响力费用、各类议题路由阈值和投票公开方式后续定稿。固定岗位权限表先明确可执行事项与辖区，再讨论动态扩展。政治线不随本次 resolver 改造上线；经济与刑罚另见[经济与司法](经济与司法.md)。
