# MVP 规则与数值

本文是书生线数值与保留规则的统一说明。接口与资源见[后端开发](../开发者手册/后端开发.md)，流程与范围见[玩法与范围](玩法与范围.md)。

## 一、数值约定

智力、道德、政治、交际、体能为五项通用属性；识字、经义、文章、策论、文学为五项书生能力。两组数值与健康、疲劳、阅读进度均使用 0～100 的整数。金额以整数文保存，考试分数也使用整数；总学识允许小数且不封顶。

计算中使用 `BigDecimal`，整数结果按 `HALF_UP` 四舍五入。`clamp(下限, 上限, 数值)` 表示把数值限制在指定范围。实际收益等于最终值减原值，超出上限的部分不算收益。

常量见 [GameRuleConstant.java](../../src/main/java/mvp/engine/GameRuleConstant.java)，逐书参数见 [book.json](../../src/main/resources/game/book.json)。

## 二、开局与时间

| 项目 | 初始值 |
| --- | --- |
| 出生年／开局年 | 1541／1547 |
| 开局时间 | 六岁，正月第一回合，累计回合 0 |
| 五项通用属性 | 各 20 |
| 健康／疲劳 | 75／0 |
| 识字／其余书生能力 | 5／各 0 |
| 人物钱包 | 2000 文 |
| 家庭财富 | 固定 100000 文；规则允许范围为 10000～1000000 文 |

家庭财富只表示出生背景，与钱包分别保存；交易改变钱包。玩家与 NPC 共用人物、钱包、书生档案和背包结构。开局创建固定 NPC、补齐公共教材定义，背包起初为空。

童年背景通过独立接口生成并缓存，提示词要求 250～500 字，程序拒绝空白或超过 1000 个 Unicode 字符的结果。叙事只展开六岁入学前的既定背景，不回写初始属性、财富和时间；开局接口本身不调用模型。

每月 3 回合，每年 12 个月，年龄按当前游戏年份减人物出生年份计算，跨年增加。玩家与 NPC 共用时间线，但各自使用自己的出生年。读书、练习、休息和自由行动消耗一回合；查看、进入场景、获取物品和普通对话不消耗回合。玩家浏览位置随行动传入，不单独模拟移动过程；动态 NPC 和场景物件保存各自所在场景。拾取与使用清茶也不消耗回合。

| 年龄 | 考试 | 累计回合 | 通过线 |
| --- | --- | --- | --- |
| 8 | 蒙学阶段考 | 72 | 35 |
| 12 | 经义阶段考 | 216 | 45 |
| 15 | 县试预考 | 324 | 52 |
| 16 | 县试 | 360 | 60 |

累计回合包括 NPC 行动及强制休养。上表年龄指玩家年龄；到达节点时先完成本回合，再用玩家当前属性、书生能力和学识准备考试。只有玩家考试结算能恢复求学或令存档进入 `COMPLETED`；NPC 考试结算不切换整局阶段。

## 四、阅读与学识

### 阅读条件

必须处于求学阶段，背包有书，并同时满足配置要求的年龄、通用属性、领域能力和前置书籍进度。`growthDomainCode` 只表示收益所属领域，不限制人物身份。

所有书籍统一以进度 100 为读满。同一本书按人物分别记录进度。没有阅读记录时按 0 显示，第一次读书时创建；多本副本不重复增加学识，失去书籍不清空已学进度。

### 常规计算

```text
智力系数 = 0.75 + 0.50 × 智力 / 100
身体系数 = clamp(0.55, 1.20, 0.65 + 健康×0.003 + 体能×0.002 - 疲劳×0.003)
学习量 = 13 × 智力系数 × 身体系数
普通进度增量 = min(剩余进度, max(0, round(学习量)))
综合能力 = 五项书生能力按本书百分比权重求和
递减系数 = clamp(0.20, 1, 1 - 综合能力 / 120)
学习池 = (0.50 + 0.20 × 学习量) × 递减系数
单项能力增量 = round(学习池 × 本书该项权重 / 100)
```

基础阅读速度统一为每回合 13 点，由 `GameRuleConstant.READING_PROGRESS_PER_TURN` 维护；开局属性20、健康75、疲劳0时，普通骰点下实际推进10点。同一人物状态下，各书的常规阅读速度一致。进度达到100后标记“已完成”，普通阅读与“以身入局”均停止，不再消耗回合或产生收益、疲劳。各项能力分别取整，小于 0.5 的收益会变成 0，不累计余数。

### 阅读骰点

1D100 表示产生一个 1～100 的随机整数，由业务层在有效阅读时生成，作为计算方法的参数。

| 骰点 | 结果 |
| --- | --- |
| 1 | 进度和能力收益为 0 |
| 2～99 | 按常规公式计算 |
| 100 | 直接补满进度，能力仍只按本回合正常收益计算 |

三种结果都消耗本回合，并计算书籍疲劳。实际骰点与结果一并保存，重传同一请求不会重投。首次读满保存 `BOOK_MASTERED` 人生节点。

### 以身入局读书

允许此方式的科举类书籍可先由 AI 提出一道具体的体会题，玩家输入自己的理解与理由，AI 返回0至100分及点评。初始七本教材、《经世策论集》《八股破题精义》开启“以身入局”读书，《GPT-1的权重》仅支持普通阅读；由书籍的 `playerReadingEnabled` 决定。

| 得分 | 评分对应进度 |
| --- | --- |
| 0 | 10 |
| 50 | 50 |
| 80 | 74 |
| 90 | 82 |
| 100 | 90 |

评分先限幅至0～100并四舍五入，`进度增量 = min(剩余进度, round(10 + 80 × 评分 / 100))`。评分对应10～90点，接近读满时实际可少于10；从0开始满分也只到90。人物和身体状态不再修正这部分进度。

出题评阅采用宽松标准，目标是北京市重点高中语文程度、高考约110/150分的玩家认真写体会即可满分。题面给足背景，回应核心、理解基本准确，并用自己的话给出一个合理理由或做法即可100分；不要求专业经学、独到见解、引用或长篇，白话、个别错字和无碍理解的疏漏不扣分，满分不强行挑错。按实际体会评分，不认自报学历成绩。

目标节奏是一次普通阅读约10点，再用一次满分体会完成余下90点。状态较差、普通骰点失常或评分较低时可能需要更多回合。以身入局不额外掷阅读骰子，评分奖励只增加进度，能力与疲劳仍按一次普通读书结算。

出题不耗回合，同一玩家、同一本书、同一回合复用原题。提交体会成功消耗一个正常读书回合，同一题同一原文重传返回原结果，换原文不能再次结算。出题后若先做了推进回合的行动，要重新出题；AI失败不改变进度和时间。已完成的书保留全部进度和学识，不能再次阅读或写体会。

### 学识计算

```text
p = 0：贡献0
1 ≤ p ≤ 99：贡献 = 单书满学识 × 0.6 × p / 100
p = 100：贡献 = 单书满学识
总学识 = 全部不同书籍的贡献之和
考试知识分K = clamp(0, 100, round(总学识 / 2))
```

`p` 是阅读进度。“不同书籍”按装备定义 ID 区分。学识保留小数，进入考试换算时才取整；书籍内容介绍不按阅读档位拆分。

## 五、练习、休息与健康

练习文章的原始增长为 `2.40 × 智力系数 × 身体系数 × clamp(0.25, 1, 1 - 文章/120)`，取整后加入文章能力，基础疲劳为 4。

休息恢复疲劳 `18 + round(体能×0.10)`，恢复健康 `3 + 体能/25的整数商 + (原疲劳≥70 ? 1 : 0)`，结果限制在 0～100。

### AI 带来的成长

自由行动及整场对话结束时，AI 给出变化量，再由程序限制驱动量、取整并计算实际结果：

| 项目 | 每次结算的驱动量范围 |
| --- | --- |
| 通用属性 | 每项 ±3 |
| 书生能力 | 每项 ±5 |
| 疲劳 | ±20 |
| 健康 | ±10 |

缺省值为 0，不保证每次互动都有成长。上表限制 AI 直接给出的驱动量，最终健康变化还会叠加过劳伤害及重病处理。固定读书、练习主要提升书生能力。

### 疲劳和重病

行动疲劳为 `round(基础疲劳 × (1.15 - 体能/200) × (1 + max(0,60-健康)/100))`；基础疲劳大于 0 时至少增加 1。仅当本次疲劳变化量取整后大于 0，才计算过劳伤害：行动后疲劳超过 80，每超过 10 点（向上取整）损失 1 健康。自由行动或对话结算的疲劳变化量为 0 或负数时，不追加过劳伤害；AI 直接给出的健康变化仍正常结算。

健康降到 0 且尚未重病时，通用属性各减 2，并进入 4 个休养回合。每回合推进日历、疲劳减 20，最后一回合恢复健康至 40。属性只在进入重病时扣一次。

休养遇到玩家考试先暂停，剩余回合保留。玩家在阶段考试后继续休养；NPC 则在下次收到自己的固定行动请求时继续休养，不由玩家考试代为调度。玩家县试结束后不再推进。读书、自由行动或对话结算都可能触发休养；已在重病中的固定行动请求只处理休养。首版不设死亡或后台倒计时。

## 六、考试计算

玩家节点考试开始时，用节点回合完成后的玩家数据计算基础分 `B`：通用属性、书生能力和考试知识分按题目权重相加，四舍五入后限制在 0～100；权重合计为 1.00。

身体修正 `R` 和普通运气修正 `L` 为：

```text
R = round(clamp(-8, 4,
    (健康-70)×0.06 - max(0,疲劳-20)×0.08 + (体能-50)×0.03))
x = (骰点 - 50.5) / 49.5
普通运气修正L = round(25 × x³)
```

题目、通过线、`B`、`R`、总学识、骰点及 `L` 一起保存。之后即使人物状态或参数改变，也不重算这次考试的数据。

| 骰点 | 系统代行结果 |
| --- | --- |
| 1 | 0 分，必定失败 |
| 2～99 | `clamp(0,100,B+R+L)` |
| 100 | 100 分，必定通过 |

玩家作答使用 `clamp(0,100,B+R+L+round(clamp(-10,10,M)))`；`M` 是 AI 按题目及评分点给出的答案内容加减分，最终最多加 10 分或减 10 分。程序先限幅再四舍五入，避免异常大数转为整数时溢出；骰点 1 和 100 的极端结果仍优先。内容评价不能替代角色本身的能力、身体状态和已保存骰点。

例如 `B+R+L=50`，M为+8、-6、+30时分别得58、44、60分。最终分数和通过状态由程序决定。

角色思路按 `B+R` 的 35、60、80 分界分为四档。首次请求时让 AI 依据角色水平和已读书籍生成提示，并保存至该考试；再次请求复用，不重投骰点或透露最终成绩。提示是思路，不是完整答案。

系统代行先计算最终成绩，再生成相符的完整答卷和总结。玩家作答先取得内容评价，再由程序计分，最后生成结果总结；模型不能回写分数或通过状态。生成失败时保留待考状态，不保存部分答卷或成绩；先前已成功保存的思路不受影响。

重复结算同一考试返回原成绩，不重复推进阶段；不同答案或不同作答方式不能覆盖已完成记录。考试本身不消耗回合，但考试后可能继续剩余休养回合。旧版已经完成的考试保持原结果，不重新评价或补写 AI 内容。

## 七、物品获取与对话

### 领取和购买

七本学校教材由窦苞免费提供，每个人物每种教材只能领取一次，每次数量为 1；原请求重放返回原结果，不重复发书。三本付费书和清茶由陆掌柜提供，付费单次数量为 1～100，必须满足资金限制。固定目录无限供应，不扣供应者的背包或另外维护库存。

清茶 `ITEM_QINGCHA` 每份 20 文，只在书铺购买。书目与杂物供应分别展示，`SupplyOffer` 返回实际可获取状态、已有数量及被阻止的原因。初始钱包 2000 文，三本付费书价格合计 2000 文；本线不新增收入和出售，使用清茶需要在购书预算中取舍。

价格和提供者由数据库定义决定。扣款、提供者收款、背包记录和请求结果须在同一事务内完成。每次获取分别记录，同种物品在背包中合计数量。免费获取不扣钱，普通获取不消耗回合；自由行动中附带获取时，整次行动仍消耗回合。

### 人物身份分级

固定 NPC 与玩家长期保存。动态 NPC 由 resolver 随行动提出身份与保留建议，程序确认后建立同结构的人物和书生档案；不能凭叙述冒用固定 NPC 的教学、交易或考试权限。每次最多确认 4 名人物，其中新增最多 2 名；引用旧人物必须使用观察快照中实际在场的 ID。

| 级别 | 动态人物的保留方式 |
| --- | --- |
| L0 | 缓存本次场景身份，期限为实际结算回合加 1；仅观察到而未实际交互的新人物使用此级别 |
| L1 | 跨回合保存，期限由 resolver 从 3、9、18 回合中选择，缺省为 9；从实际结算回合开始计算 |
| L2 | 在本存档中长期保存，期限为空，不自动归档 |

只有新的实际互动可以延长期限或提高级别，读取不续期，既有身份不因重复请求改名或重新生成。人物级别只升不降，新期限不缩短旧期限。到期退出日常出场，仍保留 ID、档案、物品和历史引用；活跃对话中的双方受到保护，结束后再依据当前期限处理。

`participated` 区分真实参与者与仅被看到的人物，事件只向程序确认的参与者分配记忆。有实际关系或明确约定的 L2 记忆保存成功时，同事务将其中真实参与的动态 NPC 提升为 L2；如果摘要补齐前该人物已到期归档，可以恢复原身份，保留原 ID 和场景且不改变 enabled，避免人物期限截断持续关系。记忆级别与人物级别分别保存。

### 场景物件、拾取和使用

场景物件复用物品实例表，公共装备定义保持独立。每次行动最多确认 8 条物件变化，其中新物件最多 2 个；新物件数量为 1，动态名称和描述分别不超过 64、600 个 Unicode 字符。旧物件必须在观察时确实存在于当前场景。resolver 只能决定叙事说明和保留策略，不指定可出售价格、通用装备定义、人物数值效果或额外数量。

L0 物件保留至实际结算回合加 1；L1 使用 3／9／18 回合，无效期限回落为 9；L2 不到期。真实交互可以续期或升级，查看和请求重放不续期。归档只退出场景列表，保留实例记录。

物件在场景中使用 `SCENE` 状态。拾取在同一事务中检查存档、场景、回合、有效期及所有权，随后将原实例改为 `OWNED`、绑定人物、清空场景和期限、提升为 L2，原 ID 与描述保留。动态物件不自动成为公共目录的一部分，不能通过一段叙述变成昂贵教材。已持有物品不会因为记忆或身份期限消失。

公共物品按定义汇总背包数量，动态小物按实例显示。使用接口每次只消费一份有固定用途的物品：清茶疲劳减少 `min(10, 当前疲劳)`，不消耗回合；疲劳为 0 时拒绝使用，不扣数量。数量减到 0 后实例状态为 `CONSUMED`，保留历史，背包不再显示。动态小物与书籍没有清茶的使用效果。

### 自由行动与人物对话

模型在事务外处理事实快照，结算前核对人物和回合；过期结果不覆盖新状态。观察回合用于验证当时看到的人物和物件，实际结算回合包含本次行动及重病强制推进；新增或延长的保留期限从全部实际推进后的回合计算，避免本次行动发现的对象立即过期。

自由行动与对话使用游戏日期、行动者真实年龄和能力、玩家家庭、场景、书目及在场 NPC。家庭背景不代表 NPC 家庭或人物钱包；上下文见[后端开发](../开发者手册/后端开发.md#事务与模型)。

普通对话只能向当前交谈的供应者获取其目录内物品；与同窗或管书人交谈不能代向塾师领书，和父母交谈也不能代向书商购买。自由行动可向当前场景中的合法供应者下单。

普通对话往返可以完成本轮交易、当前对方的保留决策和场景小物变化，不结算属性。私人对话只更新当前对方，不创建第三人或把旁人加入谈话；新人物相遇通过自由行动进行。玩家手动结束或 AI 决定结束时，整场只结算一次属性。手动结束只总结已有历史，不执行当前未发送的文字，不新增人物或物件、不重做旧交易，也不会把草稿写进真实发言记忆；结束失败不撤销此前已成功的交易。

一次行动者输入与对方回应算一轮，`version` 记录已完成轮数。每场最多 5 轮，模型接收 `dialogueRound` 和 `maxDialogueRounds=5`，通过 `endDialogue=true` 表示结束；语义完整时可以提前结束，第 5 轮必须结束。若模型第 5 轮仍返回 `false`，程序拒绝本轮结果并返回 502，可原样重试，不替模型强行结算。

AI 说“送了书”不等于已入包，必须以程序实际执行的交易为准。行动或对话调用失败时返回错误，提示检查网络或模型账户余额，不自动重试。

### 跨场记忆

记忆来自已提交的整场结束对话、普通自由行动及人生节点。结束对话依据完整回执，为实际双方分别评估；自由行动和人生节点只为事件明确记录的参与者评估。普通自由行动保存为 `FREE_ACTION`；已经形成重要节点的同次行动只使用节点，内部 `AI_ACTION` 不重复生成记忆。常规固定行动和独立物品获取的普通回执不单独生成记忆。

`MemoryResolver` 在现有摘要调用中同时建议级别、类别、期限、原因和需要强化的旧记忆；后端确认边界后保存。期限按游戏累计回合计算，离线时间不影响记忆。

| 级别 | 保留与召回 | 到期方式 |
| --- | --- | --- |
| L0 当场 | 本场原文保留在对话／事件中；只写已处理的归档索引，不新建跨场摘要正文 | 本场结束后不进入跨场召回，也不被缺口补齐重新生成 |
| L1 近期 | 摘要与索引持久保存；resolver从3、9、18回合选择期限，未给有效期限时用9回合 | `expiresAtTurn = 发生回合 + 期限`；当前回合达到该值即退出召回，并在相关读取或生成时标记归档 |
| L2 长期 | 在本存档内持续保留，按需选入上下文 | 无自动到期；不代表每次完整读取所有历史 |

记忆类别为 `EXPERIENCE`（经历）、`RELATIONSHIP`（有依据的关系经历）、`COMMITMENT`（明确约定及履行／取消记录）。人生节点、关系经历和明确约定强制采用L2；已执行交易至少采用L1。级别缺失或无效时按L1处理，类别无效时按普通经历处理。人物身份与每段经历的记忆级别独立，固定和动态 NPC 都使用相同记忆规则。

新的实际经历可以强化当时提供给resolver的旧记忆：只允许同一存档、同一拥有者、尚未到期的L1，保留原ID。新经历为L1时，期限取原期限与“新事件发生回合＋建议期限”的较大值；为L2时，旧记忆提升为L2。读取、重放同一请求、复述旧事和单纯见面不构成强化。已归档记录不自动复活。

对话优先为与当前对象有关的关系和约定保留最多3条位置，再纳入最多2条本人长期经历、有关近事及其他近期经历，重复项只带一次。自由行动先选本人最多2条长期经历，再补近期经历。每次仍最多8条，包含标识、级别、类别及摘要的完整JSON最多5000个Unicode字符；每条摘要最多1000字符，空间不足时只缩短摘要字符串，保持JSON有效。

NPC在相关话题中延续已确认的称呼、态度和约定，不凭对话次数产生好感分数或虚构关系。约定记忆表示当时说过、答应过、完成或取消过什么；书生线不维护任务状态，不自动履约、扣款或发奖。回应应结合较新的确认结果，不把旧约定一概当成仍未履行。各人只能使用自己参与或知晓的记忆，当前人物、背包及结算事实优先于旧摘要。

事件 `eventSequence` 是稳定先后，同一回合内的新约定与取消也能明确排序；回合只表示游戏时间。记忆带有 `sourceEventSequence`，补齐旧事件只读取更早事件，不把同回合后来发生的事情当成先前经历。实际交易、人物公开身份与场景物件分别取已提交的 `executedTrades`、`resolvedNpcs`、`sceneItems`；场景物件存在不表示已经持有，未参与者的心理不作为事实。

正文保存在运行目录下的 `memory/<saveId>/<memoryId>.json`。数据库保存索引、级别、类别、期限、来源事件序号、强化回合与序号及归档状态；归档保留记录及已有正文，不删除人物、物品、事件或文件。摘要生成失败不撤销已完成的操作，后续每次最多补齐两条活跃缺口；L0和到期记忆均不会重新生成。文件格式仍沿用现有 `version: 1`，详见[记忆目录说明](../../memory/README.md)。

## 八、重复请求与随机结果

固定行动、获取、拾取、使用、自由行动和对话使用 `requestId`。同一存档、同一编号、相同参数重传时返回原结果；同一编号换参数则拒绝。新操作使用新编号。

固定行动检查 `expectedTurnNumber`，对话检查 `expectedVersion`。普通请求结果不进入人生节点列表。

计算类不访问数据库、不调用模型、不自行掷骰；相同输入和骰点得到相同结果。实际游戏的随机数在业务层生成并保存，UUID 主键不属于玩法随机。[随机种子](../后续设计/后续规划.md#随机种子)留待后续实现。
