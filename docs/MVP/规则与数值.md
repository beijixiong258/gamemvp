# MVP 规则与数值

本文是书生线公测数值与保留规则的统一说明。接口与资源见[后端开发](../开发者手册/后端开发.md)，流程与范围见[玩法与范围](玩法与范围.md)。数值已接入代码；公网部署暂缓，真实玩家通过率尚待公测。

## 术语与规则状态

系统操作直接使用玩法原名，以身入局在原名后加“（手动）”，例如阅读／阅读（手动）、考试／考试（手动）。这两类操作方式不决定是否调用 AI，也不决定是否占主要行动额度。

| 规范术语 | 含义与边界 |
| --- | --- |
| 系统操作 | 玩家选择操作，由系统按角色能力执行，不要求玩家提供被评价的正文。阅读、练习文章、休息属于系统操作；考试仍调用 AI 生成答卷与总结。 |
| 以身入局 | 玩家亲自提供参与内容，由系统评价并结算。正式按钮使用“阅读（手动）”“考试（手动）”。 |
| 书籍学习 | 阅读与阅读（手动）的统称。 |
| 阅读 | 程序按人物状态、骰点和书籍配置结算进度与成长，不调用 AI。 |
| 阅读（手动） | 先生成阅读题目，再由玩家提交回答，AI 评阅后由程序结算阅读。 |
| 生成阅读题目 | 准备操作，不发放阅读成长、不占主要行动额度。 |
| 提交阅读回答 | 提交正文并完成一次阅读结算；只写草稿不算提交。 |
| 练习文章 | 按固定公式提升文章能力，对应 `PRACTICE_WRITING`。 |
| 休息 | 主动恢复体力与健康，对应 `REST`，与重病强制休养分开。 |
| 自定义行动 | 玩家输入行动意图，由 AI 理解、解算、复核，程序验证并提交。 |
| 人物对话 | 发送发言、主动结束并结算、免费离开、收起面板是不同操作。 |
| 考试 | 系统操作，对应 `EXAM_AUTO`，AI 生成答卷，程序决定成绩。 |
| 考试（手动） | 玩家撰写答卷，AI 评价内容，程序决定成绩。 |
| 独立 AI 行动 | 自定义行动、人物对话回复及主动结束对话，每次成功业务消耗 15 点体力；内部多次模型调用不重复计费。阅读与考试按各自玩法成本结算。 |
| 游戏回合 | 游戏日历单位，每月 3 回合；文档单独说“回合”均指此项。 |
| 对话轮次 | 一次发言与一次 NPC 回复；每场最多 5 轮，不推进游戏回合。 |
| 主要行动额度 | 阅读、提交阅读回答、练习文章、休息共享每游戏回合 1 次。 |
| 阅读成长额度 | 某本书按进度发放的固定属性与能力总量，与行动次数分开。 |
| 体力 | 当前可用行动资源，显示整数“当前体力／体力上限”。 |
| 疲劳消耗 | 行动扣除体力的展示用语，不是另一项人物状态资源。 |
| 体能 | 0～100 的长期通用属性，决定体力上限，不直接作为行动余额扣除。 |
| 结束回合 | 玩家主动推进日历并刷新主要行动额度，与结束人物对话分开。 |

### 操作方式与具体玩法

| 具体玩法 | 系统操作 | 以身入局 |
| --- | --- | --- |
| 书籍学习 | 阅读 | 阅读（手动） |
| 应考 | 考试 | 考试（手动） |

### 体力显示与行动反馈

状态栏与详情统一显示当前体力及动态上限。行动反馈显示“疲劳消耗 X 点体力”“恢复 X 点体力”或“体力无变化”，按实际发生量计算。存储字段 `characterPilao` 仅保存已消耗体力；展示字段 `stamina`、`maxStamina` 由当前体能和已消耗量计算，不独立持久化。满体力不能使用仅恢复体力的清茶。

### 体能与体力上限

体能为 0～100 的整数。体力上限采用端点归一化 sigmoid，陡峭参数 `k=0.10`；中段变化快、两端慢，最终统一向下取整。

```text
x = clamp(0,100,体能)
σ(z) = 1 / (1 + exp(-z))
M(x) = 50 + 100 × [σ(0.10 × (x - 50)) - σ(-5)] / [σ(5) - σ(-5)]
体力上限 = floor(M(x))
```

`x=0、50、100` 直接返回 `50、100、150`，避免浮点尾差使精确锚点少 1。这里的 100 点是体能 50 时的上限；开局体能 20，体力为 54／54。

| 体能 | 体力上限／点 |
| --- | --- |
| 0 | 50 |
| 10 | 51 |
| 20 | 54 |
| 25 | 57 |
| 50 | 100 |
| 75 | 142 |
| 90 | 148 |
| 100 | 150 |

上限单调不减，不要求相邻体能必定增加上限。体能增长只提高上限，保持当前体力绝对点数；同次行动消耗另扣。体能下降时保持当前点数，超过新上限的部分截断。

### 体力不足与过劳

体力不足以支付完整成本时禁止执行，不可透支；0 体力仍可查看、免费离开对话、结束回合，或按额度执行休息。过劳阈值是当前体力 **≤20 点**，21 点不属于过劳，不按百分比判断。

学习效率按行动前状态计算，过劳时身体系数再乘 0.80；每次成功消费后若剩余体力 ≤20，扣 1 点健康。同一项业务只按实际的一次体力消费判定过劳伤害。没有消费的休息、清茶和结束回合不产生该伤害。

### MVP 成长与数值设计方向

正常路线主要依靠书籍与固定练习，人物对话、自定义行动提供额外收益。免费教材的后续智力门槛为《孟子》《诗经》28、《大学》31、《名家文钞》36；免费教材完整成长额度保持不变。一次重病的通用属性各减 2 后，免费教材路线仍能解锁，年龄和前置书要求保留。

本轮已增加五本覆盖 6～14 岁的付费选修书，后半程可解锁《文章章法集》《治学通论》，但是否买得起仍受钱包约束。新的活动、收入来源和后续学习生活留待设计；不增加职业、缩短 360 回合或扩展县试后玩法。

难度目标的统计口径是：**正常游玩后，通过最终县试的玩家占 75%**；不要求四场考试全部通过。前三场失败仍继续求学，县试结算后本局结束。参照策略与真实引擎模拟结果见“公测难度校准”；模拟不是实测玩家通过率。

### 行动与回合规则

| 操作 | 体力成本／恢复 | 主要行动额度 | 自动推进游戏回合 |
| --- | --- | --- | --- |
| 阅读 | 按本书配置消耗，当前 2～18 点 | 占 1 次 | 否 |
| 生成阅读题目 | 0 | 不占用 | 否 |
| 提交阅读回答 | 仅本书阅读成本，与阅读相同 | 占 1 次 | 否 |
| 练习文章 | 消耗 8 点 | 占 1 次 | 否 |
| 休息 | 恢复至多 20 体力、5 健康；健康恢复封顶 75 | 占 1 次 | 否 |
| 自定义行动、人物对话回复、主动结束对话 | 每次成功业务消耗 15 点 | 不占用 | 否 |
| 生成童年背景、生成考试思路 | 0 | 不占用 | 否 |
| 考试、考试（手动）交卷 | 每次结算基础成本 5 点 | 不占用 | 否 |
| 清茶 | 恢复至多 10 点体力，每份 20 文，健康成本 0 | 不占用 | 否 |
| 免费离开对话 | 0，不结算本场成长 | 不占用 | 否 |
| 结束回合 | 0，无自然恢复 | 刷新下一回合额度 | 是 |

主要行动共享一次额度；换书、换操作方式都不能多做一次。成功执行即占用，包括阅读骰点 1、能力已封顶或恢复被上限截断；校验失败、AI 失败与同一请求重放不重复消耗额度。读满书籍禁止继续阅读。未使用主要行动额度也可直接结束回合。

生成阅读题目需主要行动额度尚未使用，并检查当前体力足够支付本书阅读成本。出题本身免费，不预扣或锁定体力；提交时重新检查额度、体力和快照。题目同书同回合缓存，结束回合后失效。

### AI 调用与玩法成本

是否调用 AI 不决定收费；费用归属于业务操作，不能将模型调用次数叠加为多笔体力成本。

| 业务操作 | 成功时体力成本 | 说明 |
| --- | --- | --- |
| 生成童年背景 | 0 | 首次生成与读取缓存均免费 |
| 生成人物对话回复 | 15 | 一次发送计一笔，回复同时结束对话不重复收费 |
| 主动结束人物对话 | 15 | 根据已发送历史生成结束回复和结算，不发送草稿 |
| 提交自定义行动 | 15 | 内部理解、解算、复核合计一笔 |
| 生成阅读题目 | 0 | 不占主要行动额度 |
| 提交阅读回答 | 本书阅读成本 | 无额外 AI 费用 |
| 生成考试思路 | 0 | 首次生成与读取缓存均免费 |
| 提交考试或考试（手动） | 5 | 独立的考试基础成本，无额外 AI 费用 |

成本在模型完成、结果校验通过、提交事务成立时扣除。模型处理前预检，提交时锁定存档并核对人物、能力、钱包、额度与回合等状态；过期结果拒绝，失败不收取本笔成本。缓存和同请求重放不重复结算体力或成长。

打开／收起面板、输入草稿、创建对话记录和后台记忆补齐不收费。免费离开对话不调用 AI、不结算未发放成长，保留此前已完成交易；活跃对话需先结束或离开，再结束游戏回合。

AI 不直接增减体力，模型字段 `fatigueOffset` 必须为 0。自定义行动与人物对话共享每人物每游戏回合一次额外成长额度：首次实际产生正向通用属性或书生能力成长时占用；没有正成长则不占用。额度用完后的正向属性／能力增长归零，负变化与健康变化仍结算，体力仍正常扣除。非结束的对话轮次不发放属性，也不占成长额度。

强制考试入场先补满当前体力，再冻结考试数值与骰点，保证能够支付一次交卷的 5 点基础成本。思路免费；考试中的消费不重新计算已冻结成绩输入。重病按下文强制休养规则处理。

## 一、数值约定

游戏的绝大部分状态和结算数值使用整数；公式系数、概率和中间计算量可以使用小数，不因“整数”原则统一改成向下取整。智力、道德、政治、交际、体能为五项通用属性；识字、经义、文章、策论、文学为五项书生能力。两组数值与健康、阅读进度均使用 0～100 的整数，金额以整数文保存，考试分数也使用整数。体力使用整数点，当前值为 0～体力上限，体力上限按已确认规则为 50～150。总学识目前允许小数且不封顶，作为现有例外保留，本次未变更。

现有涉及小数的业务计算使用 `BigDecimal`，一般整数结果按 `HALF_UP` 四舍五入；阅读成长按累计额度向下取整，详见下文。新体力上限单独规定按完整 sigmoid 结果向下取整，其他既有结算方式不变。`clamp(下限, 上限, 数值)` 表示把数值限制在指定范围。实际收益等于最终值减原值，超出上限的部分不算收益。

常量见 [GameRuleConstant.java](../../src/main/java/mvp/engine/GameRuleConstant.java)，逐书参数见 [book.json](../../src/main/resources/game/book.json)。

## 四、阅读与学识

### 阅读条件

必须处于求学阶段，背包有书，并同时满足配置要求的年龄、通用属性、领域能力和前置书籍进度。`growthDomainCode` 只表示收益所属领域，不限制人物身份。

所有书籍统一以进度 100 为读满。同一本书按人物分别记录进度。没有阅读记录时按 0 显示，第一次读书时创建；多本副本不重复增加学识，失去书籍不清空已学进度。

### 常规计算

```text
智力系数 = 0.75 + 0.50 × 智力 / 100
身体系数 = 健康系数 H(健康) × (行动前体力 ≤20 ? 0.80 : 1)
学习量 = 13 × 智力系数 × 身体系数
普通进度增量 = min(剩余进度, max(0, round(学习量)))
单项累计成长额度(p) = floor(本书该项完整成长 × clamp(0,100,p) / 100)
单项应发成长 = max(0, 累计成长额度(新进度) - max(累计成长额度(原进度), 本书旧版已发成长))
单项实际成长 = min(100, 当前值 + 应发成长) - 当前值
```

阅读的基础学习量为每次 13 点，由 `GameRuleConstant.READING_PROGRESS_PER_TURN` 维护；健康系数见“健康与学习效率”；开局正常状态常规阅读约增加 11 点进度。同一人物状态下，各书的常规阅读速度一致。进度达到 100 后标记“已完成”，禁止继续阅读或提交阅读回答，不再产生阅读收益或疲劳消耗。新人物的“本书旧版已发成长”为 0。每次发放新旧累计额度之差，小额成长会随进度积累，不因逐回合取整而丢失。例如《三字经》的经义完整额度为 3，进度 30 时累计为 0，进度 40 时累计为 1。

### 阅读骰点

1D100 表示产生一个 1～100 的随机整数，由业务层在有效阅读时生成，作为计算方法的参数。

| 骰点 | 结果 |
| --- | --- |
| 1 | 进度和阅读成长为 0 |
| 2～99 | 按常规公式计算 |
| 100 | 直接补满进度，发放剩余成长额度 |

三种骰点结果都占用本回合一次主要行动额度并扣除书籍成本，不推进游戏回合。实际骰点与结果一并保存，重传同一请求不会重投。首次读满保存 `BOOK_MASTERED` 人生节点。

### 阅读（手动）

阅读（手动）是书籍学习中的以身入局，分为两个业务操作：先“生成阅读题目”，由 AI 以塾师身份给出问题；再“提交阅读回答”，由玩家提交理解与理由，AI 返回 0～100 分及点评，程序按下列公式结算进度和成长。生成题目不会增加阅读进度。当前除《GPT-1的权重》仅支持阅读外，其余 14 本均支持阅读（手动）；由书籍的 `playerReadingEnabled` 决定。

| 得分 | 评分对应进度 |
| --- | --- |
| 0 | 10 |
| 50 | 50 |
| 80 | 74 |
| 90 | 82 |
| 100 | 90 |

评分先限幅至0～100并四舍五入，`进度增量 = min(剩余进度, round(10 + 80 × 评分 / 100))`。评分对应10～90点，接近读满时实际可少于10；从0开始满分也只到90。人物和身体状态不再修正这部分进度。

出题评阅采用宽松标准，目标是北京市重点高中语文程度、高考约110/150分的玩家认真写体会即可满分。题面给足背景，回应核心、理解基本准确，并用自己的话给出一个合理理由或做法即可100分；不要求专业经学、独到见解、引用或长篇，白话、个别错字和无碍理解的疏漏不扣分，满分不强行挑错。按实际体会评分，不认自报学历成绩。

目标节奏是一次阅读约增加 10 点进度，再通过一次满分的阅读（手动）增加余下 90 点。这是两次阅读结算；按已确认的主要行动规则，须分属两个游戏回合，不能在同回合先阅读再提交阅读回答。状态较差、阅读骰点失常或评分较低时可能需要更多次阅读。阅读（手动）不掷阅读骰子，成长按实际新增进度发放；提交仅扣除本书阅读成本，无额外 AI 费用，按一次消费判定过劳伤害。相同起点、相同最终进度下，阅读、阅读（手动）和阅读骰点 100 的直接读满具有相同的阅读成长额度；属性封顶和游戏中另行发生的损失仍按实际情况处理。

生成阅读题目免费，不推进回合；同书同回合复用原题。提交成功占用本回合主要行动，不推进日历；同题同原文重传返回原结果，换原文不可重复结算。回合改变后题目失效。AI 失败不改变进度、时间、体力或主要行动额度；放弃免费题目也不会扣除体力。

### 旧存档阅读成长补齐

进入存档时，程序依据每本书的现有进度和原阅读结算回执，逐项补发“新累计额度减旧版实际已发”的正差额。已经取得的超额收益保留，后续新增进度先抵足这部分，再发剩余额度。只核算阅读与提交阅读回答的实际回执，读满人生节点不再计一次；自定义行动、人物对话和练习文章所得不算作旧阅读收益。

每人物在相同成长配置下只核对一次，并与人物及书生档案一起提交；再次进入或重试不会重复发放。核算记录保存当时的逐书额度，调整成长配置后按最新记录重新核对，之前已经消耗的额度继续计入，切回曾用过的配置也不会重复领取。失去书籍也保留原阅读记录，因此照常核算。已有进度、回合、年龄、钱包、身体状态及历史考试不重置，已经冻结的考试成绩输入不重新计算。达到属性上限而未到账的部分不会在未来属性下降时重新领取。

如果原始阅读回执缺失，或无法与累计阅读回合数、现有阅读进度对应，程序返回明确错误并回滚本次补齐，不根据当前属性猜测历史收益。无额度快照的旧空核算记录，仅在尚无补发且后续阅读回执完整时自动恢复；已补过收益却缺少逐书额度时，需先核对原始数据。正常完整存档会在进入后显示本次实际补发的成长。

### 学识计算

```text
p = 0：贡献0
1 ≤ p ≤ 99：贡献 = 单书满学识 × 0.6 × p / 100
p = 100：贡献 = 单书满学识
总学识 = 全部不同书籍的贡献之和
快照参考知识分K = clamp(0, 100, round(总学识 / 2))
```

`p` 是阅读进度。“不同书籍”按装备定义 ID 区分。学识保留小数，快照参考知识分换算时才取整；书籍内容介绍不按阅读档位拆分。当前四场考试的知识权重均为 0，学识和 K 仅用于阅读记录、快照及叙事参考，不计入考试成绩；读满时学识的跳变也不会直接提高考试分数。

## 五、练习文章、休息与健康

### 健康与学习效率

健康不低于 50 时学习无惩罚，也不提供额外增益。0～50 区间采用端点归一化 sigmoid；以下系数供阅读、练习文章和考试身体修正共用。

```text
h = clamp(0,50,健康)
σ(z) = 1 / (1 + exp(-z))
H(h) = 0.50 + 0.50 × [σ(0.20 × (h - 25)) - σ(-5)] / [σ(5) - σ(-5)]
身体系数 = H(h) × (行动前体力 ≤20 ? 0.80 : 1)
```

健康 0、25、50 的系数分别精确为 0.50、0.75、1.00；健康 50～100 均使用 1.00。健康归零仍按下文进入重病，系数下限不意味着重病期间可以学习。健康 75 以上用于抵抗未来伤害事件的机制留待后续设计，本轮不新增事件、药物或食物。

### 练习与恢复

练习文章的增长为 `max(0, round(2 × 身体系数))`，加入文章能力并按 100 封顶；固定消耗 8 点体力，占本回合主要行动。不再按智力放大或随文章能力递减。健康 ≥50 且不过劳时，每次实际增加至多 2 点文章；达到上限后的无收益练习仍占额度并消耗体力。

休息恢复至多 20 点当前体力和 5 点健康，占用每回合共享的一次主要行动额度。体力不超过当前上限；健康恢复封顶 75，已有健康高于 75 时保持原值，不会被降低。AI 提供的正向健康恢复也采用 75 上限。体能只影响可恢复到的体力上限，不放大每次恢复量；强制休养每个回合同样恢复至多 20 点体力。

### AI 带来的成长

当前实现中，自定义行动及整场人物对话结束时，理解、解算、复核三个模型阶段提出并核验变化量，程序拒绝无依据或超界输出后，再由引擎取整并计算实际结果：

| 项目 | 每次结算的驱动量范围 |
| --- | --- |
| 通用属性 | 每项 ±3 |
| 书生能力 | 每项 ±5 |
| 体力 | 程序按独立 AI 业务每次 15 点收费，模型的 fatigueOffset 必须为 0 |
| 健康 | ±10；正向恢复至多到 75，已有更高健康保持原值 |

无变化时必须明确输出 0，不保证每次互动都有成长；行动流程拒绝缺失字段或越界驱动量，不以裁剪到上限代替校验。上表限制 AI 直接给出的驱动量，正向属性／能力还受每游戏回合一次额外成长额度限制，最终健康变化会叠加过劳伤害。固定阅读依照各书配置提升通用属性和书生能力，练习文章只提升文章；这些固定成长不使用 AI 限幅或 AI 额外成长额度。

### 过劳与重病

过劳按当前体力 ≤20 点判定。行动前过劳使学习身体系数乘 0.80；消费后处于过劳区间，每业务扣 1 健康。体力不足禁止执行，体能增长不恢复当前体力。

健康降到 0 且尚未重病时，在重病检查中通用属性各减 2，并设置 4 个休养回合，属性只扣一次。固定行动与 AI 行动结算可以标记重病，但不自动推进日历；消耗品健康成本导致归零时，在结束回合检查重病。

使用“结束回合”后，程序依次完成剩余强制休养回合：每回合推进日历并恢复至多 20 点体力，健康保持 0，最后一回合恢复至 40。休养遇到玩家考试先暂停，剩余回合保留；阶段考试结束后继续完成剩余休养。玩家回合推进仅处理玩家休养，NPC 不后台推进共享日历；玩家县试结束后不再推进。已在重病中时禁止固定行动，包括主动休息；使用“结束回合”继续强制休养。首版不设死亡或后台倒计时。

## 六、考试计算

### 基础分、身体状态与运气

玩家节点考试开始时，先补满当前体力，再按当时人物状态冻结考试快照。四场考试的基础分 `B` 均由智力 10% 与五项书生能力合计 90% 加权，四舍五入后限制在 0～100。道德、政治、交际、体能与学识的考试权重均为 0；学识仅作为快照与叙事参考。

| 考试 | 智力 | 识字 | 经义 | 文章 | 策论 | 文学 | 通过线 T |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 蒙学阶段考 | 10% | 55% | 10% | 10% | 5% | 10% | 18 |
| 经义阶段考 | 10% | 20% | 35% | 15% | 10% | 10% | 29 |
| 县试预考 | 10% | 15% | 25% | 20% | 20% | 10% | 33 |
| 县试 | 10% | 15% | 30% | 20% | 15% | 10% | 33 |

身体修正 `R` 使用健康系数 `H` 与绝对体力阈值，不再单独叠加体能收益。健康 ≥50 且不过劳时 `R=0`，健康更高也不加分。普通运气修正 `L` 使用立方分布：

```text
B = clamp(0,100,round(智力 × 0.10 + 五项书生能力的对应加权和))
R = round(clamp(-5,0,-6 × (1 - H(健康)) - (当前体力 ≤20 ? 3 : 0)))
x = (骰点 - 50.5) / 49.5
L = round(25 × x³)
```

题目、通过线、`B`、`R`、总学识、骰点及 `L` 一起保存。之后即使人物状态或参数改变，也不重算这次考试的数据。入场补满体力不恢复健康，因此健康惩罚仍可能存在。

### 考试

| 骰点 | 考试结果（系统操作） |
| --- | --- |
| 1 | 0 分，必定失败 |
| 2～99 | `clamp(0,100,B+R+L)` |
| 100 | 100 分，必定通过 |

### 考试（手动）

模型依据题目、评分点和玩家答卷给出 `answerScore`，必须是 0～100 的整数，60 为答卷合格基准。缺失、越界或非整数评分会被拒绝。程序以答卷表现为主，并按本场通过线校正角色贡献：

```text
A = answerScore
T = 本场通过线
普通骰点最终分 = clamp(0,100,T + round(0.80 × (A - 60) + 0.20 × (B - T)) + R + round(0.20 × L))
effectiveContentModifier = 最终分 - (B + R + L)
```

骰点 1 与 100 仍优先覆盖为 0 分失败／100 分通过。80% 与 20% 分别作用于“答卷偏离 60 分”和“角色基础分偏离本场通过线”，不是直接把答卷分与角色分相加；身体修正完整保留，普通运气只取原修正的 20%。例如县试 `T=33、B=36、R=0、L=0` 时，答卷 60 分最终为 34，答卷 80 分最终为 50。

`effectiveContentModifier` 是程序结算后相对旧自动基线 `B+R+L` 的差，沿用字段 `aiPlayerContentModifier` 保存和展示为“相对自动基线调整”，不是模型直接给出的 ±10 分。实际答卷评分写入已保存评价 `aiContent` 的开头“答卷评分：xx/100”；正式成绩继续以 `finalScore`、通过线和通过状态为准。

### 思路、交卷与重放

角色思路按 `B+R` 的 35、60、80 分界分为四档。首次免费请求时让 AI 依据角色水平和已读书籍生成提示，并保存至该考试；再次请求复用，不重投骰点或透露最终成绩。提示是思路，不是完整答案。

考试先计算最终成绩，再生成相符的完整答卷和总结；考试（手动）先取得答卷评分，再由程序计分，最后生成结果总结。模型不能回写最终分数或通过状态。生成失败时保留待考状态，不保存部分答卷或成绩；先前已成功保存的思路不受影响。

重复结算同一考试返回原成绩，不重复推进阶段；不同答案或不同作答方式不能覆盖已完成记录。两种交卷方式均只扣 5 点考试基础体力，无额外 AI 成本，思路免费。缓存和重放不重复扣除。考试本身不推进游戏回合，但阶段考试后可能继续剩余强制休养回合；旧版已完成考试保持原结果，不重新评价或补写 AI 内容。

### 公测难度校准

当前通过线为蒙学 18、经义 29、预考 33、县试 33。基准是免费教材配合少量固定练习，不要求文章能力练满、购买昂贵书籍或获得 AI 加点。难度目标是正常玩家最终县试通过率约 75%，不以四场全过为口径。

参照策略：优先读当前可读的免费教材；课程空档练习文章，累计最多 20 次；下一次消费会进入 ≤20 体力时先休息，其他空档可休息或直接结束回合。阅读骰点固定为 50，考试穷举全部 100 个骰点；不购买付费教材，不假定 AI 稳定加点。以下为本轮实际核心测试通过后的引擎模拟结果。

正常参照路线共阅读 65 次、练习 20 次、休息 22 次，文章能力为 71。四场考试的 `B` 依次为 21／32／36／36，`R` 均为 0，通过线依次为 18／29／33／33，各有 76 个通过骰点。整数计分下，以此结果贴近正常玩家最终县试 75% 的设计目标。

| 模拟路线 | 最终文章 | 县试基础分 B | 县试通过骰数／100 |
| --- | --- | --- | --- |
| 免费 7 本＋20 次练习 | 71 | 36 | 76 |
| 免费 7 本，不练习 | 31 | 28 | 22 |
| 前 3 本＋20 次练习 | — | 21 | 12 |
| 前 6 本＋20 次练习 | — | 33 | 63 |
| 免费 7 本＋100 次练习 | 100 | 42 | 86 |
| 五项通用属性各损失 2 后，免费 7 本＋20 次练习 | — | — | 76 |

各路线的县试通过线均为 33；“—”表示本表不列该项，不代表 0。只读免费 7 本的路线共阅读 65 次、休息 14 次。以上概率仅穷举考试骰点，未抽样阅读骰点或模型输出；也不能把单场通过概率相乘解释为实际四场全过比例。

付费书可改善成长，阅读（手动）可节约主要行动；考试（手动）使用独立的答卷主导公式，不混入系统考试的基准概率。

上述为特定策略的数值模型，尚无真人样本，不代表已经有 75% 的真实玩家通关。公测以最终县试参加人数与通过人数统计结果，并记录完成教材、练习次数和是否使用手动作答；不同策略与中途离开需分开解释。本轮不添加埋点系统，也不将没有参加县试的存档直接算作考试失败。本轮定向 Maven 验证覆盖 7 个测试类、39 项测试，0 失败、0 错误、0 跳过；前端构建及 TypeScript 检查通过。未启动后台或进行联网 AI 质量测试，答卷评分质量与真实游玩体验仍需后续验证。

## 七、物品获取与对话

### 领取和购买

七本学校教材由窦苞免费提供，每个人物每种教材只能领取一次，每次数量为 1；原请求重放返回原结果，不重复发书。八本付费选修书和清茶由陆掌柜提供，付费单次数量为 1～100，必须满足资金限制。固定目录无限供应，不扣供应者的背包或另外维护库存。

清茶 `ITEM_QINGCHA` 每份 20 文，只在书铺购买。书目与杂物供应分别展示，`SupplyOffer` 返回实际可获取状态、已有数量及被阻止的原因。初始钱包 2000 文，八本付费书标价合计 45800 文；《经世策论集》《八股破题精义》《GPT-1的权重》三本原有付费书合计 36600 文。不能假定初始钱包可以买齐所有教材；本线不新增收入和出售，购书与清茶需要共同安排预算。

价格和提供者由数据库定义决定。扣款、提供者收款、背包记录和请求结果须在同一事务内完成。每次获取分别记录，同种物品在背包中合计数量。免费获取不扣钱，独立获取物品不推进游戏回合；自定义行动附带获取物品时也不推进游戏回合，自定义行动本身照常消耗 15 点体力。

### 人物身份分级

固定 NPC 与玩家长期保存。动态 NPC 由 resolver 随行动提出身份与保留建议，程序确认后建立同结构的人物和书生档案；不能凭叙述冒用固定 NPC 的教学、交易或考试权限。每次最多确认 4 名人物，其中新增最多 2 名；引用旧人物必须使用观察快照中实际在场的 ID。

| 级别 | 动态人物的保留方式 |
| --- | --- |
| L0 | 缓存本次场景身份，期限为实际结算回合加 1；仅观察到而未实际交互的新人物使用此级别 |
| L1 | 跨回合保存，期限由 resolver 从 3、9、18 回合中选择，缺省为 9；从实际结算回合开始计算 |
| L2 | 在本存档中长期保存，期限为空，不自动归档 |

只有新的实际互动可以延长期限或提高级别，读取不续期，既有身份不因重复请求改名或重新生成。人物级别只升不降，新期限不缩短旧期限。到期退出日常出场，仍保留 ID、档案、物品和历史引用；活跃对话中的双方受到保护，结束后再依据当前期限处理。

`participated` 区分真实参与者与仅被看到的人物，事件只向程序确认的参与者分配记忆。有实际关系或明确约定的 L2 记忆保存成功时，同事务将其中真实参与的动态 NPC 提升为 L2；如果摘要补齐前该人物已到期归档，可以恢复原身份，保留原 ID 和场景且不改变 enabled，避免人物期限截断持续关系。记忆级别与人物级别分别保存。

### 场景物件、拾取和使用

场景物件复用物品实例表，公共装备定义保持独立。每次行动最多确认 8 条物件变化，其中新物件最多 2 个；新物件数量为 1，仅允许普通纸片、小石子、落叶、木片四种程序模板；名称和说明由模板固定，不能通过改名创造财物或凭证。旧物件必须在观察时确实存在于当前场景。resolver 只能选择允许模板、描述发现过程并提出保留策略，不指定可出售价格、通用装备定义、人物数值效果或额外数量。

L0 物件保留至实际结算回合加 1；L1 使用 3／9／18 回合，无效期限回落为 9；L2 不到期。真实交互可以续期或升级，查看和请求重放不续期。归档只退出场景列表，保留实例记录。

物件在场景中使用 `SCENE` 状态。拾取在同一事务中检查存档、场景、回合、有效期及所有权，随后将原实例改为 `OWNED`、绑定人物、清空场景和期限、提升为 L2，原 ID 与描述保留。动态物件不自动成为公共目录的一部分，不能通过一段叙述变成昂贵教材。已持有物品不会因为记忆或身份期限消失。

公共物品按定义汇总背包数量，动态小物按实例显示。使用接口每次消费一份配置了恢复用途的 `CONSUMABLE`，读取 `equipment.json` 中的 `restoration.staminaRecovery` 与 `restoration.healthCost`。单次体力恢复量硬限制为 0～20，实际恢复不超过当前上限；健康成本硬限制为 0～100。先恢复体力，再扣健康，健康最低为 0；健康不足支付标价时仍可使用，实际损失只到 0。健康归零在结束回合时进入重病。当前只有清茶，配置为恢复 10 体力、健康成本 0；本轮不新增药物或食物。

使用不推进游戏回合、不占主要行动。体力已满时拒绝使用，不扣数量或健康。数量减到 0 后实例状态为 `CONSUMED`，保留历史，背包不再显示。动态小物与书籍没有消耗品的恢复效果。

### 自定义行动与人物对话

模型在事务外处理事实快照，结算前核对人物和游戏回合；过期结果不覆盖新状态。观察回合用于验证当时看到的人物和物件；自定义行动与对话结算不推进日历，新增或延长的保留期限从当前实际结算回合计算。后续结束回合或强制休养按正常日历推进与归档。

自定义行动与对话共用多步骤解算流程，输入按角色可见信息裁剪。自定义行动保留行动者自身数值，玩家家庭仅给玩家；私聊不提供发起者的完整钱包、能力、家庭和背包。在场身份、当前发言、旧记忆和执行回执明确区分，见[智能体解算与验证](../开发者手册/智能体解算与验证.md)。

人物对话只能向当前交谈的供应者获取其目录内物品；与同窗或管书人交谈不能代向塾师领书，和父母交谈也不能代向书商购买。自定义行动可向当前场景中的合法供应者下单。

人物对话的非结束轮次可以完成本轮交易、当前对方的保留决策和场景小物变化，不结算属性。私人对话只更新当前对方，不创建第三人或把旁人加入谈话；新人物相遇通过自定义行动进行。玩家手动结束或 AI 决定结束时，整场只结算一次属性。手动结束只总结已有历史，不执行当前未发送的文字，不新增人物或物件、不重做旧交易，也不会把草稿写进真实发言记忆；结束失败不撤销此前已成功的交易。

一次已发送的玩家发言与 NPC 回复构成一个对话轮次，`version` 记录已完成轮数；对话轮次不推进游戏日历。每场最多 5 轮，模型接收 `dialogueRound` 和 `maxDialogueRounds=5`，通过 `endDialogue=true` 表示结束；语义完整时可以提前结束，第 5 轮必须结束。若模型第 5 轮仍返回 `false`，程序拒绝本轮结果并返回 502，可原样重试，不替模型强行结算。

AI 说“送了书”不等于已入包，必须以程序实际执行的交易为准。网络失败、格式错误、来源或语义不合法时，本次候选不结算；错误信息区分原因。结构校验每阶段最多一次格式修正，语义拒绝不自动重试。

### 跨场记忆

记忆来自已提交的整场结束对话、普通自定义行动及人生节点。结束对话依据完整回执，为实际双方分别评估；自定义行动和人生节点只为事件明确记录的参与者评估。普通自定义行动保存为 `FREE_ACTION`；已经形成重要节点的同次行动只使用节点，内部 `AI_ACTION` 不重复生成记忆。常规固定行动和独立物品获取的普通回执不单独生成记忆。

`MemoryResolver` 先生成带来源引用的摘要、级别、类别、期限、原因和强化建议，再独立复核其语义；后端确认边界后保存。期限按游戏累计回合计算，离线时间不影响记忆。

| 级别 | 保留与召回 | 到期方式 |
| --- | --- | --- |
| L0 当场 | 本场原文保留在对话／事件中；只写已处理的归档索引，不新建跨场摘要正文 | 本场结束后不进入跨场召回，也不被缺口补齐重新生成 |
| L1 近期 | 摘要与索引持久保存；resolver从3、9、18回合选择期限，未给有效期限时用9回合 | `expiresAtTurn = 发生回合 + 期限`；当前回合达到该值即退出召回，并在相关读取或生成时标记归档 |
| L2 长期 | 在本存档内持续保留，按需选入上下文 | 无自动到期；不代表每次完整读取所有历史 |

记忆类别为 `EXPERIENCE`（经历）、`RELATIONSHIP`（有依据的关系经历）、`COMMITMENT`（明确约定及履行／取消记录）。人生节点、关系经历和明确约定强制采用L2；已执行交易至少采用L1。级别缺失或无效时按L1处理，类别无效时按普通经历处理。人物身份与每段经历的记忆级别独立，固定和动态 NPC 都使用相同记忆规则。

新的实际经历可以强化当时提供给resolver的旧记忆：只允许同一存档、同一拥有者、尚未到期的L1，保留原ID。新经历为L1时，期限取原期限与“新事件发生回合＋建议期限”的较大值；为L2时，旧记忆提升为L2。读取、重放同一请求、复述旧事和单纯见面不构成强化。已归档记录不自动复活。

对话优先为与当前对象有关的关系和约定保留最多3条位置，再纳入最多2条本人长期经历、有关近事及其他近期经历，重复项只带一次。自定义行动先选本人最多2条长期经历，再补近期经历。每次仍最多8条，包含标识、级别、类别、个人回忆标记及来源事件证据摘录的完整JSON最多5000个Unicode字符；每条摘要最多1000字符，空间不足时只缩短摘要字符串，保持JSON有效。

NPC在相关话题中延续已确认的称呼、态度和约定，不凭对话次数产生好感分数或虚构关系。约定记忆表示当时说过、答应过、完成或取消过什么；书生线不维护任务状态，不自动履约、扣款或发奖。回应应结合较新的确认结果，不把旧约定一概当成仍未履行。各人只能使用自己参与或知晓的记忆，当前人物、背包及结算事实优先于旧摘要。摘要始终标记为个人回忆；召回从实际来源事件重建证据，旧摘要不能通过重复引用升级为客观事实。

事件 `eventSequence` 是稳定先后，同一回合内的新约定与取消也能明确排序；回合只表示游戏时间。记忆带有 `sourceEventSequence`，补齐旧事件只读取更早事件，不把同回合后来发生的事情当成先前经历。实际交易、人物公开身份与场景物件分别取已提交的 `executedTrades`、`resolvedNpcs`、`sceneItems`；场景物件存在不表示已经持有，未参与者的心理不作为事实。

正文保存在运行目录下的 `memory/<saveId>/<memoryId>.json`。数据库保存索引、级别、类别、期限、来源事件序号、强化回合与序号及归档状态；归档保留记录及已有正文，不删除人物、物品、事件或文件。摘要生成失败不撤销已完成的操作，后续每次最多补齐两条活跃缺口；L0和到期记忆均不会重新生成。文件格式仍沿用现有 `version: 1`，详见[记忆目录说明](../../memory/README.md)。

## 八、重复请求与随机结果

固定行动、获取、拾取、使用、自定义行动和对话使用 `requestId`。同一存档、同一编号、相同参数重传时返回原结果；同一编号换参数则拒绝。新操作使用新编号。

固定行动与结束回合检查 `expectedTurnNumber`，对话及免费离开检查 `expectedVersion`。普通请求结果不进入人生节点列表。

计算类不访问数据库、不调用模型、不自行掷骰；相同输入和骰点得到相同结果。实际游戏的随机数在业务层生成并保存，UUID 主键不属于玩法随机。[随机种子](../后续设计/后续规划.md#随机种子)留待后续实现。
