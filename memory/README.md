# 本地人物记忆

应用以启动时的工作目录为基准，把跨场记忆正文保存为 `memory/<saveId>/<memoryId>.json`。从项目根目录启动时，这里就是实际存储目录。迁移时须同时保留数据库和对应目录，工作目录改变后也要同步移动目录。

## 分级与关系延续

`memory_record` 保存索引和保留策略，摘要正文保存在 JSON 文件中。相同人物对同一事件只有一条索引。新记忆沿用存档、人物和事件组合生成的确定性 ID，已有 ID 保持不变。

| 级别 | 保存方式 | 召回与到期 |
| --- | --- | --- |
| L0 当场 | 本场原文保留在对话／事件中；保存归档索引，不新建跨场摘要正文 | 不进入跨场召回，不作为缺失记忆补齐 |
| L1 近期 | 保存摘要、索引、到期回合 | 期限为 3／9／18 游戏回合；当前累计回合达到到期值即退出召回，相关读取或生成时标记归档 |
| L2 长期 | 保存摘要和索引，无到期回合 | 在本存档内持续保留，按上下文需要选取 |

`MemoryResolver` 在摘要调用中同时建议级别、类别、期限、原因和强化目标，后端确认后保存。类别为 `EXPERIENCE`、`RELATIONSHIP`、`COMMITMENT`。人生节点、关系经历和明确约定强制采用 L2；已执行交易至少 L1。非法级别／类别分别回落到 L1／EXPERIENCE，L1 期限无效时取 9 回合。

数据库保存 `memory_level`、`memory_kind`、`retention_reason`、`expires_at_turn`、`last_reinforced_turn`、`source_event_sequence`、`last_reinforced_sequence` 和 `archived`。到期只归档，不删除索引或已有正文；已归档记录即使缺少文件也不重新生成。离线时间不推进游戏回合，没有后台定时清理。

新的实际经历可以强化当时提供给 resolver 的旧记忆，只限同一存档、同一拥有者、来源更早且尚未到期的 L1。新经历为 L1 时延后期限，为 L2 时可提升旧记忆，原 ID 保持不变。读取、请求重放、复述旧事不续期；已归档记忆不自动复活。

人物身份、物品实例和经历记忆分别分级。固定与动态 NPC 使用相同的经历记忆规则，人物身份过期不删除历史；已确认关系或约定的 L2 记忆保存时，将真实参与的动态 NPC 身份提升为 L2。若摘要补齐前身份已到期归档，可恢复同一 ID 与原场景，且不改变 enabled；这只恢复真实关系对应的人物身份，不复活已归档的 L1 经历。具体人物／物品期限见[规则与数值](../docs/MVP/规则与数值.md#人物身份分级)。本线不维护数值好感或任务状态，不自动履约、扣款或发奖。

## 正文格式

UTF-8 JSON 使用 `version: 1`。下面是格式示例，ID 为 32 位十六进制 UUID，示例事件序号用于区分同回合内的先后：

```json
{
  "version": 1,
  "id": "11111111111111111111111111111111",
  "saveId": "22222222222222222222222222222222",
  "ownerCharacterId": "33333333333333333333333333333333",
  "sourceEventId": "44444444444444444444444444444444",
  "sourceEventSequence": 37,
  "occurredTurnNumber": 12,
  "summary": "我曾与书商讨论购书；交易回执确认我购得一本书。",
  "retentionDecision": {
    "level": "L1",
    "kind": "EXPERIENCE",
    "retentionTurns": 9,
    "reason": "近期购书经历",
    "reinforcedMemoryIds": []
  }
}
```

`retentionDecision` 保存首次确认的保留建议，用于正文已落盘但索引失败时复用决策；数据库是当前级别、期限和归档状态的依据，后续续期／提升不重写历史正文。旧文件缺少 `retentionDecision` 或 `sourceEventSequence` 仍可读取。修复已有索引的缺失正文不重设已有期限。

## 来源与检索

记忆来源为已提交的整场结束对话、普通自由行动和人生节点。结束对话为双方各评估一次，言论、承诺与实际交易分开交给模型；手动结束记录不会将未发送草稿作为发言。其他事件只为主流程明确记录并核验同存档的真实参与者生成，不扩散给旁人，也不让刚出现的第三人获得此前整场私人历史。

普通自由行动使用 `FREE_ACTION` 事件，读取已保存的叙述、场景和实际结算回执；同次行动已形成人生节点时只评估该节点。常规固定行动、独立物品获取及内部 `AI_ACTION` 的普通回执不单独生成记忆。

叙述不能单独证明新人物、物品、交易或数值已成立。`resolvedNpcs` 仅提供实际参与人物的公开身份字段，不读取他人心理或钱包；`sceneItems` 是程序确认的场景物件，不表示取得所有权；已执行交易来自 `executedTrades`。当前背包和业务结果优先于旧摘要。

事件保存前在业务事务内锁定存档，由数据库分配 `eventSequence`；UUID 保留为主键，序号不要求连续。记忆按最后强化序号、来源序号排序，回合仅用于期限；补齐旧事件时严格只读取来源序号更小的经历。同回合内的约定、履行和取消因此具有明确先后。

每条摘要最多 1000 个 Unicode 字符。后续上下文最多 8 条，完整 JSON 最多 5000 字符，字段包含 `memoryId`、`sourceEventId`、`sourceEventSequence`、`turnNumber`、`level`、`kind` 和 `summary`。对话先为与当前对象有关的关系／约定保留最多 3 条位置，再选最多 2 条本人长期经历、有关近事及其他近期经历；重复项只出现一次。自由行动先选最多 2 条本人长期经历，再补近期经历。超预算时只缩短摘要字符串，保持 JSON 和 Unicode 字符完整。

约定记忆记录当时实际说过、答应过、履行或取消过什么，不自动表示现在仍未履行。回应须结合较新的确认结果和当前事实；记忆不覆盖钱包、背包和考试结果。人物只读取自己的记忆，未知信息不能补造。

## 保存、故障与清理

事件事务提交后同步评估记忆，模型调用期间不占用数据库事务；随后在独立短事务中锁存档重读当前回合，再保存索引、同一拥有者的旧记忆强化及相关动态人物的长期保留，避免模型等待期间已经到期的 L1 被旧快照续期。同一事件／人物的唯一索引保证请求重放不重复续期。

正文先写入同目录固定 `.json.pending`，再原子替换正式文件。成功后不保留 pending；不支持原子移动或写入失败时保留未发布 pending 供后续覆盖重写，不将其作为可用记忆。正文先于索引发布，索引失败时可复用已有正文和首次决策。

模型、文件或索引失败不撤销已完成的游戏操作。后续每次检索最多尝试补齐两条活跃缺口，单条失败冷却 60 秒，事件序号游标轮流处理缺口；L0 和已到期记忆都被排除。归档正文不会因为文件缺失被重新生成。

程序不自动删除正式 JSON 或归档文件。存档清理、搬迁仍应处理对应目录；本机文件清理按用户规则移入 `C:\Users\user\Desktop\智能体回收站\垃圾桶`，不永久删除。运行时 JSON 和 pending 文件不提交到 Git。
