# 本地人物记忆

应用以启动时的工作目录为基准，把记忆正文保存为 `memory/<saveId>/<memoryId>.json`。从项目根目录启动时，这里就是实际存储目录。部署或迁移时须同时保存数据库和这个目录，工作目录改变后也要把目录移至新的工作目录下。

数据库 `memory_record` 只保留记忆 ID、存档、拥有者、来源事件、发生回合，以及相关人物、场景和物品编码等检索字段，不存摘要正文。相同人物对同一事件只有一条索引。新记忆使用由存档、人物和事件组合得到的确定性 ID，已有索引的 ID 保持不变。

正文使用 UTF-8 编码，格式如下（ID 均为 32 位十六进制 UUID）：

```json
{
  "version": 1,
  "id": "11111111111111111111111111111111",
  "saveId": "22222222222222222222222222222222",
  "ownerCharacterId": "33333333333333333333333333333333",
  "sourceEventId": "44444444444444444444444444444444",
  "occurredTurnNumber": 12,
  "summary": "我曾与书商讨论购书；交易回执确认我购得一本书。"
}
```

每条事件先由 AI 压缩成不超过 1000 个 Unicode 码点的摘要。携带到下一次对话或自由行动的记忆是最多 8 条的有效 JSON 数组，优先选取与对话对象有关的近期记忆，再补充本人其他近期记忆；包括 JSON 字段名和标点在内，整个字符串最多 5000 个 Unicode 码点。超出剩余预算时只缩短摘要字符串，再重新序列化，避免截断 JSON 或拆开生僻汉字。

记忆仅来自已经提交的整场结束对话和人生节点。结束对话为双方各生成一份，言论、承诺与已执行交易分开给模型；人生节点只为事件明确关联且属于同一存档的人物生成；自由行动的重要经历还会摘取已保存的场景及实际交易回执，用于摘要和相关物品索引。普通行动回执及内部 AI 结算回执不会重复生成记忆，未参与的 NPC 不会收到他人的经历。

当前实现同步在事件事务提交后生成摘要，模型调用期间不占用数据库事务，随后用新的短事务保存索引。模型、文件或索引保存失败不会撤销已经完成的游戏操作。后续回忆每次最多尝试补齐两条遗漏或缺失、损坏的文件，单条失败冷却 60 秒；游标轮流处理遗漏，避免一条失败永久挡住其他事件。

写入先完整保存到同目录固定 `.json.pending` 文件，再进行原子替换，成功后不保留临时文件。文件系统不支持原子移动或写入失败时，保留未发布的 pending 文件供下次覆盖重写，不把它当作可用记忆。程序不自动删除正式 JSON；存档清理或搬迁应连同对应目录一并处理。运行时 JSON 和 pending 文件不提交到 Git。
